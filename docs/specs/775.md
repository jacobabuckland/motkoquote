# CONTRACT-1: A sent contract can be withdrawn

## Problem

Contractors have no way to withdraw a sent contract before the customer signs it. If they spot an error in the deposit, scope, or any contract terms after sending but before signature, the link stays live and signable with incorrect information. They're locked out of editing the quote (which would fix the error) and have no route to stop the customer from signing a contract that contains a mistake.

## Scope: what changes

### Contract withdrawal action

Add a `withdrawContract(contractId)` server action in `src/app/jobs/actions.ts` that:
- Verifies the contract is sent but not signed
- Refuses if the contract is already signed (throws an error at the write level)
- Updates `contracts.status` to `"withdrawn"`
- Revalidates relevant paths (`/jobs/[id]`, `/c/[contractId]`)
- Does NOT trigger any customer notifications (no email, no SMS)

### Contract page rendering

The contract page (`src/app/c/[id]/page.tsx`) must handle the new withdrawn state:
- Withdrawn contracts show: "This contract has been withdrawn by {contractor.trading_name}"
- No signing UI is shown for withdrawn contracts
- Void contracts (from account erasure) continue to return `notFound()` exactly as they do today

### Quote editability

`src/lib/quote-editability.ts` currently blocks editing when ANY contract exists. Change the rule to check contract STATUS:
- A withdrawn contract does NOT block editing (treat as if no contract exists)
- A sent, signed, or declined contract continues to block editing
- The `hasContract` helper and `quoteEditability` function signature stay unchanged, but the implementation must check `contract.status`

### Job stage derivation

`src/lib/job-stages.ts`'s `deriveSituation` function must treat a withdrawn contract as if no contract exists:
- Withdrawn contract → return `"accepted_need_contract"` situation
- This puts the job back into the "Accepted — need contract" stage rather than stuck waiting for a signature that will never come

### UI to trigger withdrawal

The job page (`src/app/jobs/[id]/page.tsx`) needs a way to trigger the withdrawal action:
- Show a "Withdraw contract" action when contract status is "sent" (unsigned)
- Hide this action when contract is signed, declined, or withdrawn
- Call the `withdrawContract` server action

## Explicitly out of scope

- Superseding a signed contract with a new one (decision 2 closes withdrawal for signed contracts)
- The erasure void path (status "void" remains unchanged, continues to 404)
- Re-issuing a quote after acceptance (already shipped on 16 Sep)
- Archiving a job (JOB-2, separate item)
- A dashboard view of withdrawn contracts (decision 16 Sep: withdrawn contracts do not appear in "Signed & declined contracts" list)
- Any migration (decision 16 Sep: `contracts.status_changed_at` is untouched because withdrawn contracts don't appear in the list it sorts)

## Edge cases

### Contract statuses

- **Sent (unsigned)**: withdrawal succeeds
- **Signed**: withdrawal refused, throws error
- **Declined**: withdrawal not offered (already terminal)
- **Withdrawn**: withdrawal not offered (already withdrawn)
- **Void** (erasure): unaffected by this item, continues to 404 on public page

### Quote editability after withdrawal

The critical test is that editability considers STATUS:
- Quote with NO contract → editable
- Quote with WITHDRAWN contract → editable (new behavior)
- Quote with SENT contract → not editable (unchanged)
- Quote with SIGNED contract → not editable (unchanged)

A weak test that only checks "withdrawn → editable" would pass against an implementation that removes the contract check entirely, reopening every quote. Must test BOTH withdrawn (editable) AND live contract (blocked).

### Empty states

- Company name missing: should never happen (required field), but if null/undefined, show "This contract has been withdrawn" without "by {name}"
- Contract record deleted: `notFound()` (standard missing-record behavior)

### Notification suppression

The action must NOT call notification services. Decision (1): "The customer is not told — no email, no SMS. The link simply stops working."

## Risks

### Status model collision with void

**Risk**: Reusing `status = "void"` would conflict with account erasure.

**Mitigation**: Use a new status value `"withdrawn"`. The `contracts.status` column has no CHECK constraint (migration 00000000000011), so a new value stores without any schema change. Void contracts continue to behave exactly as they do today (404 via `isPubliclyUnavailable` in `src/lib/erased-artefact.ts`).

### Quote editability implementation

**Risk**: Checking only `hasContract(contract)` instead of examining `contract.status` leaves quotes frozen after withdrawal.

**Mitigation**: The acceptance tests explicitly verify a withdrawn contract does NOT block editing. The function signature can stay the same, but the implementation must receive and check the contract's status field.

### Job stage stuck waiting

**Risk**: Without updating `deriveSituation`, a withdrawn contract leaves the job showing "Awaiting signature" forever.

**Mitigation**: The stage derivation must handle `contract.status === "withdrawn"` the same way it handles no contract at all — return `"accepted_need_contract"` so the job offers "Send contract" again.

### Race condition: withdrawal during signing

**Risk**: Customer clicks Sign while contractor clicks Withdraw.

**Mitigation**: The write happens server-side with a status check. If signing wins the race, `withdrawContract` reads back `status = "signed"` and refuses. If withdrawal wins, signing fails (contract is no longer in sent status). Whichever write lands second is rejected. This is the same pattern used by `deleteDraftJob` checking quote status server-side.

## Derived criteria

From the issue body and decisions:

1. **Criterion 1**: A contractor can withdraw a sent, unsigned contract via the job page
2. **Criterion 2**: Attempting to withdraw a signed contract is refused at the server action level (not just hidden in UI)
3. **Criterion 3**: A customer opening a withdrawn contract's link sees "This contract has been withdrawn by {company name}" and cannot sign it
4. **Criterion 4**: Withdrawal sends the customer nothing (no email, no SMS, no notification service calls)
5. **Criterion 5**: After withdrawal, the quote can be edited again (withdrawn contract does not block editing)
6. **Criterion 6**: A quote with a live (sent/signed) contract still cannot be edited (unchanged behavior)
7. **Criterion 7**: A contract voided by account erasure is unaffected and still returns 404

Criterion 5 and 6 together prevent a weak test that only checks withdrawal — must verify status discrimination, not presence alone.
