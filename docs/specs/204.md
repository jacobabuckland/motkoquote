# Reconcile APP_STORE_CHECKLIST.md against the current tree

## Problem

APP_STORE_CHECKLIST.md describes a Stripe-based payment model and instructs the reader to smoke-test a Stripe payment link. The tree has never had Stripe as a payment provider — payments are handled by TrueLayer pay-by-bank (Payments API for customer→trade payments, commercial VRP for trade→motko fee collection). The checklist also claims that aps-environment is currently set to `development` and needs flipping to `production`, but the entitlement file already shows `production`. These stale claims create a submission risk: describing the wrong payment model to App Review, missing the open-banking considerations that a Stripe description would not surface, and testing a configuration change that's already done.

## Scope: what changes

- **Remove all Stripe references** from APP_STORE_CHECKLIST.md
- **Correct the payment model description** to reflect TrueLayer Payments API (pay-by-bank for customer invoices) and TrueLayer commercial VRP (cVRP, for motko fee collection from trades)
- **Update the smoke-test step** to test the actual TrueLayer pay-by-bank payment flow instead of a Stripe payment link
- **Correct the aps-environment note** to reflect that the entitlement is already set to production in ios/App/App/App.entitlements
- **Verify every remaining claim** in the checklist against the current tree:
  - Privacy manifest (PrivacyInfo.xcprivacy) declares UserDefaults CA92.1
  - Export compliance (ITSAppUsesNonExemptEncryption=false) is set
  - Microphone usage description (NSMicrophoneUsageDescription) is present
  - App identity values (appId, name, Team, web target)
  - File paths referenced (entitlements, Info.plist, workspace)
- **Remove any claim that cannot be verified** from the tree rather than reword it

## Explicitly out of scope

- Do NOT add App Review guidance, legal advice, or open banking compliance notes beyond correcting the payment model facts
- Do NOT change any entitlement, capability or configuration file (ios/App/App/App.entitlements, Info.plist, etc.)
- Do NOT change STATUS.md or README (covered by separate items)
- Do NOT add new checklist items beyond correcting existing ones
- Do NOT submit or prepare a submission to App Store Connect
- Do NOT change the Stripe-related migration files or test files — those are historical

## Edge cases

1. **A checklist item describes a step that no longer applies**: Remove it and note the removal in the PR description, rather than leaving it as a no-op step someone will perform.

2. **A checklist item cannot be verified from the tree** because it concerns App Store Connect configuration (screenshots, listing metadata, demo account): Mark it explicitly as requiring manual verification rather than deleting it or asserting it is done. The checklist serves as a launch guide, not just a build verification.

3. **Privacy manifest and export compliance claims**: These are common submission blockers. Verify:
   - PrivacyInfo.xcprivacy exists at ios/App/App/PrivacyInfo.xcprivacy
   - It declares NSPrivacyAccessedAPICategoryUserDefaults with reason CA92.1
   - Info.plist contains ITSAppUsesNonExemptEncryption set to false
   - Info.plist contains NSMicrophoneUsageDescription
   
   If any of these is missing or incorrect, the checklist claim must be corrected or removed.

4. **Conflict between the checklist and STATUS.md**: This item only corrects APP_STORE_CHECKLIST.md. Note any conflict in the PR description for the STATUS.md item to resolve.

5. **The "Parallel (Jacob-owned)" section at the end** references "Stripe Pay by Bank" and Stripe Dashboard configuration. This entire section is stale — TrueLayer is the provider, and there is no Stripe Dashboard. Remove this section entirely.

6. **TrueLayer-specific test steps**: The smoke-test should reference:
   - Creating an invoice
   - Testing the pay-by-bank payment flow (the "Pay by bank" button on /i/[id])
   - Verifying the TrueLayer Hosted Payment Page appears
   - Testing both completion and abandonment flows
   
   Do NOT add specific test account details or sensitive configuration — those belong in internal docs, not a checklist committed to the repo.

## Risks

**Payment model misrepresentation to App Review**: Describing Stripe when the app uses TrueLayer pay-by-bank is a factual error that could delay or block submission. Open banking/pay-by-bank carries specific review considerations (account access permissions, bank redirect flows, FCA authorization questions) that a card/Stripe description would not surface.

**Stale configuration verification**: The aps-environment note instructs the reader to flip a setting that's already production. If someone follows the checklist mechanically, they'll waste time looking for a change that's done — or worse, flip it back to development.

**No user-visible impact**: This is internal documentation only.
