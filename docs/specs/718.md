# #718: Motko must ask who the quote is for, and the full materials question

## Problem

Reported 12 Sep from a live call: the quote came back with the customer's name, materials supply and agreed costs all missing. Not because the call ended early — because Motko never asked.

Two different failures:

1. **Customer's name**: Not in `CHECKLIST_QUESTION_IDS` at all. It's a paragraph of prompt instruction with no `askQuestion` call, no enforcement mechanism, and no record of whether the model complied. A call wraps cleanly today with no customer name. The wrap-up detour added in #714 (`CUSTOMER_NAME_QUESTION`) covers one exit path but not all.

2. **Materials supply**: IS a required slot and the wrap detour does hold for it, but the question is too narrow. The current question asks only "Who's supplying the materials" (captured in `responsibility`). It doesn't ask HOW MUCH is needed or WHAT SPECIFICALLY — both critical for pricing and purchasing. A call can wrap with `materials_supply` set to `{ responsibility: "contractor", contractor_supplied: [], customer_supplied: [] }` — the question was "answered" but the answer carries no useful information.

## Scope: what changes

### Customer's name becomes a first-class required slot

- Add `"customer_name"` to `REQUIRED_CHECKLIST_QUESTIONS` in `src/lib/schemas/sow.ts`, alongside `crew`, `duration`, `materials_supply`, `working_dates`, and `agreed_costs`.
- Add it to the main `CHECKLIST_QUESTION_IDS` array.
- Add the question text to `CHECKLIST_QUESTIONS` and a label to `CHECKLIST_SLOT_LABELS`.
- Update `getUnansweredChecklistQuestions` to check whether `customer_name` is present (same test as `getMissingCustomerDetails` already uses: not null/undefined and not whitespace-only).
- The wrap-up detour (`concludeOrAskRequired`) already gates on `getUnansweredRequiredChecklistQuestions` — adding `customer_name` there is sufficient to hold every exit path, not just the one #714 covered.

### Materials supply question widened to capture all three parts

Extend `materialsSupplySchema` in `src/lib/schemas/job.ts` to add:

- `quantity_guidance`: `z.string().optional()` — how much is needed, in the contractor's words. Examples: "about fifteen metres of cable", "twelve sheets of plasterboard", "you work it out". The last one is a storable answer distinct from silence: the contractor deferred the quantity to Motko on purpose, which is a decision recorded.
- `materials_detail`: `z.string().optional()` — what specifically is needed, again in their words. Examples: "twin and earth", "12.5mm tapered edge board", "standard 13A sockets". Free text rather than enforcing the arrays, because a contractor saying "standard domestics, nothing fancy" has answered the question even if the model does not parse it into a list.

Both fields are OPTIONAL because old rows must parse unchanged, and because a genuinely unanswerable question ("haven't sized it yet") should not trap a wrap. The slot is considered ANSWERED when `responsibility` is set AND at least one of the two new fields is present. An empty object or one with only `responsibility` is NOT answered.

Update the question in `CHECKLIST_QUESTIONS` to:
```
"Who's supplying the materials for this job — you, or the customer? And roughly how much do you need, and what specifically?"
```

Update `SOW_DELTA_TOOL_PARAMETERS.materials_supply` to document the two new fields and instruct the model to ask for both.

Update the merge logic in `mergeSowDelta` to handle the two new fields using last-value-wins (like other string fields), not append-dedupe.

## Explicitly out of scope

- **Contact details and site address**: Deliberately absent per Jacob's decision of 12 Sep. A contractor mid-call does not know their customer's email off by heart. Motko takes them if volunteered but never holds a wrap for them. The capture path already exists in the quote editor (Site address, email, phone fields, `hasContactChannel`, and a graceful no-channel send).

- **Moving `askedRequiredSlotsRef` out of telemetry**: The note says "a signal that must change behaviour cannot terminate in telemetry", and `askedRequiredSlotsRef` currently reaches the server only to build an analytics event. That refactor is not this ticket — this ticket makes the slots themselves enforceable (adds `customer_name` as a checklist slot, widens `materials_supply` so answering it means something), which is the prerequisite. Using `askedRequiredSlotsRef` to surface "we never asked" flags on the job page is a follow-on.

- **Agreed costs**: Already promoted to required on 8 Sep (P2-13), recorded in `areas/motko.md`. This ticket changes nothing about it.

## Files

- `src/lib/schemas/job.ts` (modify) — extend `materialsSupplySchema` with `quantity_guidance` and `materials_detail`
- `src/lib/schemas/sow.ts` (modify) — add `customer_name` to `CHECKLIST_QUESTION_IDS`, `REQUIRED_CHECKLIST_QUESTIONS`, `CHECKLIST_QUESTIONS`, and `CHECKLIST_SLOT_LABELS`; update `CHECKLIST_QUESTIONS.materials_supply` text; update `getUnansweredChecklistQuestions` to check `customer_name`; update `SOW_DELTA_TOOL_PARAMETERS.materials_supply` description and properties; update `mergeSowDelta` materials_supply merge logic
- (no component changes needed — the wrap-up detour already gates on `getUnansweredRequiredChecklistQuestions`, so promoting `customer_name` there is sufficient)

## Edge cases

- **Old rows without the new fields**: Both `quantity_guidance` and `materials_detail` are optional, so every existing `materials_supply` object parses unchanged. The "is answered" check must account for rows written before this item.

- **A contractor who genuinely doesn't know**: "You work it out" in `quantity_guidance` or "Standard stuff" in `materials_detail` answers the slot — it records that the question was asked and deferred. Absence of both means the question never landed.

- **A customer-supplied job with no contractor materials**: `{ responsibility: "customer", quantity_guidance: "two tins", materials_detail: "white emulsion" }` answers the slot even though `contractor_supplied` is empty — the question is about the job's materials, not only what the contractor brings.

- **Customer's name is whitespace-only**: The check must treat `"   "` as missing, matching `getMissingCustomerDetails`. Use `.trim()` before testing presence.

- **A declined slot**: If `declined_slots` contains `"customer_name"` or `"materials_supply"`, the slot is filtered out of `getUnansweredChecklistQuestions` and does not block a wrap. This is the existing behaviour for all checklist slots and must hold for the newly-promoted one.

## Risks

- **Schema change touching a shared type**: `materialsSupplySchema` is imported by both `job.ts` and `sow.ts`. Adding optional fields is safe (no migration needed, old rows parse unchanged), but the type change propagates to every call site. Existing acceptance tests using `materials_supply` fixtures may need widening per AGENTS.md's "Widening a frozen fixture" rule — but only if a test explicitly builds a `MaterialsSupply` literal and the new fields are made required. They are optional here, so no widening is forced.

- **The "is answered" rule is load-bearing**: A slot considered answered when it carries no useful information is the failure mode this exists to fix. The rule must be: `responsibility` is set AND (`quantity_guidance` is present OR `materials_detail` is present). Presence means non-null, non-undefined, and (for strings) non-empty after trim. Test both positive and negative cases.

## Derived criteria

1. `customer_name` appears in `CHECKLIST_QUESTION_IDS` and `REQUIRED_CHECKLIST_QUESTIONS`.
2. `CHECKLIST_QUESTIONS` carries an entry for `customer_name` asking for the customer's name.
3. `CHECKLIST_SLOT_LABELS` carries a short label for `customer_name`.
4. `getUnansweredChecklistQuestions` returns `"customer_name"` when `sow.customer_name` is null, undefined, empty, or whitespace-only.
5. `getUnansweredChecklistQuestions` does NOT return `"customer_name"` when `sow.customer_name` is a non-empty string.
6. A SoW with every checklist slot filled EXCEPT `customer_name` reports `customer_name` as unanswered.
7. `materialsSupplySchema` accepts `quantity_guidance` and `materials_detail` as optional strings.
8. `SOW_DELTA_TOOL_PARAMETERS.materials_supply.properties` documents both new fields.
9. The materials supply question in `CHECKLIST_QUESTIONS` asks for who supplies, how much, and what specifically — all three parts in one question.
10. A `materials_supply` object with only `responsibility` set (no arrays, no `quantity_guidance`, no `materials_detail`) is NOT considered answered by `getUnansweredChecklistQuestions`.
11. A `materials_supply` object with `responsibility` AND `quantity_guidance` (even if `materials_detail` is absent) IS considered answered.
12. A `materials_supply` object with `responsibility` AND `materials_detail` (even if `quantity_guidance` is absent) IS considered answered.
13. The merge logic in `mergeSowDelta` handles `quantity_guidance` and `materials_detail` with last-value-wins, falling back to the base value when the delta omits them.
14. Old rows with `materials_supply` objects lacking the new fields parse unchanged through `materialsSupplySchema`.
15. Whitespace-only strings in `quantity_guidance` or `materials_detail` are treated as absent when determining if the slot is answered.
