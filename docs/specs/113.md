# Issue #113: Add a DOM test environment and shared Capacitor mocks

**Source:** [Notion roadmap item](https://app.notion.com/p/Add-a-DOM-test-environment-and-shared-Capacitor-mocks-3b91e4f908b481ae9888c72c5e14d38d)

**Requires database migration:** No

---

## Problem

The test harness cannot exercise any DOM or native behaviour. The global vitest config sets `environment: "node"` with no setup file, no DOM library is installed (jsdom/happy-dom), no tests render components, and no test has ever mocked a `@capacitor/*` plugin despite five plugins being installed. The 15 `vi.mock` calls in the repo all target first-party `@/lib/*` modules. Roadmap items #95 (app lifecycle resume) and #96 (haptics) both overran the turn cap at 55 and 57 turns while six comparable items finished in 20-43 — they are the only two requiring tests for native/DOM behaviour. Every future Capacitor or component item pays this cost separately, each inventing incompatible mocking approaches.

## Scope: what changes

1. **DOM environment available per-file**: Tests that need the DOM opt in via a `@vitest-environment` directive at the top of the file. The existing node-environment suite remains untouched — this is additive, not a migration.

2. **Install a DOM library**: Add `happy-dom` (or `jsdom`) to devDependencies so DOM-environment tests can render components and fire interactions.

3. **Shared Capacitor mock helpers** at `tests/helpers/capacitor.ts`:
   - `mockNativePlatform(isNative: boolean)`: mocks `@capacitor/core`'s `isNativePlatform()` so a test can run as native or web. Defaults to web (false) so tests that don't opt in behave exactly as today.
   - `mockCapacitorPlugins()`: mocks the installed plugins (@capacitor/app, @capacitor/haptics, @capacitor/push-notifications, @capacitor/share, @capacitor/splash-screen) with spy-instrumented stubs, recording every call for assertion. Call records reset between tests via vitest's `beforeEach`.

4. **Example tests** proving both paths:
   - One DOM test that renders a component, fires a user interaction, and asserts a mocked plugin was called with expected arguments.
   - One test asserting the web path is a no-op (native guard returns early, plugin never called).

5. **Documentation** in `AGENTS.md`:
   - How to opt a test into the DOM environment
   - How to use the shared Capacitor mock helpers
   - When to use DOM vs node environment

## Explicitly out of scope

- Do **not** implement #95 (lifecycle resume) or #96 (haptics) user-facing features — this is test infrastructure only.
- Do **not** add haptics, lifecycle, or other user-facing behaviour to the app.
- Do **not** migrate existing node-environment tests to DOM.
- Do **not** add end-to-end or browser-driver testing (Playwright already installed but unused for this).
- Do **not** change Capacitor configuration, add Capacitor plugins, or modify the iOS project.
- Do **not** change CI pipelines beyond what running the existing + new tests requires.

## Files

Expected touches:

- `vitest.config.ts` — no change required if using per-file `@vitest-environment` directives, but may need to ensure happy-dom is recognized
- `package.json` / `package-lock.json` — add `happy-dom` (or `jsdom`) to devDependencies
- `tests/helpers/capacitor.ts` — **new file** with shared mock helpers
- `tests/acceptance/113.test.ts` — **new file** with acceptance tests
- `AGENTS.md` — append testing conventions section
- Possibly a vitest setup file if global teardown is needed for mock resets (evaluate in implementation)

## Edge cases

1. **Four existing acceptance tests assert against files on disk** — they must keep running in the node environment. Per-file selection, not a global switch, is mandatory.

2. **Default must be web** (isNativePlatform false) so any test that does not explicitly opt into native mode behaves exactly as it does today. No implicit native mode.

3. **A plugin that is not installed must not be mocked into existence** — mocking a plugin the app does not depend on would let a spec pass against an API that is not there. Only mock the five installed plugins: @capacitor/app, @capacitor/haptics, @capacitor/push-notifications, @capacitor/share, @capacitor/splash-screen.

4. **Mock call records must reset between tests** via vitest's `beforeEach`, so one test's calls cannot satisfy another's assertion. The shared helper should handle this automatically.

5. **A test that opts into the DOM environment but asserts nothing DOM-related must still pass** — the environment itself introduces no failures.

6. **CI must not require a native build or simulator** to run these tests. Mocks replace the actual native layer.

7. **Empty state**: A test that mocks native mode but never calls any plugin method should pass — mocking the environment is not the same as asserting plugin calls happened.

8. **Failure mode**: If a test asserts a plugin call that never happened, the test must fail with a clear message showing what was expected vs what was recorded.

## Risks

- **None touching money, migrations, or user data** — this is test infrastructure only, no production code path changes.
- **Regression risk**: The full existing test suite (57 files, 538 tests) must pass unchanged before and after. This is the primary acceptance gate.
- **Maintenance risk**: If the shared mock helpers become stale (e.g. a plugin upgrades its API), tests may pass against an outdated mock. Mitigation: keep mocks minimal (just enough to record calls), avoid reimplementing plugin logic.

## Derived criteria

The human is asking for:

1. A way for a test file to opt into a DOM environment without affecting other tests (per-file selection).
2. A DOM library installed so components can be rendered and interacted with.
3. A single shared helper that mocks `Capacitor.isNativePlatform()` to control native vs web branching in tests.
4. A single shared helper that mocks the five installed Capacitor plugins, recording all calls for assertion.
5. One example test showing the full DOM path: render → interact → assert plugin called.
6. One example test showing the web path: assert native guard short-circuits, plugin never called.
7. Documentation in AGENTS.md so future PM agent runs know the convention.
8. The existing 538 tests across 57 files must pass unchanged — this is additive scaffolding, not a rewrite.
9. Mock call records auto-reset between tests so tests are isolated.
10. Default to web (isNativePlatform false) so tests that don't opt in behave as today.
11. CI runs these tests without requiring a native build or simulator.
