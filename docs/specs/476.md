# FEE-6: Replace flat fee bands with a marginal ladder on net job value

## Problem

The motko fee is currently a flat two-band structure (£2 up to £1,000, £4 above). Under any flat structure the fee is either loss-making at the bottom or arbitrary at the top, and it does not scale with the value of the work motko is doing. The flat cap means a £1,500 job and a £50,000 job both pay £4, which under-values motko's service on high-value work. Additionally, motko absorbs Stripe's processing cost (see FEE-7), so several job values settle net negative for motko.

## Scope

Replace the flat-band fee calculation in `motkoFeePennies` with a marginal percentage ladder charged to the tradesperson:

**Ladder structure:**
- First £5,000 of net job value: 0.3% (30 basis points)
- Next £5,000 (£5,001–£10,000): 0.2% (20 basis points)
- Above £10,000: 0.15% (15 basis points)
- Floor: £2.00 (200p) — if computed fee is below this, charge the floor
- No cap

**Key properties:**
1. **Marginal, not flat.** Each slice is rated at its own rate and the results summed. A £5,001 job must never earn less than a £5,000 job.
2. **Input is net job value** — the quote subtotal, excluding VAT. Read from the quote's stored subtotal. Do not derive by dividing a gross figure by 1.2: domestic reverse charge (gross equals net) and reduced/zero-rated work exist. Deriving would silently undercharge.
3. **Per payment transaction.** The ladder restarts on each payment. A job paid in four instalments runs the ladder four times.
4. **Round half up** to the nearest penny, once, after summing all slices — not per slice.
5. **Rates, breakpoints and floor live in fee configuration** — the same constant the rest of the fee path reads. No second constant. This is a TypeScript constant, not a database table.

**Worked values (net job value → service fee):**
- £500 → £2.00 (floor applies)
- £666.67 → £2.00 (exactly at floor boundary)
- £1,000 → £3.00
- £2,500 → £7.50
- £5,000 → £15.00
- £7,500 → £20.00
- £10,000 → £25.00
- £22,000 → £43.00

## Edge cases

**Quote subtotal missing or null:** Fail loudly. Do not fall back to gross transaction amount — that is the silent-undercharge path this ticket exists to close.

**Payment amount differs from quote subtotal** (part payment, deposit, variation): Rate the ladder on the amount actually being taken, net of VAT, not on the original quote total.

**Non-integer pence from percentage maths:** Resolved by the single round-half-up at the end. Assert that the persisted `fee_amount_pennies` is always an integer.

**Zero or negative net value:** Return the floor (200p), not a negative or zero fee. A free quote should not produce a negative fee.

**Existing settled rows:** Keep their historical fee values untouched. No backfill, no recalculation.

**VAT on motko's own fee:** The existing `fee_net_pennies` and `fee_vat_pennies` columns already handle this. Once motko is VAT-registered, the ladder output is the net fee and VAT is added on top (£15.00 becomes £18.00 at a £5,000 job). Confirm the existing split still computes correctly against ladder values.

**Boundary behaviour:** The floor binds below £666.67. At exactly £666.67, the computed fee equals £2.00. The breakpoints at £5,000 and £10,000 are inclusive of the lower band (£5,000.00 is charged at 0.3% for the full amount; £5,000.01 charges £15.00 for the first slice plus 0.2% on £0.01).

## Risks

**Money.** Fee calculation affects what contractors are charged. Any defect here is a pricing defect.

**Monotonicity.** The fee must never decrease as job value increases. This is enforced by the marginal structure, but incorrect breakpoint handling could break it.

**Gross vs net confusion.** Passing a gross (VAT-inclusive) amount where net is expected causes a 20% overcharge for VAT-registered contractors and correct charging for unregistered ones — an inconsistency that would be invisible in testing if only one contractor type is exercised.

**No migration required.** This is a pure calculation change. The database schema is unchanged.

## Derived criteria

1. The fee for any net job value is computed via a three-tier marginal ladder (0.3% / 0.2% / 0.15%) with a £2.00 floor, charged to the tradesperson.
2. The fee is strictly monotonic: increasing the net job value never decreases the fee.
3. Worked values (£500 / £1,000 / £2,500 / £5,000 / £7,500 / £10,000 / £22,000) return exactly (200p / 300p / 750p / 1500p / 2000p / 2500p / 4300p).
4. Boundary cases return correct values: £666.66 → 200p, £666.67 → 200p, £5,000.00 → 1500p, £5,000.01 → 1500p, £10,000.00 → 2500p, £10,000.01 → 2500p.
5. Zero or negative net value returns the floor (200p), not zero or a negative fee.
6. The fee is computed from the quote subtotal (net of VAT). A VAT-registered contractor and an unregistered contractor with the same subtotal produce an identical fee.
7. A job under domestic reverse charge (no VAT line) produces the same fee as an equivalent standard-rated job of the same subtotal.
8. Changing a rate, a breakpoint or the floor in fee configuration changes the output with no code change.
9. No call site charges on a gross amount. Every caller of `motkoFeePennies` produces the same fee for a VAT-registered and an unregistered contractor at the same subtotal.
10. The persisted `fee_amount_pennies` is always an integer (never fractional pence).
11. The existing VAT split (`fee_net_pennies` and `fee_vat_pennies`) computes correctly against ladder-derived fees.
12. All 15 assertions listed in the issue body are retired in the first commit, with their `describe` wrappers removed if emptied.
