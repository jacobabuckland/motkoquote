# Issue #148: Add a dwell to the Sent terminal state before navigating

**Source:** [Notion roadmap item](https://app.notion.com/p/Add-a-dwell-to-the-Sent-terminal-state-before-navigating-3b81e4f908b48195a2ddf769cbdd20c3)  
**Module:** ui

## Problem

The quote editor (`quote-editor.tsx:319`) sets the terminal "Sent ✓" label and immediately calls navigation, so the label renders for approximately one frame. This violates the CLAUDE.md requirement that the terminal state must be shown. Sending a quote is one of the four moments that matter, and it currently produces no confirmation the user can register.

## Scope: what changes

1. **Send flow timing**: After `setSent(true)`, hold for approximately 450ms before calling `router.push()` and `router.refresh()`.

2. **Visual feedback during dwell**: 
   - Add a "green wash" effect to the button during the success state (a subtle green background tint, using the `--success` or `--color-primary` token)
   - Apply a check-draw animation (a checkmark that draws itself in, similar to success confirmations in other apps)
   - The button continues to show "Sent ✓" text during the dwell

3. **Haptic feedback**: Fire a light haptic (`Haptics.impact({ style: "light" })`) when the terminal state is set.

4. **Navigation control**:
   - Navigation must occur exactly once after the dwell
   - Repeated button presses during the dwell must not trigger additional navigations
   - The dwell timer must be cancelled if the component unmounts
   - If the user navigates back during the dwell, cancel the pending navigation

5. **Reduced motion support**: Under `prefers-reduced-motion: reduce`, retain the 450ms dwell duration but render the check in its final state without animation.

6. **Error path unchanged**: If sending fails (the catch block), no dwell occurs and the error displays immediately as it does today.

## Explicitly out of scope

- Do not change send logic, retry behaviour, or error handling beyond the success path
- Do not change the destination route or query parameters
- Do not add a cancel or undo affordance during the dwell
- Do not apply this pattern to the signed or paid moments (those are separate)
- Do not modify CLAUDE.md

## Files

- `src/app/jobs/[id]/quote-editor.tsx` — add dwell timer, haptics call, success state styling
- `src/app/globals.css` (or new file) — add check-draw keyframe animation
- `tests/acceptance/148.test.tsx` — acceptance tests

## Edge cases

| Scenario | Expected behaviour |
|----------|-------------------|
| User presses back during dwell | Cancel the pending navigation timer and do not navigate afterwards |
| Component unmounts during dwell | Cancel the timer, no navigation, no warning |
| Send resolves after user has left screen | No dwell, no navigation (component is unmounted) |
| Repeated send presses | First press resolves and starts the dwell. Subsequent presses are inert because the button is disabled (`sent \|\| isSending` is true) |
| Send fails (catch block) | No dwell, no haptic, error displays immediately. Existing behavior unchanged |
| Legacy persisted data | None (this is a runtime-only UI state change) |
| Reduced motion preference | Dwell duration retained, check renders in end state without animation |

## Risks

- **Timing race**: If the router navigation somehow fires before the timer completes (e.g., due to state updates triggering re-renders), navigation could occur prematurely. Use a ref to track the navigation intent and ensure it only fires once.

- **Memory leak**: If the component unmounts during the dwell, the timer must be cleared to avoid attempting to call `router.push()` on an unmounted component. Use cleanup in `useEffect` or similar.

- **Perceived delay**: The 450ms dwell adds noticeable latency to the "send quote" → "view job" flow. This is intentional (per the requirement to show the terminal state), but contractors may perceive it as sluggishness. The visual feedback (green wash + check animation) should make the delay feel like confirmation, not waiting.

## Derived criteria

The Engineer will implement:

1. A ~450ms timer that delays navigation after a successful send
2. The "Sent ✓" button state remains visible for at least 400ms before navigation
3. A green wash (subtle green background) applied to the button during the success state
4. A check-draw animation that animates a checkmark drawing in during the dwell
5. A haptic impact call (`Haptics.impact({ style: "light" })`) fired when the success state is set
6. Navigation occurs exactly once after the dwell, and cannot be triggered by repeated presses
7. The dwell timer is cancelled if the component unmounts before it fires
8. Under reduced motion, the dwell duration is retained but the check renders without animation
9. The error path (send failure) remains unchanged — no dwell on error
10. The button remains disabled during the dwell (already true via `sent || isSending`)

## Implementation notes

**Animation primitive**: The issue references "the check-draw keyframe from the animation primitives item", but no such keyframe currently exists in `globals.css`. The Engineer should create a `@keyframes check-draw` animation that draws a checkmark path over ~300ms. Reference: iOS/Android success animations, where the checkmark strokes in from left to right.

**Haptics wrapper**: The issue references `haptics.tap()`, but no such utility exists. The Engineer should call `Haptics.impact({ style: "light" })` directly from `@capacitor/haptics`. If a wrapper is needed for consistency, it can be added, but the acceptance tests will verify that `Haptics.impact()` is called.

**Green wash**: Apply a success background color to the button during the `sent` state. Suggested: `bg-success/10` or `bg-primary/10` (using Tailwind's opacity syntax), or a custom class that uses `var(--success-bg)`.

**Timer management**: Use a `useRef` to track the navigation timer, and clear it in cleanup. Example pattern:
```tsx
const navigationTimer = useRef<ReturnType<typeof setTimeout> | null>(null);

useEffect(() => {
  return () => {
    if (navigationTimer.current) {
      clearTimeout(navigationTimer.current);
      navigationTimer.current = null;
    }
  };
}, []);
```

**Navigation guard**: To prevent double-navigation if the user hammers the button, ensure navigation only fires once. The button is already disabled when `sent` is true, which should prevent re-clicks, but the timer should also check that navigation hasn't already occurred before calling `router.push()`.
