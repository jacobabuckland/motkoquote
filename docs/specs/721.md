# Issue #721: Motko must ask who the quote is for, and the full materials question

## Problem

Voice intake is inconsistent about capturing essential job information. Calls wrap cleanly while missing the customer's name (reported 12 Sep from a live quote) or materials supply details. `customer_name` exists as a field but has no enforcement mechanism — it's a paragraph of prompt instruction with no `askQuestion` call, no checklist entry, and no record of whether it was asked. Materials supply is recorded but incompletely: the current question asks who supplies them but not roughly how much is needed or what specifically, so pricing has insufficient context.

## Scope: what changes

### Customer name becomes a first-class checklist slot

1. Add `customer_name` to `CHECKLIST_QUESTION_IDS` as a seventh slot
2. Add `customer_name` to `REQUIRED_CHECKLIST_QUESTIONS` so it gates wrap
3. Add entry to `CHECKLIST_QUESTIONS` with the question text
4. Add entry to `CHECKLIST_SLOT_LABELS` for the job-page banner
5. Update `getUnansweredChecklistQuestions` to check `customer_name` answeredness

The wrap detour mechanism (#716, `concludeOrAskRequired`) already routes every exit path through `getUnansweredRequiredChecklistQuestions`, so promoting `customer_name` to a required checklist slot is sufficient to hold every exit. No component change needed.

### Materials supply widened to three parts

1. Add `quantity_guidance` field to `materialsSupplySchema` (in `src/lib/schemas/job.ts`)
   - Type: `nullishString` (consistent with other optional text fields)
   - Accepts "you work it out" as a storable answer, distinct from silence
2. Update materials supply answeredness check: both `responsibility` AND `quantity_guidance` must be set
3. Update `SOW_DELTA_TOOL_PARAMETERS.materials_supply` description to prompt for all three parts

The existing arrays (`contractor_supplied`, `customer_supplied`) already handle "what specifically", so no schema change needed there.

## Explicitly out of scope

- **Contact details and site address** — not promoted to checklist slots. A contractor mid-call doesn't know their customer's email off by heart (Jacob, 12 Sep). These flow through the existing capture path in the quote editor, with its graceful no-channel send.
- **Changing how checklist slots are asked** — the question flow and turn budget are unchanged.
- **Modifying `getMissingCustomerDetails`** — that function's blocking list (`customer_name`, `customer_contact`) remains as-is; only the checklist enforcement changes.

## Files

### Modify
- `src/lib/schemas/sow.ts` — add `customer_name` to lists, update answeredness checks
- `src/lib/schemas/job.ts` — widen `materialsSupplySchema` with `quantity_guidance`
- `src/lib/voice/job-intake-prompt.ts` — update tool description (if materials guidance lives there)
- `src/lib/schemas/sow.test.ts` — update fixture expectations for widened required list

### Call sites that pass `materials_supply` through (grep for callers)
None expected beyond schema/test files — the field is constructed via `update_sow` tool calls and merged by `mergeSowDelta`, not passed as parameters.

## Edge cases

### Customer name
- **Empty string or whitespace-only** — treated as unanswered (existing `trim()` logic)
- **Declined** — if added to `declined_slots`, does not block wrap (existing filter in `getUnansweredChecklistQuestions`)

### Materials quantity guidance
- **"You work it out"** — stored as-is; a valid answer distinct from null/undefined
- **No guidance given but responsibility stated** — slot reads as unanswered (the change)
- **Both fields present** — slot is answered

### Integration with existing wrap logic
- `concludeOrAskRequired` already gates on `getUnansweredRequiredChecklistQuestions`
- All three exit paths (`maybeStartFollowups` no-follow-ups, `askNextQuestion` drain, wrap detour) route through it (#716)
- No new gate needed — the promotion is enforcement

## Risks

- **Type safety on customer_name** — the field is `nullishString`, which transforms `null` to `undefined`. Tests must use `undefined` or omit the field, never `null`, or they freeze with TS2322.
- **Materials answeredness tightening** — existing SoWs with only `responsibility` set will now read as unanswered. Verify no production data is affected, or handle migration if needed.
- **Regression test sensitivity** — `tests/regression/every-wrap-asks-the-customer-name.test.tsx` asserts the wrap-detour behaviour. Once `customer_name` is a checklist slot, it's asked in the flow, not at the detour. That test's structural cases (cannot end with name outstanding, does not ask when present) remain valid; rewrite assertions to observe the name being asked wherever the new flow asks it.

## Derived criteria

1. `customer_name` appears in `CHECKLIST_QUESTION_IDS` as a seventh entry
2. `customer_name` appears in `REQUIRED_CHECKLIST_QUESTIONS`
3. `CHECKLIST_QUESTIONS` carries a question for `customer_name`
4. `CHECKLIST_SLOT_LABELS` carries a label for `customer_name`
5. `getUnansweredChecklistQuestions` returns `["customer_name"]` when the name is missing
6. `getUnansweredRequiredChecklistQuestions` returns `["customer_name"]` when the name is missing and other required slots are satisfied
7. `materialsSupplySchema` gains a `quantity_guidance` field of type `nullishString`
8. A `materials_supply` object with only `responsibility` set is considered unanswered
9. A `materials_supply` object with both `responsibility` and `quantity_guidance` set is considered answered
10. `materials_supply` with `responsibility` alone does NOT satisfy `getUnansweredChecklistQuestions` (it still appears in the unanswered list)
