# CLEAN-4: Correct the false fee note in .env.example

## Problem

`.env.example` lines 38–40 carry a note claiming the motko fee is "the flat, capped £2/£4 defined in src/lib/motko-fee.ts". This is false. The code has never implemented a flat, capped fee. It implements a marginal percentage ladder — 0.3% of the first £5,000, 0.2% of the next £5,000, 0.15% above £10,000, with a £2.00 floor and no cap. The note describes a third model matching neither the code nor any recorded decision. Anyone configuring an environment reads it and reasons about the fee from a figure that has never been what the code does.

## Scope

Correct the fee note in `.env.example` to accurately describe the marginal percentage ladder implemented in `src/lib/motko-fee.ts`.

## Explicitly out of scope

- Changing the fee schedule itself (CLEAN-6 and SUB-3 own that).
- The customer-facing fee copy in `FeesStatementSection` and on the terms page, which already match the code.

## Files

- `.env.example` (modify)
- `tests/acceptance/650.test.ts` (new)

## Edge cases

The note must remain accurate when the fee schedule changes. The acceptance test imports the rate constants and floor from `motko-fee.ts` and verifies the note is consistent with them, so it fails the day the schedule changes rather than silently going stale.

## Risks

This is documentation about money. The false note has been in the tree long enough that someone configuring a new environment may have reasoned from it.

## Derived criteria

- The note in `.env.example` no longer claims a "flat" fee or a "capped" fee.
- The note describes the marginal percentage ladder, the floor, and the absence of a cap.
- The note still states there is no fee env var and the fee is not configurable per environment.
- The acceptance test imports `motkoFeePennies` and the rate constants and verifies the note is consistent with what they compute, so the check survives fee schedule changes.
