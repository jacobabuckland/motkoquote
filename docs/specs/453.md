# DATA-2: Voice cost intake tells every contractor they have no jobs

## Problem

The voice cost capture feature is completely broken. When a contractor logs a cost via voice, the system fetches their recent jobs to present them with options. The query selects three columns that don't exist (`customer_name`, `job_reference`, `updated_at`), PostgREST rejects it, but the error is never checked. The null data gets coalesced to an empty array, so every contractor appears to have no jobs and is told to create one first. The feature cannot work at all.

Confirmed on production 30 Aug 2026: these columns do not exist in the `jobs` table. No migration is needed.

## Scope: what changes

1. **Fix the select in `createCostRealtimeSession`**: Change from non-existent columns to `id, created_at, customer:customers(name)`. The customer relation follows the existing pattern at `src/app/ledger/query-actions.ts:198-200`.

2. **Destructure and check the query error**: Currently `const { data: jobs } = ...` ignores the error. Must destructure both `data` and `error`, check the error, and throw if it's present. A failed query must not present as "no jobs".

3. **Narrow the embedded relation**: PostgREST types embedded to-one relations as arrays. `j.customer?.name` is a compile error. Must narrow to the first element before accessing the name property. Use a placeholder `"(no customer)"` when the customer is null so jobs with no customer still appear.

4. **Remove `job_reference` from the prompt's `JobSummary`** (`src/lib/voice/cost-intake-prompt.ts`), which is a local type nothing else imports.

   **`src/lib/match-job.ts` is a different type and cannot have the field removed.** Two frozen acceptance contracts disagree about it and both must hold: `tests/acceptance/258.test.tsx` constructs summaries with `job_reference` and `updated_at` and asserts matching on both, while `tests/acceptance/453.test.ts` constructs them with `created_at`. A strict shape satisfies one and breaks the other in either direction. Make all three fields optional and have the recency sort fall back `updated_at ?? created_at`; a summary carrying neither sorts last rather than throwing.

5. **Update the rendered job line**: Currently renders `${customer_name} (${job_reference}) — last updated ${updated_at}`. Change to `${customer_name} — created ${created_at}`.

6. **Remove job-reference instructions from the prompt**: Three places in `buildCostIntakeInstructions` mention asking for or matching by job reference. Remove these references, leaving customer name and recency as the two ways to match a job.

7. **Update `match-job.test.ts` test fixtures** to exercise the `created_at` shape. The job-reference matching branch stays and stays reachable in tests, because #258 asserts it; with real data it is unreachable, since `jobs` has no such column.

## Explicitly out of scope

- **Adding a `job_reference` column or human-readable job codes**: Product decision about how jobs are named aloud.
- **Adding `jobs.updated_at`**: Would be a migration, and nothing else needs it.
- **Cleaning up the dead job-reference matching code in `match-job.ts`**: The matcher has a `looksLikeJobReference` function and a branch that tries to match by `job.job_reference`. After this change, that code is unreachable (the field doesn't exist), but removing it is not part of fixing the defect.
- **The other #409 drifts**: `src/app/ledger/query-actions.ts:199` (#454), `src/app/jobs/[id]/pnl-actions.ts` (#457), `src/lib/recover-lost-fees.ts:165` (money path).
- **The matching logic the model performs**: The prompt changes, but the model's logic for matching spoken references to jobs stays the same.
- **`require-contractor.ts` and redirect-on-error**: This call site throws rather than redirecting.

## Files

- `src/app/costs/actions.ts` (modify) — fix the select, destructure and check error, narrow the customer relation
- `src/lib/voice/cost-intake-prompt.ts` (modify) — update JobSummary type, fix the rendered line, remove job-reference instructions
- `src/lib/match-job.ts` (modify) — update JobSummary type
- `src/lib/match-job.test.ts` (modify) — update test fixtures to use created_at
- `tests/regression/schema-in-tree.test.ts` (modify) — retire the `jobs.customer_name` example from the drift canary, which this item repairs; `contractors.mandate_status` remains as a live example so the canary keeps its purpose
- `tests/acceptance/453.test.ts` (new) — acceptance tests

## Edge cases

- **A contractor with genuinely no jobs**: The existing "create one first" instruction is correct and must remain. The distinction is between *no rows returned* and *the query failed*.
- **A job with no customer row** (`customer_id` null): Render it with a placeholder `"(no customer)"` rather than omitting it. A job the contractor can identify is still one they may want to log a cost against.
- **More than 50 jobs**: The `limit(50)` stands unchanged.
- **Jobs are ordered by created_at descending**: Most recent jobs appear first.

## Risks

None. This is data shaping for a voice prompt. No money, no migrations, no stored state changes. The feature is currently inoperative, so the change cannot make it worse.

## Derived criteria

What I understood the issue to be asking for:

1. The query in `createCostRealtimeSession` must select only columns that exist: `id`, `created_at`, and the customer's name via the `customer:customers(name)` relation.
2. A query error must be destructured and checked, and must throw rather than being silently coalesced to an empty array.
3. The embedded `customer` relation must be narrowed from array to single value before accessing `name`, because PostgREST types to-one relations as arrays.
4. `cost-intake-prompt.ts`'s `JobSummary` carries only `id`, `customer_name` and `created_at`. `match-job.ts`'s carries those plus optional `job_reference` and `updated_at`, so that both #258 and #453 typecheck and pass.
5. The rendered job line in the prompt must show `Customer name — created <date>` instead of the current format.
6. The prompt instructions must no longer mention job references as a way to identify a job, leaving only customer name and recency.
7. Test fixtures in `match-job.test.ts` must be updated to use the new field names.
8. A contractor with no jobs still gets the "create one first" message.
9. A job with no customer appears with a placeholder rather than being omitted.
