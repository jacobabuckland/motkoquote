# PRICE-5: Guards for invented spec, unbacked "as agreed", and double-charged bundles

## Problem

Three distinct routes by which invented content is laundered into a document that reads as authoritative, all appearing on one quote:

1. **"As agreed" with nothing behind it (D7)** — The quote printed "Board cost £180 as agreed." underneath a £270 charge. The customer reads a contractor who has been caught overcharging. Nothing was agreed at £270; the model generated the phrase.

2. **Invented specification (D5)** — Brands, finishes, ratings and product details that were never stated, presented with the same confidence as the ones that were.

3. **Double-charging a bundled item (D8)** — Testing was charged at £150 and named inside the £600 line's scope. Billed twice in a single document.

Additionally, two clauses inherited from adjacent cards:

4. **The statement of work carries no pricing** — The SoW is the scope document; the quote is the priced document. No monetary amount may be generated into `additional_items`, `inclusions`, `exclusions`, or any other SoW prose field. (Recorded in areas/motko.md, 28 Aug, Precedent: yes)

5. **An exclusion may not contradict the captured materials answer** — The drafting model does not write a materials-supply claim into exclusions. That question has a structured field and a rendered section of its own.

## Scope: what changes

### D7: "as agreed" may only render from a captured field
The phrase family — "as agreed", "as discussed", "as per our conversation", "as we discussed" — may appear only where a captured field backs it. Never from model generation. Enforced by a CI lint over generated output, so it fails a build rather than reaching a customer. The lint drafts quotes from fixture transcripts and asserts the rendered text contains no "as agreed" unless a captured field backs it.

### D5: No invented specification
No brand, finish, rating or product detail with no transcript source. The drafting prompt constraints forbid inventing specificity: the model may only name brands, finishes, ratings or product details that appear in the transcript.

### D8: Double-charge rejection
Nothing named in a bundled line's scope (`includes_tasks`) may also be charged separately. Enforced by the reconciliation gate PRICE-4 introduced; this item attaches the rule to it. The check flags both the bundled line and the separate charge. An item named in a bundled scope that also appears as a flagged £0/TBC line is NOT rejected (the flagged line is not a charge). Fuzzy matching will over-reject, so prefer under-matching: a missed double-charge is the status quo, while a false rejection blocks a send.

### Inherited clause 4: SoW carries no pricing
Constraint already present in `SOW_DELTA_TOOL_PARAMETERS` (src/lib/schemas/sow.ts) for `inclusions`, `exclusions`, and `additional_items` fields. Regression test already exists at `tests/regression/sow-prose-carries-no-pricing.test.ts` verifying the constraint. No new implementation required.

### Inherited clause 5: Exclusions may not contradict materials answer
Constraint already present in `SOW_DELTA_TOOL_PARAMETERS` (src/lib/schemas/sow.ts) for the `exclusions` field. Regression test already exists at `tests/regression/materials-responsibility-agreement.test.ts` verifying the constraint. No new implementation required.

## Explicitly out of scope: what does not change

- **Legitimate contractor-written notes** — `src/lib/note-channels.ts` carries `customer_note` text the contractor wrote, including "Supplied by you as agreed", which is pinned by `tests/regression/note-channels.test.ts` (if that test exists). That is a captured field and must keep working. The rule is about model generation, not about the phrase.
- **The assumption_note mechanism** in `compile-draft.ts`.
- **Extraction, locking, provenance, and the gate's core reconciliation** — PRICE-1 to PRICE-4.
- **Existing customer-facing copy** that says "as agreed" from a real field anywhere in `src/lib/contracts/templates.ts` or the fee copy.
- **Quotes drafted before this item** — No new lint applies retroactively to stored rows.

## Edge cases

- **The contractor genuinely said "as we agreed"** — It is in the transcript, so it is captured, so it renders. The rule is about origin, not vocabulary.
- **"As agreed" inside a contract template** — `templates.ts` is contractor- and lawyer-authored fixed text, not generated. Out of scope.
- **A brand the contractor named** ("a Hager board") — Stated, so it renders. D5 forbids invention, not specificity.
- **A bundled line whose scope names an item priced at £0/TBC** — The flagged line is not a charge, so this is not a double-charge. Do not reject it.
- **A bundled scope naming something in different words** ("testing and certification" versus a "Part P / EIC" line) — Exact-string matching will miss it; fuzzy matching will over-reject and start refusing correct quotes. Prefer under-matching here and say so: a missed double-charge is the status quo, while a false rejection blocks a send. Where the gate cannot decide confidently, it should not block.

## Risks

- **The double-charge rule can reject a correct quote** — See the fuzzy-matching edge case; the bias is deliberately toward under-matching.
- **The lint runs in CI, so a false positive blocks the build for everyone** — Its fixtures need to be the ones that actually exercise the phrase, not a broad sweep.
- **D7 is the cheap half and lands first** — The "as agreed" lint is independent of both other rules and can ship inside this item before them.

## Derived criteria

### D7: "as agreed" enforcement
1. Drafted output containing "as agreed" (or "as discussed" / "as per our conversation" / "as we discussed") with no backing captured field fails the CI lint.
2. Drafted output containing the same phrase WITH a backing captured field passes.
3. A contractor-written `customer_note` containing "as agreed" is unaffected (if the test exists).

### D5: No invented specification
4. The drafting prompt in `src/lib/claude.ts` explicitly forbids inventing brands, finishes, ratings, or product details not present in the transcript.
5. Given a fixture transcript that names a specific brand (e.g., "Hager board"), drafted output includes that brand.
6. Given a fixture transcript with no brands/finishes/ratings mentioned, drafted output contains no such specificity.

### D8: Double-charge rejection
7. An item named in a bundled line's `includes_tasks` and also charged as a separate non-provisional line is rejected by `reconcileStatedPrice`, naming both.
8. An item named in a bundled scope that also appears as a flagged £0/TBC line (provisional or unpriced) is NOT rejected.
9. The rejection message names the bundled line and the separate charge.

### Inherited clause 4: SoW carries no pricing
10. `SOW_DELTA_TOOL_PARAMETERS` descriptions for `inclusions`, `exclusions`, and `additional_items` contain "NO MONETARY AMOUNTS".
11. Each field's description says "belongs on the quote" (where stated prices should appear).
12. Each field's description gives the worked contrast ("two extra double sockets", not "two extra double sockets at £85 each").
13. `tests/regression/sow-prose-carries-no-pricing.test.ts` passes unmodified.

### Inherited clause 5: Exclusions may not contradict materials answer
14. `SOW_DELTA_TOOL_PARAMETERS` description for `exclusions` contains "NEVER state who supplies materials".
15. The description references `materials_supply` as the structured field that owns that question.
16. `tests/regression/materials-responsibility-agreement.test.ts` passes unmodified.

### CI lint
17. `scripts/check-generated-language.mjs` exists and can be invoked.
18. The lint fails when fixture-drafted output contains unbacked "as agreed".
19. The lint passes when no such phrases appear.
20. The lint asserts on drafted output for fixture transcripts, not on a regex over files under `src/`.
21. `.github/workflows/ci.yml` runs the lint in the `gate` job.
