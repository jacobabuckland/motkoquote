# Issue #352: A /join/<code> landing route for referral links

## Problem

The current referral share link (`/signup?ref=CODE`) drops referred trades straight onto a password form with no context about what Motko is, who referred them, or what they get. That is the whole ask, up front, from someone who has been told nothing about the product beyond "try this". There is no room to say what the product does or acknowledge the referral.

A landing page that names the product and the referral offer before asking for anything gives the referee enough context to decide whether to proceed.

## Link shape (DECIDED 2026-08-26)

`/join/<code>` — the code is a path segment. `?ref=` keeps working indefinitely for links already in circulation.

Rationale: A path segment survives share sheets and messaging apps that trim query parameters, and it reads as a destination rather than a tracking URL. `extractReferralCode` already parses a bare code, so the path form needs no new parser. Retaining `?ref=` costs one line and the alternative is breaking every link a trade has already sent.

Decision recorded in `areas/motko.md`, 2026-08-26.

## Scope: what changes

1. **A new `/join/[code]` route** (`src/app/join/[code]/page.tsx`) that:
   - Accepts a referral code as a dynamic path parameter
   - Calls `captureReferralCode(window.location.href)` on arrival to hold the code
   - Displays the product name (Motko) and acknowledges the referral
   - States the referral offer conservatively — name what the **referrer** gets, not what the referee receives (the latter is being corrected in #351 and may overstate)
   - Provides a clear path to proceed to `/signup`
   - Handles invalid or malformed codes gracefully — still shows the landing page and allows proceeding to signup, rather than dead-ending

2. **A loading skeleton** (`src/app/join/[code]/loading.tsx`) for the route, matching the pattern used elsewhere in the app (see `src/app/loading.tsx`).

3. **Mark the route as public** in `src/lib/supabase/middleware.ts` so unauthenticated visitors can reach it. Add `request.nextUrl.pathname.startsWith("/join/")` to the `isPublicRoute` condition.

## Explicitly out of scope

- **The persistence layer** (`src/lib/referral-capture.ts`) — already built and shipped in PR #350. Do NOT rebuild it. The integration is one line: `captureReferralCode(window.location.href)`.
- **The typed referral field on `/signup`** — already exists and works. Do NOT modify it.
- **The `?ref=` path on `/signup`** — already works, covered by `tests/regression/signup-referral-field.test.tsx`. Do NOT break it.
- **Updating the share link in settings** — that happens separately once the route is live.
- **Detailed referral offer copy** — state it conservatively (what the referrer gets), do not overstate what the referee receives.

## Edge cases

1. **Valid code** (6 characters, alphabet `ABCDEFGHJKLMNPQRSTUVWXYZ23456789`, no `I`/`O`/`0`/`1`):
   - Examples: `TRADE9`, `XYZ999`, `NEW888`, `TEST99`, `DAN4K2`, `QRS789`
   - Render the landing page, capture the code, allow proceeding to signup

2. **Invalid code** (wrong length, forbidden characters, malformed):
   - Still render the landing page
   - Still allow proceeding to signup
   - The code simply won't be captured or redeemed
   - This is deliberate: losing a referral is better than dead-ending a signup

3. **Missing code** (`/join` with no segment, or `/join/`):
   - Next.js will 404 (no page.tsx at `/join`)
   - This is expected and correct — the route is for arriving **with** a code

4. **Code persistence**:
   - `captureReferralCode` writes to localStorage via `rememberReferralCode`
   - Survives tab close, reload, detour to /login
   - Read back later by `/signup` via `recallReferralCode()`
   - Cleared after signup via `forgetReferralCode()` (already implemented)

## Risks

None. This is a public landing page with no data mutations, no auth surface changes, and no money impact. The persistence layer is already tested and shipped. The existing `?ref=` path continues working exactly as it does today.

## Derived criteria

The Engineer's implementation must satisfy these criteria:

1. A visitor arriving at `/join/TRADE9` sees a landing page that names Motko and acknowledges the referral
2. The landing page calls `captureReferralCode(window.location.href)` on mount
3. The code is held in localStorage and can be read back via `recallReferralCode()`
4. The visitor can proceed to `/signup` from the landing page
5. An invalid code (`/join/INVALID`) still shows the landing page and allows proceeding, rather than erroring or blocking
6. The route is public — `src/lib/supabase/middleware.ts` includes `/join/` in the public routes check
7. A `loading.tsx` file exists for the route (required by `tests/acceptance/200.test.tsx`)
8. Signing up with `?ref=CODE` still works exactly as it does today (verified by the existing regression test, which must not be modified)
