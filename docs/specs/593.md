# DOCS-2: A ticket may not cite a document the factory cannot open

**Source:** docs/specs/motko-pre-launch-spec.md §5, order 2 of 34.
**No dependency** — DOCS-1 was done by hand on 5 Sep, so no citation in the tree is currently unresolved and this can be built against a clean baseline.

## Problem

The rule exists in prose but was broken immediately by the person who wrote it: a draft of the pre-launch spec introduced the constraint "a failing citation is fixed by committing the document, never by removing the backticks" and, one section later, converted three backticked citations to prose. That is what rules do and checks do not.

AGENTS.md records the same shape: the source-text prohibition was violated five times in two days until `check-acceptance-static.sh` existed — and that check turned out to have a hole of its own, closed on 5 Sep.

A spec or ticket that cites a document that does not exist in the repository creates an unresolvable reference. The citation looks authoritative but leads nowhere, and nothing catches this until a human tries to follow it. This wastes review time and creates ambiguity about whether the missing document was intended to exist or whether the citation should have been prose.

## Scope: what changes

A CI check script (`scripts/ci/check-spec-citations.sh`) that:
1. Extracts backticked references matching `*.md` from all files under `docs/specs/`
2. Resolves each extracted path against the repository root
3. Fails with a non-zero exit code if any path does not exist
4. Names each unresolved path in its output
5. Passes (exit 0) when all citations resolve

The check is added to `.github/workflows/ci.yml` as a new job that runs on all PRs.

A regression test (`tests/regression/spec-citations.test.ts`) verifies the extraction and validation logic can be exercised independently of CI infrastructure.

## Explicitly out of scope

- **Checking links to anything that is not a repo path.** URLs, external documents, or references without the `.md` extension are not validated.
- **Enforcing that cited documents are current rather than archived.** A citation to `docs/specs/archive/old-spec.md` is valid if the file exists, regardless of whether it's superseded.
- **Checking issue bodies or comments.** Only files under `docs/specs/` are scanned. Issue citations are read by humans at roadmap time, not by CI.
- **Prescribing which repair applies when a citation fails.** The check reports the unresolved path but does not dictate whether to commit the missing document or replace the citation with content — that distinction requires human judgment about whether the document was intended to exist.
- **Checking citations in CLAUDE.md, AGENTS.md, or other files outside docs/specs/.**

## Files

- `scripts/ci/check-spec-citations.sh` (new) — the extraction and validation script
- `.github/workflows/ci.yml` (modify) — add the new check as a CI job
- `tests/regression/spec-citations.test.ts` (new) — regression test covering extraction and validation

## Edge cases

**Citation syntax variations:**
- A path in backticks may use single quotes, double quotes, or backticks: `` `path.md` ``, `'path.md'`, `"path.md"` should all be recognized.
- A reference like `docs/specs/archive/draft.md` (absolute from repo root) should resolve correctly.
- A reference like `../sibling.md` or `./local.md` (relative path) should resolve relative to the file being scanned.

**Ambiguous references:**
- A citation like `` `spec.md` `` without a directory is ambiguous. The check should report it as unresolved unless `spec.md` exists at the repository root.
- A reference that matches multiple files (e.g., `spec.md` exists in both `docs/specs/` and `docs/specs/archive/`) is not ambiguous — only exact path matches are validated.

**Empty or malformed citations:**
- An empty citation `` `` `` (backticks with nothing inside) should be ignored, not reported as a failure.
- A citation containing spaces or unusual characters should be extracted verbatim and resolved as-is.

**Prose references without backticks:**
- A phrase like "see the pre-launch spec" (no backticks) is deliberately out of the check's view. The syntax is the opt-in.
- A reference like "the document `pricing-review-aug-2026.md` describes..." with backticks should be checked even if embedded in prose.

## Risks

**False positives from code snippets:**
- A spec that includes a code example containing a backticked path (e.g., showing how to reference a file) might trigger a false positive. The extraction pattern should be specific enough to match document citations, not arbitrary code.
- If false positives become a problem, a comment syntax like `<!-- citation-check: ignore-next -->` could be added later, but is out of scope for this ticket.

**Race condition with DOCS-1:**
- The issue states DOCS-1 landed first, so all current citations should resolve. If this ticket lands before DOCS-1 completes, the check will fail on legitimately missing documents. The spec explicitly states DOCS-1 as a prerequisite.

## Derived criteria

I understood the request to:
1. Create a CI check that extracts backticked `*.md` references from spec files
2. Validate each extracted path exists in the repository
3. Fail CI and name the unresolved path if any citation is broken
4. Pass CI when all citations resolve
5. Ignore prose references (those without backticks)
6. Not prescribe whether a failing citation should be fixed by committing the document or removing the backticks
7. Only check files under `docs/specs/`, not issue bodies or other locations
8. Verify the check works by deliberately introducing a broken citation in a test, then removing it
