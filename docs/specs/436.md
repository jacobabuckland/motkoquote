# UI-1: Send invoice rests on "Sending…" instead of a terminal state

## Problem

The send-invoice button in `src/app/dashboard/create-invoice-form.tsx` violates the settled end-state convention documented in `CLAUDE.md`. On success it calls `router.push` directly from the pending transition without landing on a terminal state first, so a slow or wedged navigation leaves the control stranded mid-spin reading "Sending…". The button must show its terminal label ("Sent ✓") before the navigation fires, exactly as the send-contract flow already does in `create-contract-form.tsx`.

## Scope: what changes

- Add a `sent` boolean state to `create-invoice-form.tsx`
- Add a `navigationTimer` ref to hold the timeout handle
- Add a useEffect to clear the timer on unmount
- On successful send (when `jobId` is present and the action succeeds), set `sent` to true, then wait ~450ms, then call `router.push`
- Update the button label to show "Sent ✓" when `sent` is true, taking precedence over the "Sending…" spinner
- Disable the button once `sent`, so it cannot be submitted twice while navigation is in flight
- Leave the no-`jobId` path unchanged — it sets local `result` state and never navigates, so it needs no terminal button state

The URL construction logic (adding `delivered=0` when the send reached no channel, adding `payout=setup` when payout setup is outstanding) stays exactly as it is. The navigation destination, the URLSearchParams logic, and the single-push choice all stay unchanged.

## Explicitly out of scope

- `src/app/dashboard/create-contract-form.tsx` — already correct, it is the model
- `src/app/dashboard/archive-quote-button.tsx` — already correct
- `src/app/jobs/[id]/mark-as-paid-button.tsx` — deliberately not part of this item
- The banner rendering on `/jobs/[id]` — already handles `sent=invoice`, `delivered=0`, and `payout=setup`
- The `createInvoice` server action — no changes
- The no-`jobId` branch's behaviour (setting local `result` state) — unchanged, but tested

## Files

- `src/app/dashboard/create-invoice-form.tsx` (modify) — add terminal state, dwell timer, disabled-once-sent
- `tests/acceptance/436.test.tsx` (new) — acceptance tests

## Edge cases

- **Send fails** — the error path does not reach the terminal state; the error is shown and the button stays usable
- **Component unmounts during the dwell** — the timer is cleared via the useEffect cleanup, so no state update fires against an unmounted component
- **No `jobId`** — the form sets local `result` state and does not navigate; the new terminal-state machinery must not leak into this path

## Risks

None. This is a client-side button state change with a dwell timer. It does not affect what is sent, what is stored, or what the customer sees.

## Derived criteria

1. After a successful send (with `jobId`), the button's accessible name is "Sent ✓" before any navigation has been observed (before `router.push` is called)
2. When the navigation never completes (a wedged `router.push`), the button stays on "Sent ✓" indefinitely — it never reverts to "Send invoice" or gets stuck on "Sending…"
3. The button is disabled once sent, so a second submit cannot fire while navigation is in flight
4. The pushed URL is unchanged for each variant:
   - Successful send with delivery → `/jobs/{jobId}?sent=invoice`
   - Nothing delivered → `/jobs/{jobId}?sent=invoice&delivered=0`
   - Payout setup outstanding → `/jobs/{jobId}?sent=invoice&payout=setup`
   - Both flags → `/jobs/{jobId}?sent=invoice&delivered=0&payout=setup`
5. A failed send does not reach the terminal state — the error is shown, the button stays usable, and "Sent ✓" is never displayed
6. The no-`jobId` path is unaffected by the new terminal-state machinery:
   - The button never shows "Sent ✓" in this path
   - `router.push` is never called
   - The inline success result is displayed as before
