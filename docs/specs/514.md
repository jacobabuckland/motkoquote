# OBS-1: Instrument the voice funnel end to end

## Problem

There is no way to tell a voice session that never started from one that hung on "Listening" from one that completed. Only `voice_session_completed` is emitted, and only when the caller supplies a wrapReason — so it fires for a call that wrapped cleanly and for nothing else.

Measured on production on 2 Sep: in July, 16 voice sessions completed and 11 job rows were left stranded at `sow_in_progress`, implying a 41% mid-call abandonment rate. In August, 17 of 18 jobs were typed by hand and exactly one voice session ran all month. Whether voice is failing or simply not being reached is currently unanswerable from the data.

## Scope: what changes

1. Add a `run_id` UUID column to the `jobs` table to uniquely identify each voice session
2. Stamp `run_id` when `createRealtimeSession` creates the job, and emit `voice_session_started`
3. Add `recordVoiceSessionAbandonment` server action for client-side abandonment detection (mic denied, connection failed)
4. Add `markOrphanedSessionsAbandoned` function to find sessions stuck in `sow_in_progress` with no completion event, and mark them abandoned server-side
5. Create cron endpoint at `/api/cron/mark-abandoned-sessions` that calls the orphan-marking function
6. Modify existing `voice_session_completed` event to carry `run_id`
7. Emit failure variants when the post-call pipeline fails in `completeSowConversation`
8. Client component calls `recordVoiceSessionAbandonment` when mic permission denied or connection fails

## Explicitly out of scope

- The voice conversation itself, intake prompt, or questions asked
- The run viewer that reads these events (OBS-3)
- Any change to pricing, drafting, or line items
- Changing the structure of the existing `voice_session_completed` payload beyond adding `run_id`

## Edge cases

**Contractor denies the microphone**: The job row already exists (created by `createRealtimeSession`). Client calls `recordVoiceSessionAbandonment` with reason "mic_denied". Must be distinguishable from other abandonment reasons in the event properties.

**Connection fails before the call starts**: Client calls `recordVoiceSessionAbandonment` with reason "connection_failed".

**Tab closes without client-side teardown**: The client cannot emit anything. Server-side cron (`markOrphanedSessionsAbandoned`) finds jobs in `sow_in_progress` status with a `run_id` but no `voice_session_completed` or `voice_session_abandoned` event, and older than 10 minutes. Marks them abandoned with reason "orphaned".

**Session is retried after a pipeline failure**: The retry must share the original `run_id`. A pipeline failure event is emitted with the `run_id`, then if the retry succeeds, `voice_session_completed` carries the same `run_id`. They are one session, not two.

**Manual (typed) quote**: Created via `createManualJob` (not `createRealtimeSession`), so has no `run_id`. Must NOT emit any voice events.

**Pipeline failure in completeSowConversation**: If drafting, knowledge sync, or price compilation fails, emit a `voice_pipeline_failed` event with `run_id`, `stage` (where it failed), and `error` (the error message). This must never block the flow — log the failure and rethrow.

## Risks

- **Event emission must never block or break the caller**: Every `track()` call is already fire-and-forget and never throws. The new events follow the same pattern.
- **Migration timing**: Per CLAUDE.md, the migration adding `run_id` must be applied to production via `supabase db push` BEFORE the PR merges, since `createRealtimeSession` will write to the new column.
- **Orphaned session window**: 10 minutes is the bound. Too short and a slow drafting pipeline gets marked abandoned while still running; too long and the data lags reality. 10 minutes matches the existing pipeline timeout.
- **Idempotency**: The cron must not double-emit `voice_session_abandoned` if it runs twice over the same orphaned session. The cron only emits for sessions with no existing `voice_session_abandoned` or `voice_session_completed` event.

## RUNNABLE

```
curl -X GET https://motko.app/api/cron/mark-abandoned-sessions \

```

(In production, invoked by Vercel Cron on a schedule, e.g., every 15 minutes)

## Derived criteria

- Every job created by `createRealtimeSession` receives a `run_id` and emits exactly one `voice_session_started` event
- A voice session that never reaches `completeSowConversation` (mic denied, connection failed, or tab closed) produces exactly one `voice_session_abandoned` event
- A completed session's `voice_session_started`, `voice_session_completed`, and any `voice_pipeline_failed` events all carry the same `run_id`
- Manual quotes (created outside the voice flow) have no `run_id` and emit no voice events
- Abandonment rate for any date range is computable from the `events` table alone: count `voice_session_started` vs. `voice_session_completed`
- The cron endpoint finds orphaned sessions (stuck in `sow_in_progress` for >10 minutes with no completion event) and marks them abandoned
- A pipeline failure in `completeSowConversation` emits a `voice_pipeline_failed` event but does not prevent the error from propagating to the caller
