## Problem (as originally described)

No unified dispatcher for customer notifications. Each lifecycle send (quote, contract, invoice) was implemented inline. Only the quote path did SMS. Contract and invoice sends were email-only, leaving phone-only customers unreachable after the quote. The `sms_opt_out` flag existed but was only honored at 2 of 5 send sites.

### Edge cases (all handled)
- Email-only customer: SMS not attempted, `sms.attempted === false`
- Phone-only customer: email not attempted, `email.attempted === false`
- Neither channel: `delivered: false`, record still marked sent, no exception
- SMS fails, email succeeds: `delivered: true` (independent channels)
- Both fail: `delivered: false`, record still marked sent
- Twilio/Resend credentials absent: channel returns `{delivered: false}` without throwing
- Phone fails E.164 normalization: treated as no phone, SMS not attempted
- `sms_opt_out = true`: SMS not attempted on any event
- Timeout: channel resolves `{delivered: false}` without blocking the other

### Out of scope (correctly)
- Chase cron (has its own dedup mechanism, already honors `sms_opt_out`)
- Contractor notifications (different recipient, different channels)
- New lifecycle events (`contract_signed`, `payment_received` declared in type but no send sites)
- Retry/queue/dead-letter mechanisms
- Backfills
