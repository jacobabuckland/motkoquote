# Wire the native share sheet for quote, invoice and contract links

## Problem

@capacitor/share is installed but has zero imports. Every link that a trade shares — quote, invoice, contract — goes through a web-style copy-link button. On mobile, which is where most trades work, this forces them to leave the app, open WhatsApp/Messages/Mail, paste, and send. The native share sheet would reach those same destinations in two taps, matching how trades actually send things to customers. The dependency is already installed and paid for; it just needs wiring.

## Scope

Replace `CopyLinkButton` with a new component that:
- On native platforms: invokes `Share.share()` from `@capacitor/share` with a title and the link URL
- On web platforms: preserves the existing copy-to-clipboard behavior unchanged
- Fires `Haptics.impact({ style: "MEDIUM" })` on native when the share sheet is invoked. Uppercase, because `@capacitor/haptics@7` defines `ImpactStyle.Medium = "MEDIUM"` and its implementation compares `style === ImpactStyle.Medium`; the lowercase form type-errors, and if cast past the compiler it silently falls through to the wrong haptic pattern on a device. This is the same finding #96 settled, for `impact` and `notification` alike
- Uses `Capacitor.isNativePlatform()` to detect the platform, the same mechanism the haptics utility would use

This component will replace all instances of `CopyLinkButton` that currently share quote, invoice, or contract links:
- Quote links in the job page (`src/app/jobs/[id]/page.tsx`) and sent banner
- Contract links in the job page, sent banner, and create-contract form (`src/app/dashboard/create-contract-form.tsx`)
- Invoice/payment links in the job page, sent banner, and create-invoice form (`src/app/dashboard/create-invoice-form.tsx`)

The shared content will include:
- A title that identifies what is being sent (e.g. "Quote for [Customer]", "Contract for [Customer]", "Payment link for [Customer]")
- The full link URL, untruncated

A user dismissing the share sheet (without selecting a destination) is a silent no-op — no toast, no error state. This is normal user behavior and not a failure.

## Explicitly out of scope

- Do not change how links are generated or what they point to
- Do not add sharing to surfaces that don't currently offer a link (e.g. the referral section at `src/app/settings/referral-section.tsx` stays copy-only)
- Do not add a custom share UI or destination picker — use the platform's native sheet
- Do not change the copy-link fallback behavior on web platforms
- Do not add analytics on share destination (the platform does not expose which destination the user picked)
- Do not pre-detect or handle "no share targets available" — the platform handles this

## Files

Files expected to change:
- `src/components/ui/copy-link-button.tsx` — either extend or replace with platform-aware sharing
- `src/app/jobs/[id]/page.tsx` — quote, contract, and payment link buttons
- `src/app/dashboard/create-contract-form.tsx` — contract link button after send
- `src/app/dashboard/create-invoice-form.tsx` — payment link button after send

Files that might need reading but should not change:
- `src/app/jobs/[id]/sent-banner.ts` — defines the banner content but doesn't render it; rendering is in page.tsx
- `src/app/settings/referral-section.tsx` — uses CopyLinkButton but for referral codes, which are out of scope

## Edge cases

1. **Share sheet dismissed by user**: Silent no-op. Not an error, no toast. This is normal user behavior.

2. **No share targets available on the device**: The platform handles this. Do not detect or pre-empt it.

3. **Link not yet generated when share is invoked**: This cannot happen — every instance of CopyLinkButton that's in scope already guards on the link existing (e.g. `{quoteUrl && <CopyLinkButton url={quoteUrl} />}`), and the button is never rendered when the link is null. Maintain this invariant.

4. **Tokenized links** (capability tokens): Once tokenized links ship, the shared link must be the tokenized one. This item shares whatever link is passed to the component (the existing `url` prop), so it inherits that change automatically. Confirm this holds — the component must not cache the link at render time in a way that would prevent updates.

5. **Very long link**: No truncation. Share the full URL as-is.

6. **User-visible change**: Yes, on native platforms. Sharing a quote/invoice/contract becomes a two-tap action (tap share → tap destination) instead of copy-paste-switch-app.

7. **Web platform unchanged**: The behavior on web must remain identical to today — copy to clipboard, show toast confirmation.

## Risks

None. This is a pure enhancement to an existing user action (sharing a link). The fallback path (web) is unchanged, and the native path uses a standard platform capability with no persistence or money involved. The component boundary (quote/invoice/contract links only) is clear and already guarded.

## Derived criteria

What this item is asking for:
1. When a trade taps a quote/invoice/contract link button on a native platform (iOS/Android), the platform's native share sheet opens instead of copying to clipboard
2. The share sheet shows a title identifying what is being sent (e.g. "Quote for [Customer]") and the full link URL
3. The user can select WhatsApp, Messages, Mail, or any other destination from the share sheet
4. Dismissing the share sheet without sharing is a silent no-op — no toast, no error
5. A haptic tap fires when the share sheet is invoked
6. On web platforms, the existing copy-to-clipboard behavior is unchanged
7. Platform detection uses `Capacitor.isNativePlatform()`, the same check a haptics utility would use
8. All surfaces that currently offer a quote, invoice, or contract link get this behavior
9. Surfaces that copy other things (like referral codes) are unchanged
10. The component does not cache the link at render time — it uses whatever link is passed via props, so tokenized links will work automatically when they ship
