# Spec: Companies House validation — confirm what already exists

**Issue:** #618  
**Module:** data

## Problem

The Companies House integration exists but is incomplete. A contractor can search for their company by name and select it, but there is no validation of a manually-typed company number, no way to pull the full registered office address, and no cross-check against voice-captured business details. This means a contractor could enter an invalid company number, or the details they dictated during voice setup could silently diverge from what's actually registered at Companies House.

## Scope: what changes

1. **Add company number validation** — a new `getCompanyByNumber(companyNumber)` function that validates a manually-entered company number exists and returns the full company profile.

2. **Pull registered office address** — extend the Companies House client and schema to fetch and return the full registered office address (currently only `address_snippet` is captured from search results).

3. **Cross-check voice-captured details** — when a contractor completes voice setup and a company number is present, automatically validate it against Companies House and surface any mismatch between:
   - Registered company name vs voice-captured `company_name`
   - Registered office address vs voice-captured `business_profile.registered_address`

   Surface mismatches as a warning in the setup form with both values shown, allowing the contractor to choose which to keep.

## Explicitly out of scope

- Anything requiring a new API credential or paid service tier
- Auto-correcting the contractor's stated values (only surface the mismatch for manual resolution)
- Validating company number format client-side (the API call is the validation)
- Retroactively checking existing contractors' company numbers (this applies to new/updated setups only)
- Validating company status (active/dissolved) — pull what's there, don't reject based on status

## Files

- `src/lib/companies-house.ts` (modify) — add `getCompanyByNumber`, extend schema to include full registered office address
- `src/app/api/companies-house/validate/route.ts` (new) — new route for validating company number and cross-checking against stated details
- `src/app/setup/actions.ts` (modify) — call validation when completing voice setup if company number present
- `src/app/setup/setup-form.tsx` (modify) — show mismatch warnings when validation results are present

## Edge cases

**Invalid company number**
- A manually-entered number that doesn't exist → API returns 404, surface "Company number not found" error

**Voice-captured company name missing**
- Validation called but `company_name` was never captured → skip the check, nothing to validate against

**Partial voice capture**
- Only `company_name` captured, no `registered_address` → validate name only
- Only `registered_address` captured, no `company_name` → validate address only

**Exact match**
- Companies House registered name exactly matches voice-captured name (case-insensitive) → no warning, silent success

**Casing/whitespace differences**
- "ABC Limited" vs "ABC LIMITED" or "ABC  Limited" (extra space) → normalize and treat as match, no warning

**Substantive mismatch**
- "ABC Limited" (voice) vs "ABC Electrical Limited" (registered) → surface warning with both values

**API failure**
- Companies House API down or rate-limited → log error, allow setup to proceed without validation (don't block setup on external API availability)

**Multiple validation calls**
- Contractor triggers validation multiple times (e.g. changes company number) → each call is independent, last result wins

## Risks

**External API dependency** — validation depends on Companies House API availability. Mitigated by allowing setup to proceed if validation fails (logged warning, not blocking error).

**False positives on name matching** — strict string comparison could flag legitimate trading name vs registered name differences. Mitigated by normalizing whitespace/casing before comparison.

**PII in logs** — registered addresses are PII. Ensure validation errors log only the mismatch fact, not the full addresses.

## Derived criteria

A successful implementation means:

1. A contractor who manually types a company number can validate it exists at Companies House
2. The validation returns the full registered office address, not just a snippet
3. After voice setup, if a company number was captured, the system automatically checks the registered name and address against what the contractor dictated
4. Mismatches between registered and voice-captured details are surfaced in the setup form with both values shown
5. The contractor can proceed with setup even if validation fails (external API failure never blocks the form)
6. Name matching normalizes whitespace and casing to avoid false positives on trivial differences
7. Validation errors are logged without including PII (company number and mismatch fact only, not addresses)
