# Issue #334: FEE-3: Split FEE_BILLING_ENABLED — delete the retired mandate UI, make honest fee surfaces permanent

**Auditing `main` @ `ddaa068` (24 Aug 2026)**

## Problem

Two live payments settled through Stripe on 20 Aug 2026 with nothing in the app naming the fee or the free-job allowance. The ledger was correct — settlement wrote the fee columns — but all fee surfaces sat behind `FEE_BILLING_ENABLED`, which is absent from `.env.example` and defaulted to false. The gap was display, not money.

Commit `f7d889c` (merged as #296 follow-up on 20 Aug) already fixed the visibility gap: it deleted `FeeBillingSection` (the dead VRP mandate CTA), `fee-billing-flag.ts`, ungated the four honest surfaces (free-jobs chip, mark-as-paid fee line, fees statement, referral section), and removed the blocking logic from `fee-runway.ts`.

What remains is the retired ladder itself. `FeeRunwayBanner` and `lib/fee-runway.ts` were built for a model that gated quote-sending on a VRP mandate. PAY-5 removed that rail, so the gate is gone — but the informational banner still shows copy about the old "first 5 paid jobs" allowance, which no longer reflects the FEE-1 grants model (trial of 3, referral of 3 rising to 5 at 5 activated referrals).

The banner was useful when it described the model accurately. Now it describes a model that's changing, and the referral section still promises "5 more fee-free jobs" per referral unconditionally. Both need updating to reflect FEE-1, or deleting entirely.

The spec opts to delete: the free-jobs chip on the dashboard already shows the balance unconditionally, and the fees statement in Settings explains the model. A third place to state the allowance is redundant and a maintenance burden as the grant tiers evolve.

## Scope: what changes

1. **Delete** `src/components/ui/fee-runway-banner.tsx` — the component that renders the amber runway warning banner.
2. **Delete** `src/lib/fee-runway.ts` — the library that computes runway state and banner copy.
3. **Delete** `src/lib/fee-runway.test.ts` — the unit tests for the deleted library.
4. **Remove FeeRunwayBanner from dashboard** (`src/app/dashboard/page.tsx`):
   - Remove the `import` of `loadFeeRunway` from `@/lib/fee-runway`
   - Remove the `import` of `FeeRunwayBanner` from `@/components/ui/fee-runway-banner`
   - Remove the `loadFeeRunway` call (currently around line 202)
   - Remove the `feeRunway` variable
   - Remove the `<FeeRunwayBanner runway={feeRunway} />` JSX (currently around line 222)
5. **Update referral copy** (`src/app/settings/referral-section.tsx`):
   - Change "you get 5 more fee-free jobs" to reflect the FEE-1 model: "they get 3 free jobs, and you get 3 more (rising to 5 at 5 activated referrals)"
   - The copy must explain both the referee's reward (3) and the referrer's reward (3 rising to 5 at the champion tier of 5 activated referrals).

The free-jobs chip on the dashboard (lines 233-240 of `dashboard/page.tsx`) remains unchanged — it already shows the correct balance unconditionally: `{freeJobsRemaining} free job{s} left`.

## Edge cases

- **Contractor with 0 free jobs**: the free-jobs chip doesn't render (line 233 guards with `{freeJobsRemaining > 0 &&`), so they see no balance. The fees statement in Settings still explains the model. No banner means no redundant "your free jobs are used up" warning.
- **Contractor with 1–2 free jobs left**: previously saw the passive nudge banner. Now sees only the chip. The fees statement explains what happens after the allowance.
- **Contractor mid-onboarding**: no Stripe account yet. The deleted banner used to show anyway (it was informational, not gated). Now they see the chip if they have credits, and the fees statement.
- **Historical jobs**: fees statement continues to show all jobs with fee columns, unaffected by the banner deletion.
- **Orphaned imports**: removing the banner from dashboard leaves no other consumers of `fee-runway.ts`, so deleting the file is safe. The test file has no other callers either.
- **Referral section with no referral code**: currently shows "Your referral code will appear here once your business setup is complete." The updated copy applies only when the code exists and the reward description renders.

## Risks

None. No money, no migrations, no database changes. Pure deletion of UI and copy update. The surfaces that explain fees (chip, mark-as-paid line, fees statement) all remain and are already ungated.

The banner was informational only — no rung blocked any action (verified in `fee-runway.test.ts:37-52`). Deleting it removes a maintenance burden without removing any capability.
