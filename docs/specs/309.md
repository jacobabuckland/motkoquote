# Issue #309: Apply disclosure to the Business page sections

**Auditing `factory/309` @ `86772b3` (with #306 merged)**

## Problem

The Business page (setup form at `/setup`) renders six sections all expanded: Company, Rates, Team, Merchants & trade discounts, Legal & contract details, and Company Branding. On mobile, six full sections stacked means finding any one of them is a scroll exercise.

This is the second consumer of the disclosure component from #306, proving it generalises.

## Scope: what changes

Wrap each of the six named sections in the `Disclosure` component, all `defaultOpen={false}`:

1. **Company** (company name, number, trade)
2. **Rates** (day rate, overtime, callout, travel, markup)
3. **Team** (team member list)
4. **Merchants & trade discounts** (merchant checkbox list)
5. **Legal & contract details** (business profile fields)
6. **Company Branding** (logo, brand colour, footer terms)

Each section gets a stable `id` for localStorage persistence (e.g. `"setup-company"`, `"setup-rates"`), inheriting the full disclosure contract: ARIA, haptics, motion tokens, reduced-motion, independent toggling, and persisted state.

A contractor who opens Rates finds it open on their next visit. Each section toggles independently — no accordion collapse-others behaviour.

## Explicitly out of scope

- **VAT section** remains as-is (not wrapped). Same for **Rate cards** section. Neither was named in the spec, and wrapping them would be scope creep.
- Reordering, renaming, merging, or splitting sections. If the IA is wrong, that's a separate ticket.
- Any change to the `Disclosure` component itself. If this ticket needs the component changed, the primitive ticket's spec was wrong — halt and report rather than forking it.

## Files

- `src/app/setup/setup-form.tsx` — wrap the six section `<section>` blocks in `<Disclosure>`, import the component at the top

## Edge cases

- **All edge cases from #306 apply unchanged**: ARIA, motion tokens, haptics, persistence, reduced-motion, independent toggling, focus management.
- **Empty section** (no team members, no merchants selected): still renders its header, collapsed, with the empty state or add button inside. Hiding it makes the feature undiscoverable.
- **Unsaved changes survive collapse**: collapsing a section with form state (typed values, checked boxes) does not reset that state. The `Disclosure` component does not unmount children when collapsed.
- **Deep-link expansion** already works (inherited from #306) and does not persist. A hash pointing inside a collapsed section expands it without writing the preference.
- **localStorage unavailable** (private browsing, quota exceeded): sections use `defaultOpen={false}` and remain functional — the toggle works, nothing persists.

## Risks

None. No money, no migrations, no user data changes. Pure UI refactor using an already-shipped component.

## Derived criteria

A human wrote this spec and expects the Engineer to:

- Import `Disclosure` from `@/components/ui/disclosure` into `setup-form.tsx`
- Wrap each of the six named `<section>` blocks (Company, Rates, Team, Merchants, Legal, Branding) in `<Disclosure id="..." title="..." defaultOpen={false}>`
- Use stable, unique `id` values for each section (e.g. `"setup-company"`, `"setup-rates"`, `"setup-team"`, `"setup-merchants"`, `"setup-legal"`, `"setup-branding"`)
- Leave VAT and Rate cards sections unwrapped (not mentioned in spec)
- All six sections collapsed by default (`defaultOpen={false}`)
- No change to section content, order, or structure — only wrapping them in the disclosure component
- Inherit all #306 behaviour: ARIA, haptics, persistence, motion tokens, independent toggling
- A contractor who opens Rates finds it open on their next visit (localStorage persistence works per-section)
- Empty sections (no team, no merchants) still render their header collapsed with content inside
