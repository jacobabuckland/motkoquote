# 676: Address & postcode lookup at capture

**Auditing branch:** factory/676 @ cb9e571

## Problem

Address is the field where voice transcription fails most reliably and unrecoverably. A garbled postcode reaches a customer-facing document and the trade looks careless. Current implementation uses Google Places API, which is expensive per lookup and returns global results requiring filtering. Switch to getAddress.io — UK-specific, lower cost per lookup, structured UK address data out of the box, and coordinates included for future travel/routing work.

Jacob has added the getAddress.io API key to Vercel env vars. The name is
`NEXT_PUBLIC_ADDRESS_LOOKUP` (his decision, 9 Sep). The card said `ADDRESS_LOOKUP`, but
the lookup runs in the browser and Next.js inlines only `NEXT_PUBLIC_*` into the client
bundle, so an unprefixed name reads as `undefined` there and the field degrades silently
to plain text. The key is therefore public by construction — it ships in the bundle —
which was accepted knowingly over a server-side proxy.

## Scope

Replace the Google Places autocomplete with getAddress.io's autocomplete/find and get endpoints wherever an address is currently captured:

1. **Business address during onboarding** (`src/app/setup/setup-form.tsx`)
2. **Client and site addresses when creating contracts** (`src/app/dashboard/create-contract-form.tsx`)

The `AddressAutocomplete` component continues to:
- Show a single text input with dropdown suggestions
- Degrade gracefully to plain text when the API is unavailable or no key is present
- Accept free-typed text as valid (selection never required)
- Return the same `StructuredAddress` shape as before

The getAddress.io API provides:
- **Autocomplete/find**: Takes a partial postcode or address, returns suggestions
- **Get**: Takes an address ID, returns full structured address with line1, line2, line3, town, county, postcode, lat/lng

Implementation:
- Replace `src/lib/google-maps.ts` with `src/lib/getaddress.ts` containing the getAddress.io client — but do NOT delete it (see the note under `## Files`)
- Update `src/components/ui/address-autocomplete.tsx` to use the new client
- Retain the same `StructuredAddress` schema — getAddress.io's response maps cleanly to it

Voice intake addresses (stored as plain strings in `sow_json.site_address`) are unchanged — this affects only the manual capture forms.

## Out of scope

- Changing how addresses are stored (schema stays the same)
- Changing voice intake address capture (it's transcribed text, not a form field)
- Adding address lookup to any surfaces beyond the two existing ones
- Migrating existing Google Places address data

## Files

- `src/lib/getaddress.ts` (new) — getAddress.io API client
- `src/components/ui/address-autocomplete.tsx` (modify) — replace Google Places calls with getAddress.io
- `src/lib/google-maps.ts` (modify) — reduced to the two exports `tests/acceptance/106.test.ts`
  imports (`placeToStructuredAddress`, `PlaceResult`). NOT removed: #106 is frozen and imports
  this path, so deleting the file takes that suite down. The Maps API client, key and network
  call are gone; what remains is pure functions with no dependency on Google.

## Edge cases

**No API key**: Component degrades to plain text input, free-typed text flows through `onChange` as `{ formatted: <text> }`. No dropdown, no error shown.

**Failed API load or network error**: Same as no API key — stay a plain text field. Do not show an error message (the contractor can still type the address).

**No results found**: Close the dropdown if open, leave the typed text in the input. The contractor can either keep typing or submit the free text.

**Empty postcode query**: Do not fetch. Require at least 3 characters before triggering autocomplete (same as current implementation).

**Stale fetch resolving after input changed**: Drop the response if the current input value no longer matches the query that was sent.

**API rate limiting or 429 response**: Treat as a failed fetch — dropdown closes, plain text mode continues.

**Selection before detail fetch completes**: Show the suggestion's text immediately in the input, await the full address fetch in the background. If it fails, keep the formatted text already shown.

**Coordinates missing from response**: lat/lng are optional in `StructuredAddress` — omit them when not returned.

## Risks

None. This is a drop-in replacement for an existing autocomplete component, with the same graceful degradation and the same output schema. No database changes, no customer-visible copy changes, no money or auth surface touched.
