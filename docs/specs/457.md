# DATA-4: The job P&L returns null on every call — restore it without the VAT half

**Audited against:** `main` @ `e81b8fe` (30 Aug 2026)

## Problem

`getJobPnL` (`src/app/jobs/[id]/pnl-actions.ts`) returns `null` for every job because it selects two columns that do not exist. The first select names `jobs.quote_id`, which does not exist (the relationship runs the other way: `quotes.job_id` references `jobs(id)`), so PostgREST rejects the query, `jobError` is set, and the function returns `null` immediately. The second select would also fail — it names `invoices.vat_amount`, which does not exist either.

Both consumers get nothing: the P&L panel never renders on the job page, and the voice P&L query has no data. Confirmed on production 30 Aug 2026.

Decision taken 30 Aug 2026 (Jacob): drop the VAT half of the P&L for now. Invoice VAT is not stored, so `vatCollected` cannot be computed. Restoring it needs a source for invoice VAT — a separate decision and migration. `job_costs.vat_amount` does exist, so `vatOnCosts` alone is computable, but showing VAT on costs with no VAT collected beside it reads as a reclaimable amount, which is worse than showing nothing. The whole VAT section goes together.

## Scope: what changes

1. **Traverse the real relationship to reach invoices.** `jobs` has no `quote_id`. Select `id` alone to keep the ownership check, then reach invoices through `quotes!inner(job_id)`:

   ```ts
   .from("invoices")
   .select("amount, quotes!inner(job_id)")
   .eq("quotes.job_id", jobId)
   ```

   The established idiom is `src/app/jobs/money-position-actions.ts:246-254`. Either the inner-join shape or the separate quote lookup (`.eq("job_id", id).maybeSingle()` as the job page does) is acceptable.

2. **Remove VAT fields from the type and computation.** Drop `vat_amount` from the invoices select; remove `vatCollected`, `vatOnCosts` and `vatPosition` from `PnLData` (`costs-section.tsx:35-37` and `pnl-actions.ts:6-16`); stop computing them in `getJobPnL`.

3. **Delete the VAT block from the component, but keep the disclaimer.** Remove the entire `contractorVatRegistered &&` section from `job-pnl.tsx:86-110`. The disclaimer inside it — *"Estimate only, not tax advice. Check with your accountant."* — must survive and move to panel level (outside the deleted block), so it applies to gross profit and margin estimates regardless of VAT registration.

   This collides with a frozen test: `tests/acceptance/252.test.tsx:183-195` (LED-2) asserts the disclaimer exists, and it currently lives inside the block being deleted. Keeping the disclaimer at panel level satisfies #252 unchanged.

4. **Use the helpers that now exist.** `requireContractor` (`src/lib/require-contractor.ts`, from #438) replaces the hand-rolled contractor lookup (lines 34-40). `throwIfQueryFailed` (`src/lib/query-error.ts`) replaces `return null` when a query fails. Keep `return null` for the genuine "no quote yet" case — that is a real answer, and the panel handles it.

## Explicitly out of scope

- Restoring VAT figures. Needs a source for invoice VAT (a column or derivation from quote VAT settings). A money decision and a migration; its own item.
- `src/app/jobs/money-position-actions.ts`. The cross-job money position computes VAT by its own route and is untouched. This changes the per-job panel only.
- Editing `tests/acceptance/252.test.tsx`. Not to be edited. Its source-text assertion predates the rule against them; rewriting it is not this item's business.
- `job_costs.vat_amount` itself, and cost entry.
- `src/lib/recover-lost-fees.ts:165` — the remaining #409 drift, a money path.
- Pence/pounds conversions. Invoice amounts are pounds `numeric(10,2)`; cost amounts are integer pence. That asymmetry is real, already correct, and must survive.

## Edge cases

- **Job with no quote yet** → `null`, exactly as today. The panel's existing empty state is correct.
- **Quote with no invoices** → P&L computes with `invoicedNet: 0`, `hasInvoice: false`. Not the same as "no quote".
- **Query that fails** → throws, so `src/app/error.tsx` shows it. A failure must never look like an empty result.
- **Job belonging to another contractor** → returns nothing. The ownership check is load-bearing.
- **VAT-registered contractor** → sees P&L with no VAT section, same as everyone else, and still sees the disclaimer.

## Risks

None. This is a correctness fix for a function that currently returns nothing. The decision to drop VAT fields is recorded in `areas/motko.md` and was taken by a human. The pence/pounds asymmetry is real and must survive — invoice amounts come from the database in pounds and are converted; cost amounts are already in pence.
