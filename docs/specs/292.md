# Issue #292: Carry the scope of works onto the customer-facing quote

## Problem

The quote PDF currently renders header, parties, metadata (job type, reference, date), line items, totals, and footer - but no scope of work. QuotePdfPayload carries six fields (reference, createdAt, lineItems, jobType, contractor, customer) with no scope, timeline, inclusions/exclusions or assumptions field. The query in `renderQuotePdf` (render-quote.ts:78) never selects `sow_json`, so QuotePdf has no scope data to render.

In fixed-price mode, `applyPricingMode` collapses the quote to a single line whose description is derived from `deriveWorksDescription` (pricing-mode.ts:18-23), producing "Rewire works as described" where "as described" points at a scope the customer was never sent. The customer receives a number with no supporting detail: no rooms, no inclusions, no exclusions, no timeline, no assumptions. When a dispute arises, neither party has evidence of agreed scope.

The scope exists and is fully rendered by SowPdf (sow-pdf.tsx), but that document is deliberately contractor-only and authenticated. The customer-facing quote PDF discards all of it.

## Scope: what changes

1. **QuotePdfPayload extension**: Add optional `scope?: QuoteScope` field, where QuoteScope is a narrowed projection of SowState containing: overviewNarrative, rooms, additionalItems, existingConditions, accessIssues, inclusions, exclusions, materialsMentioned, materialsSupply, assumptions, timeline.

2. **buildQuoteScope function** (quote-payload.ts): Pure function that builds QuoteScope from SowState. Returns null when scope is too thin (all arrays empty, all narrative fields absent) - no heading rendered in that case. Calls `synthesizeTimeline(sow, crewSize)` with the crew size the pricing actually used (via crewSizeOverride parameter) to prevent understating the crew. Module remains isomorphic (no Supabase import).

3. **renderQuotePdf query** (render-quote.ts:78): Add `sow_json` to the select string alongside created_at, line_items_json, and the job relations.

4. **quoteRowToPdfPayload mapping** (render-quote.ts:38-68): Map the selected sow_json through buildQuoteScope and attach to payload.

5. **QuotePdf component** (quote-pdf.tsx): Render "Scope of work" section between MetaRow (line 168) and the table header (line 170) when payload.scope is non-null. Reuse SowPdf's section structure and sharedStyles.sectionTitle. Render:
   - Overview narrative (if present)
   - Rooms with work items
   - Additional items
   - Existing conditions
   - Access issues
   - Inclusions
   - Exclusions
   - Materials mentioned with supply split
   - Assumptions and unknowns
   - Timeline (add to metaItems when present)
   
   Empty sub-sections are omitted individually. Contractor-only fields (contractor_flags, assumption_note, next_question, unasked_required, wrap_incomplete) must not appear.

6. **deriveWorksDescription signature** (pricing-mode.ts:18): Gain second parameter `hasScopeSection: boolean`. With scope: "Rewire works — see Scope of work". Without: "Rewire works". Empty job type with scope: "Works — see Scope of work". Empty without: "Works".

7. **applyPricingMode** (pricing-mode.ts:73): Thread knowledge of whether `buildQuoteScope(sow)` returned non-null to deriveWorksDescription.

8. **Guest path**: 
   - Add `scope?: QuoteScope` to GuestQuote (guest/quote.ts:23-42)
   - Map completed SoW through buildQuoteScope in draftGuestQuote
   - Map to payload in guestQuoteToPdfPayload (guest/pdf.ts:9-16)

9. **Golden fixtures** (tests/helpers/quote-pdf-fixtures.ts): Add fifth fixture "with-scope" carrying populated sow_json. The four existing fixtures all have sow_json = null and must hash unchanged.

10. **Golden re-baseline** (tests/regression/quote-pdf-golden.test.ts): Regenerate golden hashes with `UPDATE_QUOTE_PDF_GOLDEN=1 npx vitest run tests/regression/quote-pdf-golden.test.ts` in a separate commit so the document change is reviewable on its own.

## Explicitly out of scope

- The SoW PDF (sow-pdf.tsx) and its route - unchanged, still contractor-only
- Contract PDF, contract templates, and {{scope_of_work}} placeholder
- Voice intake, sowStateSchema, mergeSowDelta, checklist questions, wrap logic - this reads sow_json, never writes it
- Pricing logic: no change to amounts, computeQuoteTotals, compileDraftToLineItems, or which lines applyPricingMode selects. Only the fixed works line's description string changes.
- Quote editor UI - no scope-editing surface
- The /q/[id] customer web page - PDF only
- Backfill: existing sent quotes are not re-rendered or re-sent
- Finding 7's SoW link ejection (separate ticket)

## Edge cases

- **Payload without scope**: A QuotePdfPayload with scope omitted or null produces a PDF byte-identical to current output for the same inputs.

- **Multi-line-item quotes**: One scope section, rendered once, above the table, regardless of line count. Line items keep their own description, includes_tasks and customer_note - no duplication.

- **Thin utterance**: buildQuoteScope returns null when rooms, additional_items, inclusions, exclusions, assumptions_and_unknowns and materials_mentioned are all empty AND overview_narrative, existing_conditions, access_issues are all absent. Section omitted entirely - no heading, no placeholder.

- **Partially thin scope**: Any single populated field renders the section; empty sub-sections within it are omitted individually (matching SowPdf's existing rule).

- **Timeline unresolvable**: synthesizeTimeline already falls back to "To be confirmed before work begins" (sow.ts:665). Render it - the SoW PDF already treats Timeline as the one cell that always resolves.

- **Fixed-price mode**: Scope section in full; single works line carries the price. The section is what "described" now refers to.

- **Itemised mode**: Identical scope section; table unchanged with full breakdown.

- **Legacy quotes with pricing = null**: applyPricingMode returns calculated breakdown unchanged; scope renders if sow_json exists.

- **Guest mode**: Scope renders from in-memory completed SoW; contractor stays null and identity block stays omitted.

- **Guest with no captured SoW**: No scope section, same as a stored quote with sow_json = null.

- **sow_json parse failure**: Treat as absent, render no scope section, logError. A malformed SoW must never block a quote PDF that would otherwise render.

- **Contractor-only content leak prevention**: assumptions_and_unknowns[].description is customer-facing (SoW PDF prints it under "Confirm with customer" intro) and renders. contractor_flags, assumption_note, next_question, unasked_required, wrap_incomplete are contractor-only and must not appear. Acceptance criterion 14 enforces this.

- **Long scope pushing table to page 2**: Acceptable. @react-pdf paginates and the fixed page-number footer already handles multi-page documents.

- **Empty job_type**: deriveWorksDescription handles it - "Works as described" becomes "Works — see Scope of work" (with scope) or "Works" (without).

## Risks

- **Golden re-baseline must be deliberate**: The four existing fixtures must hash unchanged, proving the no-scope path is untouched. The fifth fixture with scope changes the document, so its re-baseline commit must be reviewable on its own.

- **Contractor-only content leak**: Contractor flags, assumption notes, and wrap-incomplete markers are internal and must never reach the customer-facing PDF. The acceptance tests explicitly check for their absence.

- **Crew size understatement**: Timeline must use the crew size the pricing actually used (via crewSizeOverride), not labour_plan.people_count directly, to prevent the Fenland "1-person team" bug where the timeline understated the actual crew.

- **No "as described" dangling references**: Every fixed-price quote currently renders "works as described". After this change, that phrase must never appear - it's either "works — see Scope of work" or "works" with no promise.

- **Isomorphic guarantee**: quote-payload.ts must remain isomorphic (no Supabase, no Node-only APIs) so browser rendering (guest path) and server rendering (stored quotes) use identical logic.

## Derived criteria

This issue asks for:

1. A scope-of-work section on the customer-facing quote PDF, carrying the rooms, inclusions, exclusions, timeline, assumptions and other details captured during voice intake
2. Fixed-price quotes whose works line currently reads "Rewire works as described" to either reference the scope section ("— see Scope of work") or drop the dangling "as described" if no scope was captured
3. The same scope rendering for guest quotes (in-memory SoW, browser-rendered PDF)
4. No change to existing quotes that have no scope - they must render byte-identically
5. No leakage of contractor-only content (flags, assumption notes, wrap-incomplete markers) onto the customer-facing document
6. A golden test re-baseline covering both the unchanged no-scope path and the new with-scope rendering
