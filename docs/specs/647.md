# FACT-3: Make the three recurring acceptance-test traps unreachable

## Problem

Seven of ten factory blocks on 6 September were defects in frozen acceptance-test files, not in anyone's implementation. Every one fell into a class AGENTS.md already documents by name and by issue number, yet documentation alone has not prevented recurrence. Each recurrence costs either a full re-derivation or a hand repair only a human can make, because tests/acceptance/ is frozen after the PM commits. Three classes account for all seven, and each is mechanically preventable: (1) hand-rolled Supabase stubs that return a bare promise from select() and die on the first filter (#639, #640), (2) mock signatures inferred rather than declared so mock.calls[0][0] is an index into an empty tuple (#403, #438, eighteen errors in #640), and (3) the dotAll regex flag forcing a repo-wide compile-target bump when an exact ES2017 equivalent exists (#119, #631, #643).

## Scope: what changes

Two of the three become unreachable by giving the PM a helper instead of a blank page, exactly as tests/helpers/capacitor.ts already does for Capacitor plugins — AGENTS.md mandates that helper and forbids hand-rolled vi.mock() calls for the same reason.

1. **A shared Supabase stub** at tests/helpers/supabase.ts. Returns a PostgREST-shaped query builder where every filter returns the builder, the builder is awaitable, and the caller supplies the rows to return. Records what it was asked for — the selected columns and each filter — so a test can assert the query as well as the result. AGENTS.md mandates its use in the same terms as the Capacitor helper.

2. **A shared NextRequest factory** at tests/helpers/next-request.ts. new Request(...) passed to a route handler is TS2345 at every call site — seven of them in #640 alone. One typed helper removes the class.

3. **Widen the acceptance type gate by exactly two diagnostics**: TS2493 and TS2339 when the type is never. Both arise from indexing a tuple the test's own vi.fn(...) declared empty, so they satisfy the existing admission criterion verbatim: "diagnostics about something the TEST ITSELF declares, which no implementation can change."

4. **Ban the s regex flag in acceptance tests**. check-acceptance-static.sh gains a rule naming [\s\S] as the equivalent. The flag cannot compile at ES2017, so there is no correct test that uses it.

5. **AGENTS.md sections** documenting both helpers in the same terms as the Capacitor helper, and the dotAll flag ban.

## Explicitly out of scope

- check-acceptance-static.sh's existing source-text rule. That gate already works.
- Raising tsconfig.json's compile target, under any argument. It stays at ES2017.
- Rewriting the acceptance tests of items already in flight. #640's and #643's files stay as they are; retiring a frozen assertion needs the retirement procedure and a card that names it.
- Widening the type gate beyond TS2493 and TS2339 on never. The script's header explains at length why an allowlist and not a denylist, and why the previous two attempts failed.

## Edge cases

- **A filter chain ending in maybeSingle() or single()** must return the builder from each filter. The awaited result is the rows the caller supplied, not a builder.
- **Filters with no value** (e.g., .not("field", "is", null)) must be recorded the same way as filters with a value, so the test can assert the query was constructed correctly.
- **Empty result sets** are legitimate and common. The stub returns whatever rows the caller gave it, including an empty array.
- **Type-narrowing queries** like .single() expect exactly one row. The stub does not enforce this — it returns the rows the caller supplied and leaves the cardinality assertion to the test, exactly as the real client does when typechecking is disabled.

## Risks

- **False positives from the dotAll flag ban** would block correct tests. The rule is deliberate: /…/s cannot compile at ES2017, so every instance in an acceptance test is wrong. The escape hatch is to rewrite the regex with [\s\S], which matches identically.
- **Type gate over-reach** is the recurring failure mode of that script. The previous two allowlists were wrong by matching too much, and TS2339 on a module namespace or on a type the item is about to change is a correct failing-first diagnostic. The new rule matches only TS2493 and TS2339 where the accessed type is `never` — the tuple-indexing trap specifically, not the wider class.

## Derived criteria

I understood the task as:

1. Create a shared Supabase mock helper that produces a chainable, awaitable PostgREST-style query builder, preventing the bare-promise trap that killed #639 and #640.
2. Demonstrate that the helper survives an arbitrary filter chain (multiple filters + await, and again + maybeSingle()).
3. Show that the helper records selected columns and filters for assertion.
4. Create a shared NextRequest factory that returns a properly typed Request for route handler testing.
5. Extend check-acceptance-types.sh to report TS2493 (tuple index out of bounds) and TS2339 on `never` type, both from mock.calls[0][0] on a vi.fn() the test itself declared zero-argument.
6. Prove the type gate stays silent on other TS2339 diagnostics — the over-reach failure mode.
7. Extend check-acceptance-static.sh to reject the /s regex flag, naming [\s\S] as the ES2017-compatible equivalent. Two things this rule must get right, because the check's own acceptance test is the hardest input it will ever see:

   a. **An escaped slash inside a pattern is not a terminator.** `/dotAll|\/s flag/i` is ONE regex literal containing an escaped `\/`, not a dotAll flag, and a naive `/[^/]+/s` matches it. Detection must not fire on it. This is a false positive of the rule, not a defect in the test that trips it.

   b. **The rule must exempt its own acceptance test, and only for this rule.** A test that proves the checker rejects `/s` has to contain `/s` in its fixtures, and no refinement of the pattern can distinguish fixture text from real code — this is the standard linter-fixtures problem. The exemption is scoped to the dotAll rule alone: every other rule in the file, including the source-read rules, still applies to it. Do NOT add it to the whole-file ALLOWLIST, whose entries exist for a different reason (walking src/ by design) and which skips every rule.
8. Update AGENTS.md to mandate both helpers in the same terms as the Capacitor helper, and document the dotAll flag ban.
9. tsconfig.json still targets ES2017 after this item — no compile-target bump.
