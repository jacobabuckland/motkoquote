# Issue #451: PRICE-4 — Per-amount reconciliation gate, blocking on send

**Source:** [Notion roadmap item](https://app.notion.com/p/PRICE-4-Per-amount-reconciliation-gate-blocking-on-send-3ca1e4f908b481b0babfe962e3392fe8)  
**Module:** data

## Problem

Nothing checks that what the contractor stated matches what the customer is about to be sent, at a per-amount granularity. Decision D9 requires that every stated amount maps to exactly one line at that value, and every line maps to a stated source or is flagged. When this invariant fails, send is blocked and a review screen opens naming each mismatch with both figures.

This extends the existing `reconcileStatedPrice` guard in `src/lib/stated-price-guard.ts`, which currently compares `sow.pricing.fixed_amount` against the net total of non-provisional lines. That is the same invariant at a coarser grain: one stated total against one computed total. D9 is the per-amount superset, checking every individual stated price against the rendered line items.

## Scope: what changes

### Guard extension
`reconcileStatedPrice` in `src/lib/stated-price-guard.ts` gains per-amount reconciliation logic:
- Every amount in `sow.stated_prices` (PRICE-1) that is not superseded, excluded, or already-paid must map to exactly one rendered line item at that value
- Every rendered line item must either:
  - Map to a stated source (via its `provenance` field from PRICE-3), OR
  - Carry the unsourced provenance flag that PRICE-3 introduced
- Comparison uses `samePrice` from `src/lib/money-compare.ts` (integer pence, tolerates one penny of rounding)
- A failure returns a structured result naming each mismatch: the offending line description, the stated figure, the rendered figure

The existing fixed-amount total check continues to run. The per-amount check runs alongside it, not instead of it.

### Send blocking
`sendQuote` in `src/app/jobs/actions.ts` calls the extended guard before attempting delivery. A per-amount mismatch throws with a clear message naming the reconciliation failure, blocking the send exactly as the existing unpriced-line and zero-total guards do.

### Review screen
`src/app/jobs/[id]/quote-editor.tsx` gains a reconciliation-failure mode that:
- Lists each mismatch: line description, stated amount, rendered amount
- Lists each unsourced line (provenance absent or flagged)
- Offers a "Confirm as contractor-sourced" action that marks the flagged lines with `provenance: { source: "contractor" }` and clears the block
- Is dismissable — the contractor can return to editing instead of confirming

The review screen is shown when the send attempt returns a reconciliation-failure error. It does not open on mount or on every save — only when send is blocked by the gate.

### Instrumentation
`src/lib/analytics.ts` gains a `gate_failure` event recording:
- `gate`: `"price_reconciliation"`
- `job_id`: the job being sent
- `failure_kind`: one of `"amount_mismatch"`, `"unsourced_line"`, `"duplicate_amount"`
- `failure_count`: how many lines/amounts failed

Emitted each time the gate blocks a send, so the per-quote failure rate is measurable. This is measurement of our own accuracy, not a signal that must change an outcome, so an analytics sink is the correct destination.

## Explicitly out of scope: what does not change

- **EDITABLE_STATUSES rule.** A quote remains rewritable only while draft or sent. The gate does not relax this to let a review screen edit an accepted quote.
- **ZERO_TOTAL_CONFIRM_REQUIRED.** A deliberate £0 quote is still sendable after confirmation.
- **Language and double-charge rules.** PRICE-5 will add these, and the gate is where D8's double-charge rejection will attach — but they are not part of this item.
- **Provisional sums.** The existing guard deliberately compares against non-provisional lines, because a fixed price covers the defined works while provisional sums price separately. The per-amount check inherits this: a correctly-built fixed quote carrying a provisional sum must not fail the gate.
- **Migration.** No schema changes. This reads existing `stated_prices` and `provenance` fields introduced by PRICE-1 and PRICE-3.

## Edge cases

### Amounts deliberately removed in the editor
A stated amount that the contractor explicitly removed from the quote in the editor is not a mismatch. The gate reconciles against what was stated and not since overridden. An explicit removal (the line is gone, or the amount was manually changed) is an override.

### Stated amount appearing on two lines
Blocks. "Exactly one line" is the rule, and a duplicated amount is how a customer gets charged twice for one thing. The gate reports this as `failure_kind: "duplicate_amount"`.

### Rounding
Amounts are integer pence end to end (PRICE-1). The gate compares using `samePrice` from `src/lib/money-compare.ts`, which tolerates one penny of rounding and no more.

### Legacy quote with no stated_prices
The per-amount check has nothing to reconcile and does not fire. The existing fixed-amount check (comparing `sow.pricing.fixed_amount` against the net total) still runs. A quote drafted before the PRICE chain must remain sendable.

### Every line unsourced
Blocks, with the review screen listing all of them. The contractor confirms them as contractor-sourced to proceed.

### Contractor cannot satisfy the gate
There must be a path forward that is not "abandon the quote". Confirming the lines as contractor-sourced is that path. A gate with no exit is a gate that gets removed.

### Modified after drafting, before send
The gate reads the final rendered `line_items_json` from the quote at send time, not the intermediate `drafted_line_items_json`. A modification applied in the editor between drafting and send is caught.

### Provisional sums
A correctly-built fixed-price quote carrying a provisional sum does not fail the gate. The per-amount check, like the existing total check, ignores lines where `provisional: true`.

## Risks

- **This blocks sending a quote** — the product's core action. A false positive costs a contractor a job. Decision D11 pairs blocking with instrumentation: ship blocking, log the gate-failure rate from day one, and if it exceeds roughly one in five real quotes, the extraction is the problem and gets fixed — the gate does not get downgraded.
- **Money, customer-facing.** The gate decides whether a document stating what a customer will be charged may be sent. The review-screen copy and the gate's error messages warrant a human look before merge.

## Derived criteria

A human reviewing this spec understood the following:

1. **Per-amount reconciliation extends the existing guard.** The fixed-amount total check keeps running. The per-amount check runs alongside it, in the same function, not as a second parallel guard.

2. **Every stated amount maps to exactly one line.** A stated £520 must appear on exactly one line at £520 (or £519-£521, given rounding tolerance). A stated amount on zero lines or two lines blocks.

3. **Every line maps to a stated source or is flagged.** A line with no `provenance` field, or with `provenance.source` absent, is treated as unsourced and blocks unless the contractor confirms it.

4. **The gate runs on final rendered line items.** It reads `line_items_json` from the quote at send time, not `drafted_line_items_json`. A post-drafting edit is caught.

5. **Blocking is immediate and instrumented.** Send throws on failure. The failure is logged to `events` with enough detail to compute a per-quote failure rate. D11 commits to watching that rate and fixing extraction if it exceeds roughly 20%.

6. **Confirming as contractor-sourced clears the block.** The review screen marks flagged lines with `provenance: { source: "contractor" }` and allows the send to proceed.

7. **Provisional sums are ignored.** A fixed-price quote carrying a provisional sum does not fail the gate. The check sums non-provisional lines only.

8. **Legacy quotes remain sendable.** A quote with no `stated_prices` record does not trigger the per-amount check. The existing fixed-amount mismatch check still runs.

9. **Rounding is tolerated.** `samePrice` compares integer pence and allows one penny of difference. £520.00 stated matches £519.99 or £520.01 rendered.

10. **A duplicated amount blocks.** If the same stated amount appears on two rendered lines, the gate blocks and reports `failure_kind: "duplicate_amount"`.
