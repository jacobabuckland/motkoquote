# OBS-3: A run viewer that shows where a value died

## Problem

Every stage of the voice-to-quote pipeline persists its output to six JSON columns across two tables (`jobs.conversation_json`, `jobs.sow_json`, `jobs.transcript`, `jobs.extracted_json`, `quotes.drafted_line_items_json`, `quotes.contractor_flags_json`), but none of it is ever read back for human inspection. When a stated price does not reach the quote, or when a work item mentioned in conversation does not appear in the final line items, the only way to find out where it was lost is a database query against those six JSON columns. Line-item provenance is the sharpest example: it is written, it is validated, and it blocks a quote from being sent when a line has no source — but it is rendered on no screen and no document, so no human can see which line came from the conversation and which the contractor typed.

## Scope: what changes

Create an internal run viewer at `/jobs/[id]/run` that displays the complete voice-to-quote pipeline execution for a single job. The viewer shows six panes in pipeline order, each displaying the persisted output of one stage:

1. **Conversation turns** — speaker-labelled transcript from `jobs.conversation_json` (`TranscriptTurn[]`), showing who said what and when
2. **Flat transcript** — the plain text from `jobs.transcript`, exactly as stored
3. **SoW state** — the full `jobs.sow_json` (`SowState`), including rooms with work items, stated prices with their qualifiers and transcript spans, materials mentioned, timeline, agreed costs, and all other captured scope
4. **Extraction** — `jobs.extracted_json` (`JobExtraction`), the structured form handed to the drafting model
5. **Drafted line items** — `quotes.drafted_line_items_json`, the calculated breakdown before pricing-mode collapse or user edits
6. **Final line items** — `quotes.line_items_json`, the active quote, plus `quotes.contractor_flags_json`

Plus a draft-versus-final comparison pane that:
- Shows which lines were added, removed, or edited between draft and final
- Labels a pricing-mode collapse as a collapse, not as deletions (in fixed mode, the active quote is deliberately a single works line while the stored breakdown keeps every line)

Plus provenance display:
- Each line item displays whether its price came from the conversation (`source: "transcript"`) or from the contractor (`source: "contractor"`)
- For conversation-sourced lines, displays the `transcript_span` it was matched against

Access control:
- Contractor-scoped: a contractor can only view runs for their own jobs
- The page checks `job.contractor_id` against the authenticated user and returns 403 otherwise
- An admin flag (contractor-level `is_admin` boolean, or environment-based for now) gates access to the route entirely

Edge cases and empty states:
- A job with no voice run (no `conversation_json`, no `transcript`): render "No voice run for this job" instead of six empty panes
- A job abandoned mid-call: panes 1-3 may be populated, 4-6 absent. Render the stages that exist, with a note for the missing ones ("Pipeline did not reach this stage")
- A manual quote: render "This quote was created manually" and do not show pipeline stages
- Legacy conversation turns in the older `{role, text}` shape: render them as-is, do not fail on missing `at` timestamp
- A very long transcript: the panes use scrollable containers so a long transcript does not push later panes off screen

The viewer performs no writes. It is read-only.

## Explicitly out of scope

- Audio playback (there is no audio being captured — see PFIX-6)
- Changing what any stage persists
- Any editing affordance (this surface is read-only)
- Comparing runs across multiple jobs
- Exporting or downloading the run data

## Files

- `src/app/jobs/[id]/run/page.tsx` (new) — the run viewer page component
- `src/app/jobs/[id]/run/loading.tsx` (new) — loading state for the run viewer
- `src/lib/auth.ts` or similar (modify, if contractor ID check requires a helper) — may need to add a `requireContractorOwnsJob` helper or similar
- `supabase/migrations/000000000000XX_add_is_admin_to_contractors.sql` (new, optional) — if admin flag does not exist and needs to be added as a database column

## Edge cases

- **Job with no voice run:** Display "No voice run for this job. This quote was created manually." No panes.
- **Job abandoned mid-call:** Render panes 1-3 (conversation, transcript, SoW) if present. For missing stages 4-6, display "Pipeline did not reach this stage."
- **Manual quote (no conversation_json):** Same as "no voice run" — display the empty state.
- **Legacy conversation turns (missing `at` timestamp):** Render without the timestamp, do not fail validation.
- **Very long transcript:** Each pane uses a scrollable container (`max-h-96 overflow-y-auto` or similar) so the page remains usable.
- **Stated price with no item attachment:** Display the amount and qualifiers, with "(no item)" for `item: null`.
- **Fixed-mode pricing collapse:** The draft-vs-final comparison must label the collapse as "Collapsed to single works line (fixed pricing mode)" rather than showing each non-works line as "removed".
- **Contractor viewing another contractor's job:** 403 Forbidden. The page checks `job.contractor_id` against the authenticated user's contractor ID.
- **Unauthenticated access:** Redirect to sign-in (handled by existing auth middleware).

## Risks

- **PII exposure:** The viewer displays full conversation transcripts, which include customer names, addresses, and phone numbers captured during intake. Access must be contractor-scoped (can only see own jobs) and the admin flag must be enforced.
- **Performance:** Jobs with very long transcripts (500+ turns) may render slowly. Each pane should be independently scrollable to avoid layout thrashing.
- **Schema evolution:** The viewer reads six JSON columns that have evolved over time. Legacy jobs may have partial or missing data. The viewer must handle missing fields gracefully (display "N/A" or omit the section, do not crash).

## Derived criteria

1. Given a job where a stated price did not reach the quote, the stage at which it was lost is identifiable in under 30 seconds without writing a database query. (The SoW pane shows the stated price, the extraction pane shows whether it was passed to the drafter, the drafted line items pane shows whether the drafter created a line for it.)
2. A fixed-mode quote shows its single active line and its full stored breakdown side by side, with the collapse labeled as "Collapsed to single works line (fixed pricing mode)" rather than showing deletions.
3. Each line item in the final pane displays its provenance source (`transcript` or `contractor`), and for transcript-sourced lines, the span it was matched against.
4. A job with no voice run renders as "No voice run for this job. This quote was created manually." — not an error, not six empty panes.
5. A contractor can only view runs for jobs where `job.contractor_id` matches their authenticated contractor ID. Attempting to view another contractor's run returns 403.
6. The viewer performs no writes and has no mutation affordances (no buttons, no forms, no edits).
7. Legacy conversation turns in the older `{role, text}` shape render without failure, displaying the text with a fallback speaker label if needed.
8. A very long transcript does not push later panes off screen — each pane is independently scrollable.
9. The route is accessible at `/jobs/[id]/run` and loads within the existing job layout (if any) or as a standalone page.
10. An admin flag gates access to the viewer. Non-admin contractors cannot reach the route (either the link is hidden, or the page returns 403).
