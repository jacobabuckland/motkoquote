# Voice repair: talk to Motko about an existing quote

## Problem

When a quote comes back with gaps, the app tells the trade to tap through and type. Voice is how this app captures everything else; it should be how it repairs too. Jacob's words (12 Sep): "give them an option to go back to voice — Motko can then pick up the things we're missing, ask them, and take any changes."

Currently:
- `createRealtimeSession` unconditionally INSERTs a new job row (no way to bind to an existing job)
- `buildJobIntakeInstructions` builds a cold-start intake (no way to provide already-captured slots)
- `redraftJob` rewrites line items wholesale (first path that could overwrite hand-edited quote)

The machinery exists but the path doesn't: `saveSowDelta` writes to a named job, `LineItem.edited` exists for exactly this merge problem.

## Scope

Add a voice-repair path that binds to an existing job and repairs gaps without destroying hand-edits:

1. **createRealtimeSession accepts an optional jobId** — when provided, it binds the session to that job instead of creating a new one. The job's existing `sow_json` seeds the conversation, so Motko knows what has already been captured.

2. **buildJobIntakeInstructions accepts existing SowState** — generates repair instructions that list the gaps (incomplete slots from `unasked_required`) and ask the contractor to fill them, rather than starting cold.

3. **completeSowConversation merges deltas rather than replacing** — when bound to an existing job with a quote, it applies the deltas to `sow_json` and re-prices only the affected lines, leaving `edited: true` lines untouched.

Start with the **incomplete-capture** scenario (the card is explicit): Motko has a precise list of missing slots from `wrap_incomplete` / `unasked_required` and asks the contractor to fill them. The open-ended "anything look wrong?" entry is the same mechanism with more risk; ship the targeted repair first.

## Explicitly out of scope

- Redrafting (wholesale line-item replacement) on a repair — we apply deltas and re-price only what changed
- Open-ended "review your quote" — start with targeted gap-filling from `unasked_required`
- Guest repair path — voice repair is for authenticated trades with an existing job
- Changing the status of the job/quote during repair — status transitions happen on send, not mid-repair

## Files

- `src/app/jobs/actions.ts` (modify) — add optional `jobId` parameter to `createRealtimeSession`, adjust its INSERT to UPDATE when job exists, pass existing `sow_json` to prompt builder
- `src/lib/voice/job-intake-prompt.ts` (modify) — add `existingSow?: SowState` parameter to `buildJobIntakeInstructions`, generate repair-mode instructions that list gaps and ask to fill them
- `src/app/jobs/actions.ts` (modify) — adjust `completeSowConversation` to merge deltas when a quote already exists rather than wholesale replace
- `tests/acceptance/726.test.ts` (new) — acceptance tests

## Edge cases

**Job not found**: `createRealtimeSession({ jobId })` refuses when the job doesn't exist or doesn't belong to the contractor

**Job already has quote**: repair applies deltas to `sow_json`, re-prices only changed lines, preserves `edited: true` lines

**No gaps to repair**: when `unasked_required` is empty, the repair prompt is a no-op (Motko has nothing specific to ask)

**Contractor changes scope during repair**: deltas are applied to `sow_json` as they are in initial intake — `mergeSowToolDelta` is deterministic

**Quote not editable**: repair refuses when quote status is not in `EDITABLE_STATUSES` (after acceptance/decline, figures are agreed evidence)

## Behaviour on edge cases

- Missing jobId is not an error — the function keeps working as it does today (INSERT new job)
- Job not found with jobId provided → throw "Job not found"  
- Job belongs to different contractor → throw "Job not found" (RLS scopes the read)
- Repair on non-draft quote → check `isEditableQuoteStatus`, refuse with `QUOTE_NOT_EDITABLE` same as `updateQuoteLineItems`
- Empty `unasked_required` → repair prompt is valid but has nothing specific to ask (Motko can still capture changes the contractor volunteers)

## Risks

**Merge conflict between hand-edit and voice delta**: the design says deltas win (voice is the repair), but `edited: true` lines are preserved — this is load-bearing, test it

**Re-pricing after delta**: only lines whose inputs changed (crew, duration, materials) are re-priced; lines the contractor hand-edited stay as-is

**Status transitions**: repair must not flip the quote to "sent" or mark the job complete — those are separate actions

## Derived criteria

What I understood the spec to be asking for:

1. A trade can start a voice session bound to an existing job (not just create a new one)
2. When bound to an existing job, Motko is briefed on what's already captured and asks to fill the gaps
3. The incomplete-capture scenario (from `unasked_required`) is the first target — Motko has a precise list
4. Deltas from the repair are merged into `sow_json`, not wholesale replaced
5. Lines marked `edited: true` survive the repair (contractor's hand-work is preserved)
6. Re-pricing only touches lines whose inputs changed, not the whole quote
7. Repair is refused when the quote is no longer editable (same guard as `updateQuoteLineItems`)
