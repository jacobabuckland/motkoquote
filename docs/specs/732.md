# JOBUI-1: The quote editor must not appear on a quote that can't be edited

**Source:** [Notion roadmap item](https://app.notion.com/p/JOBUI-1-The-quote-editor-must-not-appear-on-a-quote-that-can-t-be-edited-3da1e4f908b4819e97e9daf36dc4a65f)

**Module:** app

**Audited against:** main @ fe5b41a

## Problem

The quote editor mounts on every quote regardless of status. But `EDITABLE_STATUSES = ["draft", "sent"]`, and all three write paths in `src/app/jobs/actions.ts` filter `.in("status", [...EDITABLE_STATUSES])`. So on an accepted or declined quote, the server refuses every write with `QUOTE_NOT_EDITABLE` — "This quote can no longer be edited — the customer has already responded."

The trade is therefore shown, on a quote the customer has already accepted:
- a Fixed price field and Update price button
- + Add line item and Save changes buttons
- the BEFORE YOU SEND flag stack
- the full SEND TO CUSTOMER form — name, email, mobile, site address, and send channels

Every one of those is a dead end. The trade can fill in the whole send form and the server will refuse it.

## Scope: what changes

Gate the editor mount on `isEditableQuoteStatus(quote.status)`. When the quote is NOT editable (accepted or declined), show a read-only summary instead:
- The quoted job and customer (already in the header)
- The line items as readable rows (description, qty × rate, line total)
- The subtotal, VAT (if applicable), and total
- The existing "Download quote" link

The guard is exported from `src/lib/quote-send-guards.ts` and already used by the three write paths, so there is nothing new to decide — the screen simply stops offering what the server already refuses.

## Explicitly out of scope

- The save bar and SoW drift — that is a separate item (JOBUI-2) which governs the editor in its editable states. This card does not touch them.
- Allowing an accepted quote to be edited at all — that is also a separate item. Do not widen `EDITABLE_STATUSES` here.

## Files

The complete list of files expected to change:

- `src/app/jobs/[id]/page.tsx` (modify) — gate the `<QuoteEditor>` mount on `isEditableQuoteStatus(quote.status)`, render a read-only summary otherwise
- `src/lib/quote-send-guards.ts` (no change, but import the guard from here)

## Edge cases

- A quote with no line items: the read-only summary shows an empty list and a £0 total. This is the correct rendering of the stored state, not an error.
- A quote that has never been sent (status = "draft"): editor appears, unchanged behaviour.
- A quote that was sent and later declined: read-only summary, same as accepted.
- VAT-registered contractors: the summary shows subtotal, VAT and total, matching the editor's breakdown.

## Failure modes

None specific to this change. The guard is boolean and the mount is conditional — there is no partial state.

## Risks

None. The guard already exists and is already enforced server-side. This change brings the UI into alignment with what the server permits, reducing the number of dead-end interactions.

## Derived criteria

Based on the human's specification, this item asks for:

1. The quote editor (its inputs, buttons, send form) appears when a quote's status is "draft" or "sent".
2. The same editor does NOT appear when status is "accepted" or "declined".
3. A read-only view of the quote (line items, totals) IS visible in all four states.
4. The "Download quote" link remains available in all states.
5. The guard used is `isEditableQuoteStatus` from `src/lib/quote-send-guards.ts`, which returns true only for draft and sent.
6. The page still renders successfully for quotes in any status — no guard causes a crash or a blank page.

The criterion that matters: a test covering only draft would pass against the defect. Coverage must include all four lifecycle states.
