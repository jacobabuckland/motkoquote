# Issue #519: HARN-1 — A fixture corpus for the quote pipeline

## Problem

The price-fidelity chain (PRICE-1 through PRICE-5) shipped between 28 and 31 August. Production has since produced only four drafted line items from voice intake. The repository contains zero complete production transcripts, and the single existing fixture (fenland-bathroom) is a prose summary of spoken facts plus hand-built line items — it starts after the model has run, so it exercises pricing but nothing before it. There is also no function that turns a transcript into SoW state offline, as the SoW is assembled turn-by-turn during the live call. A fixture that is only a transcript therefore drives nothing, and a corpus with no transcripts cannot verify that the stated-price extraction or the drafting chain actually work against realistic spoken input.

## Scope: what changes

Commit a fixture corpus under `fixtures/pipeline/` containing at least three substantial scenarios sourced from production transcripts, with each scenario providing:
1. The verbatim transcript string (redacted of all customer PII)
2. A hand-authored SoW state matching what the realtime model would have produced
3. The expected stated-prices extraction (from `extractStatedPrices`)
4. The expected line items (from `compileDraftToLineItems`)

Redact all customer PII (name, address, phone number, email address) from the existing `fixtures/fenland-bathroom.md` file.

Each scenario file exports:
- `transcript: string` — the verbatim transcript
- `sowState: SowState` — the hand-authored SoW
- `expectedStatedPrices: StatedPrice[]` — what extraction should produce
- `expectedLineItems: LineItem[]` — what the compiler should produce

The corpus must cover:
- At least one scenario with a price stated and then corrected later in the same call (supersession)
- At least one fixed-price quote scenario (single works line, breakdown stored but not rendered)
- At least one customer-supplied material scenario (prices at £0, shown for scope only)

## Explicitly out of scope

- Building the harness that runs these fixtures (that is HARN-2)
- Recording model responses or live-call outputs
- Changing extraction, drafting, or pricing behaviour — if a fixture reveals a defect, record it as a finding; do not fix it here
- Transcribing the twenty-one voice recordings from production storage (raised separately as PFIX-8)

## Files

- `fixtures/pipeline/scenario-1.ts` (new) — first substantial scenario with all four parts
- `fixtures/pipeline/scenario-2.ts` (new) — second substantial scenario with all four parts

- `fixtures/pipeline/index.ts` (new) — barrel export for convenient imports

## Edge cases

- A production transcript with no terminal punctuation: keep it exactly as captured. Unpunctuated speech is the realistic case and normalising it would hide a real failure mode.
- A transcript whose expected output is genuinely ambiguous: leave it out rather than committing a guess. A wrong expectation is worse than a missing scenario.
- An expected extraction or line item that contradicts current behaviour: record the defect as a comment in the fixture file; do not adjust the expected value to match the wrong output.

## Risks

This item touches no money logic, no migrations, and no customer-facing surfaces. The fixtures are test data only and do not execute during normal operation.

The one risk is committing unredacted PII: production transcripts contain customer names, addresses, phone numbers and site details verbatim as spoken. Every fixture must be reviewed for PII before commit, and the acceptance tests verify that common patterns (phone numbers, postcodes) do not appear in any fixture file.

## Derived criteria

A checklist of what must be true when this item ships:

1. ✅ Three or more fixture scenarios exist under `fixtures/pipeline/`, each exported from its own `.ts` file
2. ✅ Each scenario exports all four required parts: `transcript`, `sowState`, `expectedStatedPrices`, `expectedLineItems`
3. ✅ Loading any fixture and passing its transcript through `extractStatedPrices` produces the committed `expectedStatedPrices` exactly
4. ✅ At least one fixture covers a superseded stated price (a price corrected mid-call)
5. ✅ At least one fixture covers a fixed-price quote (pricing.mode === "fixed", pricing.fixed_amount set)
6. ✅ At least one fixture covers a customer-supplied material (supplied_by === "customer", unit_price === 0)
7. ✅ No fixture file contains an unredacted phone number pattern (UK format: 07... or 01...)
8. ✅ No fixture file contains an unredacted UK postcode pattern
9. ✅ The existing `fixtures/fenland-bathroom.md` has been redacted: no occurrence of "Margaret Doyle", "17 Chapel Loke", "Wymondham", "NR18 0QT", or "07700 900112"
10. ✅ A barrel export at `fixtures/pipeline/index.ts` re-exports all scenarios for convenient importing
