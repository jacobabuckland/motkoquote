# KNOW-1: The knowledge layer suggests; it never applies

## Problem

`src/lib/quote-learning.ts` diffs every AI-drafted quote against what the contractor actually sent, stores the deltas in `quote_line_edits`, and `summarizeTendencies` turns them into prose that is fed straight into the drafting prompt as `contractor_tendencies`. The whole contractor object is serialised into the model request (`src/lib/claude.ts:209` — `JSON.stringify({ job: extraction, contractor })`), and the system prompt at `src/lib/claude.ts:182` tells the model:

> "they are learned corrections from this contractor's own past edits — **apply them proactively** (e.g. include or omit a line item they consistently add or strip)."

So an inferred pattern changes a customer-facing document with nobody's consent:

1. **A price nudge reaches a customer document.** On an established account a material with no confirmed price compiles to `unit_price: round2(estimate * markup)` (`compile-draft.ts:786`) — the model's own number. A tendency saying "prices materials ~20% higher" steers it, and the line lands marked only "Estimated material cost". Nothing says a tendency moved it.
2. **An added line is work nobody discussed.** "Consider including it upfront" drafts a line present in neither the transcript nor the SoW.
3. **Two past quotes is the whole threshold.** `MIN_SAMPLE_SIZE = 2`.

## Scope: what changes

1. **`contractor_tendencies` leaves the drafting prompt.** `ContractorContext` drops the field, `draftQuoteLineItems` must not forward it to the model even if a caller still supplies one, and the "apply them proactively" sentence goes. The model drafts from the job alone.
2. **`summarizeTendencies` returns structure, not prose.** A UI cannot offer "accept" against a sentence. It returns `Tendency[]`:

   ```ts
   export type Tendency = {
     kind: "price" | "add" | "remove";
     // The category for a price tendency; the line's description for add/remove.
     subject: string;
     sampleSize: number;
     // Signed, in percent (+20 means priced 20% above the estimate).
     // Null for add and remove, which have no percentage.
     percentChange: number | null;
   };
   ```

   A **flat** record rather than a discriminated union, deliberately: a union forces every reader to narrow before touching `percentChange`, and `tsc` reports the un-narrowed access as `TS18046: … is of type 'unknown'` in exactly the acceptance test that must stay frozen. The prose sentence becomes presentation, built where it is rendered.
3. **Tendencies surface in the quote editor**, modelled on the existing contractor-flags panel (`quote-editor.tsx:480-489`): editor-only, never on the customer document, dismissible. Unlike a flag, each carries an **Accept** control. Accepting a `price` tendency applies it to the lines in that category; accepting an `add` tendency inserts the line **unpriced**.
4. **`MIN_SAMPLE_SIZE` goes from 2 to 3.** Two quotes is a coincidence, not a pattern. (Not Jacob's call — reversible, and it only makes suggestions rarer, so it cannot overcharge anyone. Say so in the commit.)

`getContractorTendencies` returns `Tendency[]` to match, and its callers in `src/app/jobs/actions.ts` pass the result to the editor rather than into the draft input.

## Explicitly out of scope: what does not change

- `diffLineItems` and the `quote_line_edits` table. Both correct; keep recording exactly as now.
- `known_material_prices` — a contractor-confirmed price, not an inferred tendency, and right as it stands.
- The guest funnel (`src/lib/guest/quote.ts:123`), which passes no tendencies and is unaffected.
- Persisting a dismissal across sessions. Flags do not either.
- `MIN_PRICE_DELTA_PCT` and `MAX_TENDENCIES`, which keep their current values.

## Files

- `src/lib/quote-learning.ts` (modify) — export `Tendency`; `summarizeTendencies` and `getContractorTendencies` return `Tendency[]`; `MIN_SAMPLE_SIZE` 2 → 3
- `src/lib/claude.ts` (modify) — drop `contractor_tendencies` from `ContractorContext`, from the serialised request, and from the system prompt
- `src/app/jobs/actions.ts` (modify) — stop feeding tendencies into the draft input; hand them to the editor
- `src/app/jobs/[id]/quote/page.tsx` (modify) — fetch tendencies for the editor
- `src/app/jobs/[id]/quote-editor.tsx` (modify) — the suggestions panel and its accept actions
- `areas/motko.md` (modify) — records the 16 Sep decision
- `tests/acceptance/788.test.tsx` (new) — acceptance tests

## Edge cases, including failure modes and empty states

- **No tendencies** (a new account, or nothing past the threshold): no panel, no empty state. The editor looks exactly as it does today.
- **A tendency naming a line the draft already contains:** not shown. There is nothing to add.
- **A price tendency whose category has no lines on this quote:** not shown.
- **Accepting an add on a quote that is already unpriced-blocked:** the new line is one more unpriced line. It does not unblock or newly block anything — the existing flag logic decides that from the lines.
- **Dismiss then reload:** the suggestion returns, as a flag does.
- **A caller that still supplies `contractor_tendencies`:** the drafter must not forward it. Dropping the field from the type is not enough on its own, because the contractor object is serialised wholesale.

## Risks: anything touching money, migrations, or user data

**Money surface.** This only ever *reduces* what reaches a customer without a human tap. Today a tendency can move a material price and add a chargeable line with nobody's consent; after this, neither happens unless the contractor accepts. No rate, no markup and no fee changes, and no existing quote is recomputed. No migration: `quote_line_edits` is unchanged.

Recorded decision, 16 Sep (Jacob): **suggest, never apply.** Nothing a tendency proposes reaches a customer document unless the contractor puts it there. The implementing commit records this in `areas/motko.md` so a later QA run does not re-raise it.

---

## Derived criteria

1. Drafting a quote for a contractor with recorded tendencies sends the model the same thing as drafting for one with none: no tendency prose reaches the request, and the system prompt no longer instructs the model to apply tendencies proactively. It holds even when a caller still supplies the old field, because the contractor object is serialised wholesale.

2. `summarizeTendencies` returns records carrying `kind`, `subject`, `sampleSize` and `percentChange` — not prose strings — so a UI can offer an accept against one.

3. A price tendency seen across three past quotes is reported with its category, its count, and a **signed** percentage whose sign says which way the contractor moved the price.

4. A line added on three past quotes produces an `add` tendency naming that line and the count.

5. A pattern seen on only two past quotes produces no tendency at all.

6. A contractor with recorded tendencies sees them in the quote editor, naming the line or category and the number of past quotes.

7. Each suggestion carries its own accept control, so a tendency can be applied deliberately rather than silently.

8. Until the contractor accepts, every line keeps the price it was compiled with — opening the editor changes no figure.

9. A contractor with no recorded tendencies sees no suggestions panel at all, and the editor looks exactly as it does today.

10. The suggestions surface is editor-only: its text appears on no customer-facing quote surface.
