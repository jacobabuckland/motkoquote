# Issue #132: Make pipeline rows fully tappable with press feedback

**Source:** [Notion roadmap item](https://app.notion.com/p/Make-pipeline-rows-fully-tappable-with-press-feedback-3b81e4f908b481078553dc9df088b980)

**Requires database migration:** No

---

## Problem

The dashboard list is the primary navigation surface, yet only the customer name (~140px) is tappable within a row that spans the full viewport width (~375px on mobile). A tap landing anywhere else in the 64px-tall row produces no navigation and no feedback. On a phone held one-handed in a van, this is the most-repeated interaction in the product, and two-thirds of the surface area does nothing.

## Scope: what changes

1. **Full-row tappable overlay**: Add an absolutely positioned link element covering the entire row bounds, positioned below existing interactive controls (z-index layering) so nested action buttons remain independently clickable.

2. **Active state with visual feedback**: Apply a visible background color change and `scale(0.99)` transform while the row is pressed. The background change applies unconditionally; the scale respects `prefers-reduced-motion` via Tailwind's `motion-safe:` variant.

3. **Tap haptic on native platforms**: Import and call `Haptics.impact({ style: "light" })` from `@capacitor/haptics` on touch/press, guarded by `Capacitor.isNativePlatform()`.

4. **Accessibility preserved**: The overlay is keyboard-focusable, announces the job name to screen readers exactly as the current implementation does, and does not interfere with existing controls' tab order or announcements.

## Explicitly out of scope

- Do **not** change row height, padding, layout, typography, or which fields are displayed (customer name, descriptor, amount, status chip, date label).
- Do **not** add swipe gestures, context menus, or long-press distinct behaviour.
- Do **not** change the persistent right-edge action slot's appearance, position, or behaviour.
- Do **not** modify the dashboard's grouping, ordering, filtering, or data fetching.
- Do **not** apply this pattern to other list components in this item — only `PipelineRow`.
- Do **not** change how the existing customer name link is styled when hovered (underline on hover remains).

## Files

Expected touches:

- `src/components/ui/pipeline-row.tsx` — add overlay link, active state classes, haptic call
- `tests/acceptance/132.test.tsx` — **new file** with acceptance tests
- `package.json` / `package-lock.json` — no change (Capacitor Haptics already installed per `node_modules/@capacitor/haptics`)

## Edge cases

1. **Row with a nested action control** (the `action` prop slot): The nested control must remain independently clickable and must **not** trigger row navigation when pressed. Test: render a row with an action button, click the button, assert the button's handler fired and the row link's handler did **not**.

2. **Long-press**: No context menu, no distinct behaviour from a regular press. A long-press should navigate to the job exactly as a tap does.

3. **Press started on the row, released outside its bounds**: No navigation fires, and the active state returns to resting. This is standard browser `<a>` behaviour and requires no custom handling, but verify it holds with the overlay.

4. **Rows rendered while data is still loading** (no `href` prop): The overlay is present in the DOM but inert (no `href` attribute, so it renders as a non-navigable element). Test: render a row with `href={undefined}`, attempt to "click" it, assert no navigation.

5. **Keyboard navigation**: Pressing Enter while the overlay is focused must navigate to the job. Pressing Tab must move focus to the next focusable element (the action control if present, else the next row). Test: render a row, focus the overlay via `focus()`, fire a keydown Enter event, assert navigation.

6. **Screen reader announcement**: The overlay must announce the customer name as its accessible name, exactly as the current implementation does. Test: render a row with `customerName="Alice Ltd"`, query by role `link` with name `"Alice Ltd"`, assert it exists.

7. **Reduced motion**: When `prefers-reduced-motion: reduce` is active, the background change applies but the scale transform does **not**. This uses Tailwind's `motion-safe:active:scale-[0.99]` variant. Browser emulation of this media query is sufficient for testing.

8. **Haptic on web platform**: `Capacitor.isNativePlatform()` returns `false`, so the haptic call is skipped. Test: mock as web platform, render and click a row, assert `Haptics.impact` was never called.

9. **Haptic on native platform**: `Capacitor.isNativePlatform()` returns `true`, and the tap fires `Haptics.impact({ style: "light" })`. Test: mock as native, render and click a row, assert `Haptics.impact` was called once with `{ style: "light" }`.

10. **Row without an `href`** (no link at all): The customer name renders as a `<span>`, not a `<Link>`, and the overlay is absent (or inert). This is existing behaviour for rows with no destination. Verify the overlay does not add a broken link.

## Risks

- **None touching money, migrations, or user data** — this is a UI interaction enhancement only.
- **Regression risk**: Existing action controls in the right-edge slot must remain independently clickable. If the overlay's z-index is wrong or event propagation is not stopped, clicking an action button could navigate to the job instead of firing the button's handler. Mitigation: test the nested control explicitly, and position the overlay below interactive children via CSS layering.
- **Accessibility risk**: If the overlay is not properly labeled, screen readers may announce "link" with no name, breaking navigation for non-sighted users. Mitigation: give the overlay an `aria-label` matching the customer name, and verify it via `getByRole("link", { name: customerName })`.

## Derived criteria

The human is asking for:

1. A tap anywhere within the row bounds (left edge, right edge, top, bottom) navigates to the job — verified by asserting the overlay link covers the full row.
2. A visible background color change while the row is pressed (active state).
3. A `scale(0.99)` transform while pressed, applied only when motion is not reduced.
4. A `Haptics.impact({ style: "light" })` call on press, only on native platforms.
5. Any existing interactive control inside the row (the `action` slot) remains independently tappable and does **not** trigger row navigation.
6. The row is keyboard-navigable: Enter on the overlay navigates, Tab moves to the next element.
7. The overlay announces the customer name to screen readers, exactly as the current link does.
8. When `prefers-reduced-motion: reduce` is set, the scale does not apply but the background change does.
9. On web platforms, the haptic call is skipped (guarded by `isNativePlatform()`).
10. Rows with no `href` prop do not render a broken or inert overlay link.
