# Issue #141: Render the live transcript during voice intake

**Source:** [Notion roadmap item](https://app.notion.com/p/Render-the-live-transcript-during-voice-intake-3b81e4f908b481779746f581a775856c)

**Module:** ui

## Problem

The voice intake transcript is captured in `transcriptRef` and rendered nowhere. The user speaks and sees only the orb during the voice intake session. They have no way to tell whether they were heard until the quote appears at the end of the conversation, which is the point at which a mis-transcription is expensive to unpick. This is a silent leap of faith that creates user anxiety and prevents mid-conversation self-correction.

## Scope: what changes

Add a visible transcript area to the voice intake screen (`src/app/jobs/new/page.tsx`) that:

1. Renders the accumulating transcript text as it arrives in `transcriptRef`, updating without triggering a full re-render of the orb or other controls
2. Auto-scrolls to keep the most recent line visible when new text arrives
3. Occupies fixed bounds and does not push the orb, controls, or other UI elements out of position as it grows
4. Clears when a new session starts (when `attempt` increments)
5. Remains visible when the session ends with an error (so the user retains what was captured)
6. Pauses auto-scroll when the user manually scrolls up to review earlier parts of the transcript, resuming auto-scroll only when they return to the bottom

The transcript text should render in the same style for all segments — no confidence indicators, no per-segment styling, no distinction between low-confidence and high-confidence text.

## Explicitly out of scope: what does not change

- Do **not** change transcription logic, session handling, connection logic, or the orb behavior
- Do **not** make the transcript text editable
- Do **not** add confidence indicators, corrections UI, or per-segment styling beyond uniform text rendering
- Do **not** persist the transcript beyond the session (it already persists via `saveVoiceTranscript` at the appropriate times; this item only adds visual rendering)
- Do **not** change the finish flow or navigation behavior

## Files

The complete list of files expected to change:

- `src/app/jobs/new/page.tsx` — add transcript rendering area, wire up `transcriptRef` to visible UI, implement auto-scroll with manual override detection

## Edge cases

1. **No speech detected:** The transcript area renders empty with no placeholder text or "waiting for speech" message. It's just an empty scrollable region.

2. **Very long session:** Older transcript lines scroll out of view as new lines arrive, but they remain in the scrollback. The user can scroll up to review them. Do **not** truncate the transcript — all accumulated lines stay available for scrollback.

3. **Session ends with an error:** The transcript remains visible on screen (rather than clearing) so the user retains what was captured. This applies to mic failures, connection errors, and pipeline failures.

4. **User scrolls up manually:** Auto-scroll pauses. When the user scrolls back to the bottom (within some threshold of the scroll container's max scroll), auto-scroll resumes. This prevents jarring scroll jumps while the user is reading earlier parts of the transcript.

5. **New session starts:** The transcript clears completely. The `attempt` counter increment that triggers a new connection attempt should also clear the transcript UI state (though the ref itself is already cleared in the connect effect cleanup).

## Risks

None. This item is purely additive UI rendering with no database changes, no migrations, no user data persistence changes, and no money-touching logic. The transcript data is already captured in `transcriptRef` and persisted server-side when appropriate — this item only makes it visible during the session.

## Derived criteria

What I understood the human to be asking for:

1. The user can see the transcript text accumulating live as they speak and as the assistant responds, rather than seeing only the orb
2. The most recent line of the transcript stays visible automatically (it scrolls into view as new text arrives)
3. The transcript area has a fixed height/bounds so it doesn't push the orb or the "Finish & price it up" button off screen when the transcript grows long
4. When the user starts a new voice session (after an error or cancellation), the transcript from the previous session disappears
5. If the session errors out (mic failure, connection drop, pipeline timeout), the transcript text stays on screen so the user can see what was captured before the failure
6. The user can scroll up in the transcript to review earlier parts without new text arriving and auto-scrolling them back to the bottom involuntarily
7. All transcript text looks the same — no visual distinction between confident vs uncertain transcriptions, no editing UI, just readable text
8. The transcript area shows nothing (not a placeholder, not a hint) when the session is live but no one has spoken yet
