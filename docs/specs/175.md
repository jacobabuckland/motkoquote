# Issue #175: Sanitise transactional email subject lines

## Problem

Every transactional email subject interpolates the contractor's company name directly into a template string without sanitisation. Because the company name is free text typed during setup, a newline in it can inject a line break into a mail header (the classic route to mail header injection), and leading, trailing, or repeated whitespace goes out exactly as typed, making subjects like "Your quote from   Smith  &  Sons" read as broken software.

## Scope: what changes

- A new shared helper function `sanitizeEmailSubject` that removes control characters (carriage returns, line feeds, and other control characters), collapses runs of whitespace to a single space, and trims both ends
- `sendQuoteEmail` subject line is built through the helper
- `sendInvoiceEmail` subject line (both deposit and final invoice variants) is built through the helper
- `sendContractEmail` subject line is built through the helper
- `sendChaseEmail` subject line (payment reminder) is built through the helper
- Unit tests covering the helper directly, including names with embedded newlines, doubled spaces, control characters, and clean names that should pass through unchanged

## Explicitly out of scope: what does not change

- No change to the wording of any subject line template
- No validation or rejection of company name at input time; the setup flow is unchanged
- `escapeHtml` and all email body templates are untouched — this changes subject lines only
- No length limit or truncation is added
- No change to how email is sent or which provider (Resend) is used
- No database migration required

## Files

- `src/lib/email.ts` — add the `sanitizeEmailSubject` helper and apply it to every `subject:` line that interpolates `companyName`
- `tests/acceptance/175.test.ts` — acceptance tests verifying the helper and its use across all email functions

## Edge cases

- **Empty or whitespace-only company name:** The helper returns an empty string; the email is still sent; the subject reads as the template with nothing in the name position and no doubled spaces left behind (e.g. "Your quote from " becomes "Your quote from")
- **Legitimate punctuation (e.g. "Smith & Sons Ltd.", "O'Neill Plumbing"):** Preserved unchanged — only control characters and excess whitespace are removed
- **Non-Latin characters or emoji in a name:** Preserved, not stripped — the helper only removes control characters and normalises whitespace
- **Name that is nothing but control characters:** Behaves as the empty case — the helper returns an empty string
- **Name with a single newline (`"Smith\nSons"`):** The newline is removed; result is `"SmithSons"` (no space inserted where the newline was)
- **Name with multiple consecutive spaces (`"Smith  &  Sons"`):** Collapsed to single spaces: `"Smith & Sons"`
- **Name with leading or trailing whitespace (`"  Smith & Sons  "`):** Trimmed to `"Smith & Sons"`
- **Account deletion email subject:** Already contains no interpolation, so the helper is not needed and nothing changes

## Risks

- **Mail header injection:** This fix closes the injection vector. The risk is REMOVING the vulnerability, not introducing one.
- **Email deliverability:** Sanitising subjects should improve deliverability (malformed headers can cause bounces), not harm it.
- **User-visible change:** Subjects become tidier. A contractor whose company name currently has doubled spaces or line breaks will see those cleaned up in outbound emails — this is the intended fix, not a regression.
- **No data migration:** Company names in the database are not touched. Sanitisation happens at send time only.

## Derived criteria

- One shared `sanitizeEmailSubject` helper exists in `src/lib/email.ts`
- The helper removes all control characters: `\r` (CR), `\n` (LF), `\t` (tab), and any other character in the Unicode control category
- The helper collapses runs of whitespace (spaces, tabs, etc.) to a single space
- The helper trims leading and trailing whitespace
- A company name with an embedded `\n` cannot introduce a line break into the sent subject
- A company name with doubled spaces (`"Smith  &  Sons"`) is collapsed to single spaces in the subject
- A clean company name (`"Smith & Sons"`) passes through unchanged
- An empty or whitespace-only company name results in a subject with no doubled spaces and no stray whitespace at the name position
- `sendQuoteEmail` uses the helper on its subject
- `sendInvoiceEmail` uses the helper on its subject (both deposit and final variants)
- `sendContractEmail` uses the helper on its subject
- `sendChaseEmail` uses the helper on its subject
- `sendAccountDeletionEmail` is untouched (its subject has no interpolation)
- Email bodies are untouched: `escapeHtml` continues to be used exactly as it is today
- No subject line wording is changed — only the interpolated company name is sanitised
- Unit tests cover: name with embedded newline, name with doubled spaces, name with leading/trailing whitespace, name with control characters, clean name unchanged, empty name, whitespace-only name
