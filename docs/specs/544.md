# PFIX-5: Redefine the invention-rate metric

## Problem

The existing 55% invention-rate metric cannot be used as a ship gate because it measures code transformations rather than user rejection. The distribution is perfectly bimodal (identical counts or collapsed to exactly one line), nine of ten collapses were code-driven, and the figure is dominated by two test accounts. With voice intake currently paused, there is no organic signal to derive a meaningful percentage from. A fixture-derived binary gate is the only honest metric available while the product has no active user population.

## Scope: what changes

1. **New binary check function** (`checkNoInventedPrices` in `tests/helpers/pipeline-compare.ts`):
   - Extracts all monetary values from a fixture's transcript
   - Compares compiled line items against those values
   - Returns failures for any line item whose unit_price does not appear in the transcript
   - Handles edge cases: provisional sums, customer-supplied materials (£0), superseded prices

2. **Integration into pipeline harness** (`tests/pipeline/harness.test.ts`):
   - Add `checkNoInventedPrices` alongside existing checks (`checkStatedPricesSurvive`, `checkForbiddenAmounts`)
   - The combined check becomes the binary invention gate
   - Invocable via `npm run test:pipeline`

3. **Documentation updates**:
   - Mark 55% withdrawn in `docs/robustness-review-findings.md` §3
   - Mark 55% withdrawn in `docs/robustness-tickets.md` where PFIX-5 is described
   - Both carry a pointer to the decision (areas/motko.md, 2026-09-03)

## Edge cases

### A fixture whose transcript legitimately contains no prices
Every line should be unpriced or contractor-sourced (looked up from stored rates). A model-supplied figure is the defect this gate exists to catch. Include these scenarios rather than excluding them.

### A stated price that is superseded mid-call
The superseding figure counts as present in the transcript. The superseded one does not and must not appear on any line (already covered by `checkForbiddenAmounts`).

### Provisional sums
An editable placeholder (`provisional: true`) is not an invented price — it's marked as an estimate the contractor will refine. Exclude provisional lines from the invention check.

### Customer-supplied materials
Lines with `supplied_by: "customer"` price at £0 for scope tracking. Zero is not an invented price.

### Contractor-supplied materials with no stated price
If the transcript contains no price for an item and the contractor has no stored material price, the line may be unpriced (`unpriced: true`) or carry a model estimate marked `assumed: true`. Both are acceptable — this check targets prices that appear solid but were never stated.

### Labour lines priced from stored rates
A labour line priced from the contractor's stored `day_rate` or `overtime_rate` is not invented, even if those specific figures don't appear in the transcript. Exclude labour lines from the monetary-value check.

## Risks

**Low**. This is a test infrastructure change with no production code impact. The gate will initially be RED against scenario-1 (two findings already documented), which is correct behaviour — the pipeline currently does invent prices, and this gate detects it.

## RUNNABLE

The gate is part of `npm run test:pipeline`, not a standalone script. It runs as one of the checks in the pipeline harness test suite.

## Derived criteria

1. The 55% figure no longer appears in any document, dashboard, or gate as a current metric
2. Where the 55% appeared, it is explicitly marked "withdrawn" with a pointer to the decision
3. The `checkNoInventedPrices` function exists in `tests/helpers/pipeline-compare.ts` and is exported
4. The function takes a fixture name, transcript string, and compiled line items
5. It returns an array of `Failure` objects (same type as other comparison functions)
6. Against scenario-1, it correctly identifies the two known invention findings (£1,400 tiling labour stated but reaching no line, £140 radiator swap stated but appearing on multiple unrelated lines)
7. Provisional sums do not trigger the check (editable estimates are not invented prices)
8. Customer-supplied lines at £0 do not trigger the check
9. Labour lines priced from stored rates do not trigger the check
10. The check is integrated into the pipeline harness and runs as part of `npm run test:pipeline`
11. A one-penny change to a stated price that causes a line item to no longer match the transcript produces a named failure
