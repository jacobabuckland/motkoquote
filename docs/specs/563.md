# PFIX-11: "seven and a half thousand" extracts no stated price at all

## Problem

The stated-price extractor does not handle fractional multipliers in spoken amounts. When a contractor says "seven and a half thousand", "two and a half grand", or "one and a quarter thousand", the extractor returns nothing at all — not mis-parsed, simply not extracted.

This was found in a live call on 4 Sep. A contractor said "I'm gonna fix price it at seven and a half thousand" and the quote came out correct at £7,500, but the Scope of Work said "No spoken prices were picked up in this call" and the £7,500 line carried "Provenance unknown".

The figure survived only because the assistant confirmed it conversationally and it reached `pricing.fixed_amount` by a different path. The stated-price extractor recorded nothing.

## Scope: what changes

Handle fractional multipliers `and a half`, `and a quarter`, and `and three quarters` before scale words (`thousand`, `hundred`):

```
seven and a half thousand       -> 7500 (£7,500.00)
two and a half grand            -> 2500 (£2,500.00)
one and a half thousand         -> 1500 (£1,500.00)
one and a quarter thousand      -> 1250 (£1,250.00)
three and three quarters grand  -> 3750 (£3,750.00)
```

The fix belongs in `parseSpokenMoneyAmount` in `src/lib/parse-spoken-money.ts`, which is where all spoken-money parsing logic lives. The function is pure and deterministic — same input always produces same output — and this change preserves that property.

**Decision on quarter fractions** (recorded in `areas/motko.md`, 2026-09-04): Include "and a quarter" and "and three quarters" alongside "and a half". All three are natural variants of the same fractional speech pattern. Supporting only "and a half" would leave "one and a quarter thousand" broken, requiring a future PFIX-12 for the identical fix.

## Explicitly out of scope

- How a stated price is attributed to a line (PFIX-1, PFIX-3)
- The fixed-price path through `pricing.fixed_amount` (already works)
- Changes to `extractStatedPrices` logic beyond what `parseSpokenMoneyAmount` returning the correct value achieves
- Other fractional forms beyond half, quarter, and three-quarters (e.g., "and two thirds", "and one fifth")

## Files

- `src/lib/parse-spoken-money.ts` (modify) — add fractional multiplier handling in `parseSpokenMoneyAmount`
- `src/lib/voice/stated-prices.ts` (modify) — the word-list regexes in
  `extractBestMoneyPhrase` and `findCandidates` must recognise `grand`, `a`,
  `an`, `half`, `quarter` and `quarters`, or a phrase carrying a fractional
  multiplier is discarded before `parseSpokenMoneyAmount` ever sees it
- `tests/regression/spoken-money-leading-fraction.test.ts` (new) — end-to-end
  cover for the leading form through `extractStatedPrices`
- `tests/acceptance/563.test.ts` (new) — acceptance tests asserting extracted amounts

## Edge cases

1. **Fractional hundred**: "one and a half hundred" should parse as 150 (£150.00)
2. **Without scale word**: "seven and a half" with no "thousand" or "hundred" should return null (ambiguous)
3. **Multiple fractions in one phrase**: "one and a half and a quarter thousand" is malformed and should return null
4. **Fraction without "and"**: "seven a half thousand" is malformed and should return null
5. **Whole amounts unchanged**: "seven thousand" must continue to parse as 7000 (£7,000.00)
6. **Inside a sentence**: "The job is seven and a half thousand pounds" should extract 7500, same as the bare form
7. **Grand normalization**: "two and a half grand" normalizes to "two and a half thousand pounds" before parsing (existing behavior)
8. **Refusal unchanged**: Amounts with hedges, ranges, or rate units must still be refused (existing behavior)

## Risks

**Money integrity**: This parser feeds stated prices into the locking and reconciliation system. A mis-parse becomes a chargeable amount attributed to the contractor. The implementation must preserve determinism (pure function, no randomness) and must not weaken existing refusal logic (hedges, ranges, negation).

**Regression**: The parser has 60+ existing test cases. All must continue passing. Fractional support is additive — it turns null returns into valid amounts for a specific pattern, and must not alter any existing successful parse.

## Derived criteria

From the issue and scope above, the implementation must:

1. Parse "seven and a half thousand" as 750000 pence (£7,500.00)
2. Parse "two and a half grand" as 250000 pence (£2,500.00)
3. Parse "one and a half thousand pounds" as 150000 pence (£1,500.00)
4. Parse "one and a quarter thousand" as 125000 pence (£1,250.00)
5. Parse "three and three quarters grand" as 375000 pence (£3,750.00)
6. Parse "one and a half hundred" as 15000 pence (£150.00)
7. Return null for "seven and a half" with no scale word (ambiguous)
8. Return null for malformed fractional phrases (multiple fractions, missing "and")
9. Preserve all existing passing test cases in `src/lib/parse-spoken-money.test.ts`
10. Extract the spoken price from a full sentence containing a fractional amount (e.g., "The job is seven and a half thousand pounds")
11. Maintain determinism: same input always produces same output
12. Maintain purity: no side effects, no external calls
