# Sort the active jobs list by urgency, not recency

**Decision source:** `areas/motko.md` — "Which sort order does the active jobs list use?" (2026-08-21). Money-urgency tiers, oldest-first within each tier, job ID tie-break, labelled sections, dashboard unchanged.

## Problem

The jobs list currently sorts by most-recent-activity (reverse chronological on `sortAt`). A £900 invoice unpaid for thirty days sits below a draft quote edited yesterday. The order tells a contractor which job they touched most recently, not which one needs their attention most. Once terminal states are filtered from the default view, ranking the remaining active work by urgency — outstanding money first, stale drafts last — puts the right jobs at the top.

## Scope

**What changes:**

1. **New sorting function for in-progress jobs:** `sortByUrgency` replaces `sortByRecency` for the `in_progress` bucket only. Jobs are grouped into five tiers based on their situation, then sorted oldest-first within each tier, with job ID as a final deterministic tie-break:
   - Tier 1: Overdue invoices (`invoice_overdue`)
   - Tier 2: Unpaid invoices (`invoice_unpaid`)
   - Tier 3: Sent quotes (`quote_sent`)
   - Tier 4: Sent contracts (`contract_sent`)
   - Tier 5: Drafts (`draft_quote`)

2. **Labelled sections in the UI:** When displaying in-progress jobs, the list is broken into labelled sections corresponding to the tiers above. Each section header shows the tier name (e.g., "Overdue invoices", "Unpaid invoices", "Sent quotes"). Empty tiers are omitted — if there are no overdue invoices, the "Overdue invoices" header does not appear.

3. **HistoryJob type extension:** Add a `situation` field to `HistoryJob` (sourced from `deriveJobState`) so the sorting function can tier jobs by their pipeline position without re-deriving state.

4. **Conditional sort in jobs page:** The `/jobs` page applies `sortByUrgency` when `filter === "in_progress"` and `sortByRecency` otherwise (for `completed`, `archived`, `declined`, and `all`).

## Explicitly out of scope

- **No change to Completed, Archived, or Declined sorting.** These buckets continue sorting by recency (most-recent-activity first). The urgency ranking only applies to `in_progress`.
- **No change to the dashboard.** This ticket affects `/jobs` (the "My work" history page) only. The dashboard is unchanged.
- **No user-configurable toggle.** The sort order is fixed: urgency for in-progress, recency for everything else.
- **No change to what jobs appear.** Filtering terminal states from the default view is handled by the jobs list filter ticket. This ticket only reorders what remains after filtering.
- **No notifications, chasing, or automated actions.** This ticket surfaces urgency in the UI. It does not trigger reminders or alter any background behaviour.

## Edge cases

**Null or missing timestamps:**
- If `sortAt` is somehow null or malformed, treat it as epoch (oldest possible) so the job does not vanish from the list.
- If `jobId` is missing, fall back to comparing empty strings (deterministic, though this should never happen in practice).

**Multiple invoices on one job:**
- `deriveJobState` already selects the first unpaid invoice as `activeInvoice`. The situation is `invoice_overdue` if that invoice is overdue, `invoice_unpaid` otherwise. A job with multiple invoices falls into one tier, not multiple.

**Jobs not in a recognised tier:**
- Situations `accepted_need_contract` and `signed_need_invoice` are in-progress states that do not map to the five tiers above. These fall into a catch-all tier 6 (lowest priority, after drafts) and are labelled "Other in-progress jobs". This ensures every in-progress job has a section, even if its situation is not one of the five primary urgency states.

**Empty sections:**
- A tier with zero jobs does not render a section header. If a contractor has no overdue invoices, the "Overdue invoices" heading does not appear.

**Situations outside in_progress:**
- The `all` filter includes completed, declined, and archived jobs alongside in-progress ones. These do not have urgency tiers — `all` continues sorting by recency across the whole set, with no section headers.

## Risks

- **None.** This ticket is pure UI reordering. It does not touch money, migrations, auth, or user data. The sort is client-side (in the Next.js page render), so a mistake surfaces immediately and is reversible by revert.

## Derived criteria

1. When viewing the "In progress" filter, jobs are grouped into labelled sections by urgency tier: overdue invoices, unpaid invoices, sent quotes, sent contracts, drafts, and a catch-all for other in-progress states.
2. Within each tier, jobs are sorted oldest-first (earliest `sortAt` → latest `sortAt`), with job ID as a tie-break when timestamps are identical.
3. The sort order is deterministic: two renders of the same data produce the same order.
4. Empty tiers do not render section headers.
5. Completed, Archived, Declined, and All filters continue sorting by recency (most recent activity first), with no section headers.
6. The dashboard (`/`) is unchanged — this ticket affects only `/jobs`.
7. The tier labels are human-readable ("Overdue invoices", not "invoice_overdue").
8. A job in the `in_progress` bucket whose situation does not match the five primary tiers (e.g., `accepted_need_contract`, `signed_need_invoice`) falls into the catch-all tier and is labelled "Other in-progress jobs".
