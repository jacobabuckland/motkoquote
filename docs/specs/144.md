# Issue #144: Add a monogram fallback and fix logo alt text

**No database migration required.**

## Problem

Trades without an uploaded logo render nothing where a logo would sit on customer-facing pages (quotes, invoices, contracts). An empty logo slot on a payment request or contract reads as broken rather than as absent branding. Additionally, logo images render with `alt=""`, meaning screen reader users receive no indication of who is requesting payment on a page whose entire purpose is establishing who is asking.

## Scope: what changes

### 1. New monogram component
**File:** `src/components/ui/monogram.tsx` (new file)

A pure React component that renders a company's initials on its brand color:
- Accepts `companyName: string`, `brandColor?: string`, `size?: number`
- Extracts 1-2 initials from the company name
- Calculates contrast ratio and chooses dark or light text to meet WCAG AA (4.5:1 for small text)
- Renders a circular or rounded-square element with initials centered
- Empty/null company name renders a neutral placeholder glyph (a generic building/shop icon or similar)

### 2. Initials extraction helper
**File:** `src/lib/extract-initials.ts` (new file)

A pure function `extractInitials(name: string): string` that:
- Returns the first letter of the first word for single-word names
- Returns the first letter of the first two words for multi-word names (2+ words)
- Handles names starting with non-letter characters by finding the first two alphanumeric characters
- Returns empty string if no alphanumeric characters exist (caller falls back to placeholder)

### 3. Contrast calculation helper
**File:** `src/lib/color-contrast.ts` (new file)

A pure function `getContrastingTextColor(backgroundColor: string): string` that:
- Calculates the relative luminance of the background color
- Returns a dark text color for light backgrounds, light text color for dark backgrounds
- Handles invalid hex colors by defaulting to a safe assumption
- Meets WCAG AA contrast ratio (4.5:1 minimum)

### 4. Update customer-facing pages to render monogram
**Files:** `src/app/q/[id]/page.tsx`, `src/app/i/[id]/page.tsx`, `src/app/c/[id]/page.tsx`

Replace the conditional logo render:
```tsx
{logoUrl && <img src={logoUrl} alt="" className="..." />}
```

With:
```tsx
{logoUrl ? (
  <img src={logoUrl} alt={companyName} className="..." />
) : (
  <Monogram companyName={companyName} brandColor={brandColor} size={48} />
)}
```

The `alt` attribute is set to the company name in all cases.

### 5. Update PDF header to render monogram
**File:** `src/lib/pdf/shared.tsx`

Modify `PdfHeader` to render a monogram (via @react-pdf/renderer primitives: View, Text) when `logoUrl` is absent, following the same initials/contrast rules. Since @react-pdf/renderer's `Image` doesn't have alt text (it's not HTML), no alt fix is needed there.

## Explicitly out of scope

- Do not add logo upload, cropping, or management
- Do not change how the brand color is stored, validated, or chosen
- Do not apply the monogram to authenticated internal surfaces (dashboard, job pages visible only to the contractor)
- Do not change logo dimensions or positioning
- Do not add user-configurable monogram styles (font, shape, etc.)
- Do not validate that the company name is present — the schema already requires it, so treat a missing name as a data integrity edge case only

## Edge cases

- **Company name is empty or null**: render a neutral placeholder glyph (e.g. a building icon), not an empty monogram. Set alt to "Company logo" on the placeholder.
- **Company name begins with a non-letter character**: use the first two alphanumeric characters found. If no alphanumeric characters exist, use the neutral placeholder.
- **Company name is one word**: extract one initial (e.g. "Acme" → "A").
- **Company name is two words**: extract the first letter of each (e.g. "Acme Corp" → "AC").
- **Company name is three or more words**: extract the first letter of the first two words only (e.g. "Acme Corp Ltd" → "AC").
- **Brand color is unset or invalid**: use the default brand color `#004225`.
- **Brand color is very light**: monogram text switches to dark per the contrast criterion (WCAG AA, 4.5:1).
- **Brand color is very dark**: monogram text switches to light (white or near-white).
- **Legacy persisted data**: trades with no logo and no brand color render the monogram on the default brand color.
- **User-visible**: yes, to the trade's customers on quote/invoice/contract share links and PDFs.

## Risks

- **Accessibility**: the contrast calculation must be correct to meet WCAG AA. The acceptance tests verify that light backgrounds get dark text and dark backgrounds get light text, with specific test cases for edge colors.
- **Customer perception**: a monogram is better than an empty slot, but a poorly-chosen or broken monogram (wrong initials, unreadable text) could erode trust. The initials logic is tested exhaustively.
- **PDF rendering**: @react-pdf/renderer doesn't support all CSS/SVG features. The monogram in PDFs uses only basic View/Text primitives to ensure it renders correctly.
- **Brand color validation**: invalid hex colors must degrade gracefully. The contrast helper treats invalid input as the default dark green.

## Derived criteria

Based on the Notion spec, I understand the requirement to be:

1. A `Monogram` component renders the company's initials (1-2 letters) on its brand color background
2. The monogram is displayed on customer-facing surfaces (quote, invoice, contract pages and PDFs) when no logo exists
3. Initials are extracted as: one word → 1 initial, two+ words → first 2 initials
4. Monogram text color is chosen to meet WCAG AA contrast against the brand color (4.5:1 for small text)
5. Company names starting with non-letter characters use the first two alphanumeric characters found
6. Empty or all-non-alphanumeric company names render a neutral placeholder glyph, not an empty monogram
7. All logo `<img>` elements set `alt` to the company name (grep for `alt=""` on customer-facing paths returns zero results)
8. The monogram matches the logo's dimensions (h-12 w-12 on web, ~40pt height in PDFs)
9. Invalid or unset brand colors fall back to the default `#004225`
10. The contrast calculation correctly handles very light backgrounds (→ dark text) and very dark backgrounds (→ light text)
