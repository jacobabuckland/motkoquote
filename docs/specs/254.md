# Issue #254: LED-3: Receipt photo capture with confirmed extraction

**This item requires a database migration.**

Auditing branch: `factory/254` @ `8ce0eb2`

## Problem

Contractors will not type costs into a phone at the merchant counter. The two capture moments that will actually happen: photographing a receipt at the till, and speaking on the drive back. This card implements the photo half. Currently there is no way to capture cost data from a receipt photo at all — no camera access, no extraction, no cost storage linked to a job. Without this, the contractor either reconstructs costs from memory later (error-prone) or abandons cost tracking entirely (no profit visibility).

## Scope: what changes

Add a receipt photo capture flow accessible from the job page that stores the photo in Supabase storage and offers AI extraction of key fields (total, supplier name, date, VAT if legible). The extraction result is presented as a **pre-filled, editable draft** that requires explicit confirmation before any database row is written. Extraction failure is a normal outcome that falls back cleanly to a manual entry form with the photo already attached.

The photo is the record of truth. It is stored in RLS-scoped Supabase storage and linked via a new `job_costs` table. The photo remains viewable on the cost row after save — its value outlives the extraction.

### Database changes

Create `job_costs` table:
- `id` (uuid, PK)
- `job_id` (uuid, FK to jobs)
- `contractor_id` (uuid, FK to contractors, for RLS scoping)
- `amount` (numeric, the cost total)
- `supplier` (text, supplier name)
- `cost_date` (date, when the cost was incurred)
- `vat_amount` (numeric, nullable, VAT portion if known)
- `evidence_url` (text, nullable, Supabase storage URL for receipt photo)
- `extraction_method` (text, nullable, one of: 'ai', 'manual', 'voice')
- `created_at` (timestamptz)

Create storage bucket `receipts` (private, RLS-scoped to contractor's folder via `auth.uid()`).

Enable RLS on `job_costs` with policy scoped via `contractor_id`.

### Capture flow

From the job page, a "Add cost" button opens a camera/library picker. The contractor can:
1. Take a photo with the camera
2. Choose an existing photo from the library

**Camera permission handling:** If permission is denied, the camera option is hidden and only library upload is shown. Reuse the microphone permission patterns from `src/components/voice/mic-permission-screen.tsx` and `src/lib/mic.ts` — adapt them for camera instead of mic. On iOS WKWebView, `openAppSettings()` deep-links into Settings if permission is denied.

**Photo compression:** Compress to target size **800KB max** before upload. Handle rotation EXIF metadata so photos appear right-way-up.

**Offline behavior:** If offline when capture is attempted, show a clear message "No connection — try again when online" and do not attempt upload. Do NOT queue for later upload (queuing is out of scope).

### Extraction flow

After photo upload, call an AI extraction API route (`/api/costs/extract`) that:
1. Takes the storage URL
2. Sends the image to Claude (use the Messages API with vision — see `claude-api` skill)
3. Returns structured JSON: `{total, supplier, date, vat}` or `{error: "could_not_extract"}`

**Extraction is optional.** If it fails (no text found, unreadable, API error), proceed immediately to manual form with the photo already attached.

**If extraction succeeds:** Present a draft form with fields pre-filled but fully editable. The contractor can change any value before confirming. The form shows the receipt photo thumbnail above the fields as visual confirmation of what's being entered.

**Sanity bounds on extraction:** If `total` is outside the range £0.01 to £100,000, or if `date` is more than 2 years in the past or in the future, treat it as extraction failure (do not present the implausible value — go straight to manual form). This prevents a phone number being read as a £7,000,000 cost.

**Confirmation required:** A "Save cost" button. Until tapped, no row is written to `job_costs`. The draft state exists only in the form component's local state.

### Manual entry fallback

If extraction fails or the contractor chooses "Enter manually", show a blank form with:
- Amount (£, required)
- Supplier (text, optional)
- Date (date picker, defaults to today, optional)
- VAT (£, optional)

The receipt photo (if one was captured) is already attached and shown as a thumbnail. When saved, `extraction_method` is set to `'manual'`.

### Cost display on job page

Below the job timeline, a "Costs" section lists all `job_costs` rows for this job. Each row shows:
- Supplier (or "Unnamed supplier" if null)
- Amount formatted as GBP
- Date formatted as "12 Aug 2026" or "No date" if null
- Receipt thumbnail (if `evidence_url` is set) — tapping the thumbnail opens the full-size photo in a modal or new tab

Total costs summed at the bottom of the list.

## Explicitly out of scope: what does not change

- **No multi-receipt batch capture.** One photo at a time.
- **No line-item extraction.** Only total, supplier, date, VAT. Do not attempt to parse individual line items from the receipt.
- **No accounting export.** Costs are stored but not exported to Xero/QuickBooks/etc.
- **No offline upload queuing.** If offline, the capture fails clearly with a message. Do not store photos locally and retry upload later.
- **No edit/delete of saved costs.** Once saved, a cost row is immutable (edit/delete can be added later if needed).
- **No voice capture.** That is a separate item. This is photo only.
- **No cost categories or tagging.** Costs are flat records: amount, supplier, date, VAT.

## Edge cases

**Camera permission denied:** Hide camera option, show only library upload. If permission was previously granted and then revoked in Settings, show a message with "Open Settings" button (deep-link via `openAppSettings()`).

**Offline when capture is attempted:** Show message "No connection — try again when online" and do not attempt upload. The photo is not lost (it's in the device's camera roll if taken via camera) but the upload does not queue.

**Very large image (e.g., 12MP photo from iPhone):** Compress to 800KB max before upload. Use a canvas resize or similar client-side compression. Do not upload the full-resolution photo and compress server-side — that wastes bandwidth and will fail on slow connections.

**Rotated image (EXIF orientation):** Handle EXIF rotation metadata so photos appear right-way-up in the UI. If using canvas compression, apply rotation during resize.

**Extraction returns implausible amount:** If `total` is < £0.01 or > £100,000, or if `date` is > 2 years old or in future, treat as extraction failure. Do NOT present the implausible value to the contractor — go straight to manual form as if extraction returned an error.

**Extraction returns partial data (e.g., total but no supplier):** Accept it. Pre-fill the total field, leave supplier blank. The contractor can fill in the missing fields.

**Extraction API error (network failure, Claude API down, rate limit):** Treat as extraction failure. Log the error for telemetry, show manual form with photo attached.

**No photo, manual entry only:** The contractor can choose "Enter manually" without capturing a photo. In this case `evidence_url` is null. This is a valid cost row.

**Photo viewable after save:** The receipt photo must remain viewable on the cost row. Tapping the thumbnail opens the full-size image. If the storage URL expires (Supabase signed URLs expire after a period), generate a fresh signed URL on each page load. Or use a public bucket — but if public, the RLS scoping must still prevent one contractor seeing another's receipts via direct URL enumeration. **Recommendation:** Private bucket with signed URLs refreshed on page load.

**User-visible:** Yes. This is a primary data capture path. The cost list appears on every job page where costs exist.

## Risks

**Database migration required.** Schema must precede code: apply the migration to production BEFORE merging the PR, or the deploy will break when the app tries to insert into `job_costs`.

**AI extraction cost.** Each receipt photo sends one Claude vision API call. At current pricing (~$3 per 1M input tokens, ~$15 per 1M output tokens, images ~$0.01 each), a single receipt costs ~$0.02 to extract. For 100 receipts/day, that's $2/day or $60/month. Acceptable for MVP. If usage grows, consider batching or cheaper extraction (Textract, Tesseract OCR + rule parsing). **For now, use Claude vision and monitor cost.**

**Photo storage cost.** Supabase storage is $0.021 per GB/month. At 800KB per photo, 1000 photos = 800MB = $0.017/month. Negligible.

**RLS on storage.** The pattern from `voice-notes` and `logos` buckets scopes storage objects by `(storage.foldername(name))[1] = auth.uid()::text`. This works only if the upload path is `{auth.uid()}/receipt-….jpg`. If the path structure is different, the policy must match. **Ensure the upload path includes `auth.uid()` as the first folder.**

**Camera permission on iOS.** `Info.plist` must include `NSCameraUsageDescription` or the app will crash when requesting camera access. Verify this exists (probably added for barcode scanning or similar). If missing, add it in the migration.

**Offline fallback.** "No connection" message is clear, but the contractor might not understand why their photo didn't save. Consider adding guidance like "Your photo is in your camera roll — try uploading again when you have signal."

**EXIF rotation.** iOS photos taken in portrait mode have EXIF orientation metadata. If not handled, they appear sideways in the browser. The compression step must read EXIF and apply rotation, or use a library that handles this automatically (e.g., `browser-image-compression` npm package).

**Extraction accuracy.** Claude vision is good but not perfect. Some receipts (faded thermal paper, handwritten, non-English) will fail extraction. This is why the manual fallback exists. Do not promise 100% extraction — treat failure as normal.

**Sanity bounds may be wrong.** £100,000 is an arbitrary upper limit. A large materials order might exceed this. If it does, the contractor has to enter manually. Acceptable for MVP — real contractors can tell us if the bound is wrong.

**No edit/delete.** Once saved, a cost cannot be edited. If the contractor makes a mistake, they have to add a correcting entry (e.g., negative amount). This is acceptable for MVP but will need edit/delete later.

**Signed URLs expiring.** If using private storage with signed URLs, the URL in `evidence_url` will expire. Either refresh the signed URL on each page load, or store the storage path (not the full URL) and generate signed URLs dynamically. **Recommendation:** Store the path, generate signed URL on render.
