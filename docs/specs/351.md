# Spec: Referral copy overstates what the referee gets — reword to referrer-only

**Issue:** #351

## Problem

The referral section copy tells the referrer that their referee "gets 3 free jobs" for using the code, but this is materially misleading: the referee gets exactly 3 free jobs whether or not they use a referral code (the `signup_grant` in `provisionNewContractor` is unconditional). Redeeming a code creates a `referrals` row and nothing else — no credit event for the referee. The reward flows one way: the referrer gets +3 credits (rising to +5 at five activated referrals) when the referee lands their first paid job.

The existing copy is literally true but misleading because it implies the code is what earns the referee those jobs. A trade reading it is being asked to make a promise on Motko's behalf that Motko does not keep.

**Decision 2026-08-25** (recorded in `areas/motko.md`): Reword to match reality. The referee gets the standard free jobs, the referrer gets the bonus. No extra grant on redemption. The consequence — the offer is now visibly one-sided — was accepted deliberately. Accuracy was chosen over sweetening it.

## Scope

Three strings in `src/app/settings/referral-section.tsx`, all visible to the referrer:

1. **Lines 19-21, body copy.** Currently: "Share your code with another trade. They get 3 free jobs, and you get 3 more (rising to 5 at 5 activated referrals)."
   
   Must stop implying the code is what earns the referee anything. State what the referrer gets, and either describe the referee's free jobs as what they'd get anyway, or leave them out entirely. The "rising to 5" part is correct and stays.

2. **Line 11, source comment.** Currently: "The referrer's +5 unlocks when the referred trade lands their first paid job."
   
   The amount is wrong. It's +3, rising to +5 at five activated referrals (per `src/lib/paid-job-settlement.ts:162`). Fix the comment to match.

3. **Any other place the offer is stated.** Check the file for any other misleading claims about what the referee receives.

## Explicitly out of scope

- **The credit logic itself.** `signup_grant` stays unconditional at `delta: 3`, and redemption stays credit-free for the referee. That is the decided behaviour, not an oversight to tidy up.
- **The referrer's credit amounts.** +3 rising to +5 is correct. Do not change it.
- **Any logic in `src/lib/referral-signup.ts` or `src/lib/paid-job-settlement.ts`.** This is a copy-only change.

## Files

- `src/app/settings/referral-section.tsx` — the three strings listed above

## Edge cases

1. **When the referral code is null.** The fallback message ("Your referral code will appear here…") is accurate and does not need changing.

2. **Empty state.** No edge case — the copy is shown whenever a referral code exists, which is after business setup completes.

3. **What if the copy appears elsewhere?** The scope says to check, but as of this spec the offer is only stated in this one component. If it appears in any join-adjacent work landing soon, apply the same rewording there.

## Risks

None. This is a copy-only change to remove a misleading claim. No logic, no schema, no money.

2. Fix the source comment (line 11) to say +3 rising to +5, not just +5.
