# CLEAN-5: Resolve settlement-reversal.ts against the new model

AMBIGUOUS: ESCALATION — Customer-facing legal or contractual copy

## Problem

The commercial model has moved from a service fee (£2–£4, variable ladder) to a transaction fee (0.99% + 39.6p, capped at £9.90). `src/lib/settlement-reversal.ts` was written for the service-fee era and references "service fee" throughout its rules, comments and exported constants. REFUND-1 (#611, merged) already calls this file and relies on its rules being correct — the refund path is live and working.

The behavior is correct: the fee is not returned on a refund, whether called "service fee" or "transaction fee". The problem is that the WORDING references a fee model that no longer exists, and these rules are published verbatim in the contractor terms (`src/app/terms/page.tsx` lines 75-82).

## What needs resolution — and why this escalates

Three surfaces state related but separate things:

1. **settlement-reversal.ts** — defines `REVERSAL_CLAUSE`, which says "The motko service fee is not refunded..."
2. **src/app/terms/page.tsx line 76** — renders `REVERSAL_CLAUSE.serviceFee` verbatim
3. **src/app/terms/page.tsx lines 52-56** — describes the fee schedule itself: "The Motko service fee is a percentage of the job: 0.3% of the first £5,000..." — THIS IS THE OLD MODEL

The terms page currently describes BOTH:
- The OLD service fee schedule (lines 52-56)
- The OLD refund wording via REVERSAL_CLAUSE (line 76)

But the new model is:
- Transaction fee: 0.99% + 39.6p, capped at £9.90
- Three free jobs (waiving both subscription and transaction fee)
- £9.99/month subscription

**This is customer-facing legal or contractual copy** (AGENTS.md escalation list). The contractor terms are a published contract. Changing them requires:
1. A decision about what the new wording says
2. Coordination between the fee schedule section and the refund rules section
3. Verification that the new wording accurately describes what the code does
4. Owner approval before any change ships

The card's own escalation clause says: "Do not edit the contractor terms — report the required change and stop."

## Scope if resolved: what would change

IF the escalation is resolved and the decision is to update the wording:

1. **settlement-reversal.ts** — update `REVERSAL_CLAUSE.serviceFee` to reference "transaction fee" instead of "service fee", preserving the rule that it is not refunded
2. **settlement-reversal.ts comments** — update references to "service fee" in header comments and inline documentation
3. **src/app/terms/page.tsx** — update "What Motko charges" section to describe the new transaction fee model
4. **The refund behavior itself: UNCHANGED** — `refund_application_fee: false` and no fee column writes, exactly as REFUND-1 already implements

## DECISION NEEDED

**Question:** Should settlement-reversal.ts and the contractor terms be updated to reference "transaction fee" instead of "service fee", and if so, what exact wording should the updated REVERSAL_CLAUSE and the terms page "What Motko charges" section use?

**Context:**
- The current REVERSAL_CLAUSE.serviceFee says: "The motko service fee is not refunded if a payment is later refunded or reversed. The fee is charged for work that has already happened — preparing the quote, the contract, and the payment itself — and that work is not undone by a refund."
- The current terms page describes the OLD service fee: "0.3% of the first £5,000, 0.2% of the next £5,000, and 0.15% above £10,000, with a £2.00 minimum"
- The NEW model is: 0.99% + 39.6p, capped at £9.90 (derived from Stripe's cost × 1.65)
- The refund BEHAVIOR is already correct — no fee is returned
- REFUND-1 is already live and calls this file

**Options:**
(a) Update both wording to say "transaction fee" and describe the new rate, keeping the non-refundable rule unchanged
(b) Update only the fee schedule section to the new model, leave REVERSAL_CLAUSE wording as-is (since the rule itself hasn't changed)
(c) Something else — what wording should each section use?

**Recommendation:** Option (a). The terms are a single coherent contract and should use consistent language throughout. "Service fee" no longer exists in the product, so leaving it in the refund section would confuse a contractor reading the document. The rule itself (fee is not refunded) stays identical; only the noun changes.
