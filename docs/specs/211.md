# Issue #211: PAY-5: Deprecate and remove TrueLayer integration (code only, data preserved)

**No database migration required.** All historical payment/mandate data is preserved; only code is removed.

## Problem

Once PAY-3 and PAY-4 are live and verified, the TrueLayer integration becomes dead code: API routes, client libraries, VRP mandate creation, webhook handlers, environment variables, and the #93 idempotency work that targeted them all serve no active purpose. Dead payment code is a liability — it confuses every future spec and adds maintenance burden. The codebase has already spent QA cycles on stale workflow findings; leaving the TrueLayer rails in place risks similar waste on future migrations.

## Scope: what changes

1. **Delete TrueLayer library files** — Remove the four core library files (`truelayer.ts`, `truelayer-payments.ts`, `truelayer-vrp.ts`, `truelayer.test.ts`) that implement TrueLayer client configuration, payment creation, VRP mandate management, and webhook signature verification.

2. **Delete TrueLayer API routes** — Remove both Next.js API routes (`/api/truelayer/create-payment` and `/api/truelayer/webhook`) plus their test file (`create-payment/route.test.ts`).

3. **Remove TrueLayer routes from middleware allowlist** — Delete the two TrueLayer route patterns from `PUBLIC_API_ROUTES` in `src/lib/supabase/middleware.ts` (lines 9-10).

4. **Update files that import TrueLayer modules** — Remove dead imports and replace or stub out any references to TrueLayer functions:
   - `src/app/i/[id]/page.tsx` — remove `isPaymentRailsAvailable` import
   - `src/app/i/[id]/pay-button.tsx` — remove fetch to TrueLayer create-payment route
   - `src/app/settings/page.tsx` — remove `getTrueLayerMandateStatus` import
   - `src/app/settings/fee-billing-actions.ts` — remove TrueLayer mandate creation imports
   - `src/app/settings/fee-billing-section.tsx` — remove any TrueLayer-specific UI
   - `src/lib/collect-fees.ts` — remove `chargeMandate` and `getTrueLayerMandatePaymentStatus` imports
   - `src/lib/settle-paid-job.ts` — preserve TrueLayer payment handling for historical records
   - `src/app/api/cron/chase/route.ts` — remove `isPaymentRailsAvailable` import

5. **Remove TrueLayer npm dependency** — Delete `truelayer-signing` from `package.json` dependencies (line 36).

6. **Update documentation** — Replace TrueLayer references with Stripe Pay by Bank in:
   - `README.md` (Payments row in stack table, line 19)
   - `docs/STATUS.md` (Payments row in stack table, line 29)
   - `CLAUDE.md` or `AGENTS.md` if they reference the payment stack

7. **Close or supersede TrueLayer-scoped factory items**:
   - #93 (idempotency fix) — learnings already carried to PAY-3, mark as superseded
   - #97 (if it exists) — re-scope rate limiting to the Stripe route or close

## Explicitly out of scope: what does not change

- **No database changes** — All columns that store TrueLayer payment/mandate data remain untouched:
  - `invoices.truelayer_payment_id` (preserves historical payment reconciliation)
  - `invoices.payment_method` (keeps `'motko_bank'` as a valid historical value)
  - `jobs.payment_provider_ref` (historical TrueLayer payment IDs)
  - `fee_collections.provider_collection_ref` (historical mandate payment IDs)
  - `contractors.fee_mandate_id` (historical VRP mandate IDs)
  - `contractors.fee_mandate_status` (historical mandate states)
  - `contractors.payout_account_holder_name`, `payout_sort_code`, `payout_account_number` (bank details for historical TrueLayer payments)
  - No migration files are created; schema stays as-is

- **No data deletion** — Every row that references a TrueLayer payment, mandate, or fee collection is preserved exactly as-is. Historical jobs paid via TrueLayer must remain renderable.

- **No changes to the Stripe path** — All code added in PAY-2, PAY-3, PAY-4 is untouched. This ticket only removes TrueLayer code.

- **Environment variable removal is declarative** — The spec documents which seven TrueLayer env vars to remove from production environments and CI secrets, but no .env.example changes are needed (they were never added there).

- **Migration files are preserved** — All Supabase migration files that reference TrueLayer in comments or historical DDL remain untouched; they are part of the schema's audit trail.

## Edge cases

1. **In-flight TrueLayer payments or active mandates at cutover**
   - **Check:** Query production for any `invoices.truelayer_payment_id IS NOT NULL AND invoices.status != 'paid'` or `contractors.fee_mandate_status = 'authorizing'`
   - **If nonzero:** This ticket BLOCKS until they are resolved manually (wait for settlement or manually mark as failed)
   - **If zero:** Proceed with deprecation
   - The PAY-1 inventory will have counted them; this check is a pre-merge verification

2. **Historical jobs paid via TrueLayer must remain renderable**
   - After deletion, navigate to a job that was paid via TrueLayer (`payment_method = 'motko_bank'` or `payment_provider_ref` starting with `pi_`)
   - Verify the job page, invoice page, and payment history render correctly
   - `settle-paid-job.ts` must preserve its TrueLayer handling branch for historical records

3. **TrueLayer-scoped acceptance tests fail after deletion**
   - `tests/acceptance/93.test.ts` and `tests/acceptance/152.test.tsx` will fail because they import deleted modules
   - Solution: Delete those test files as part of this ticket (listed under "Removed from tests")

4. **Broken imports in files not listed**
   - Grep for `from "@/lib/truelayer` or `from "truelayer-signing"` after deletion to catch any missed imports
   - If found, remove the import and stub/replace the usage

5. **Middleware tests that assert TrueLayer routes**
   - `tests/acceptance/99.test.ts` may assert `/api/truelayer/` routes are in `PUBLIC_API_ROUTES`
   - Update those assertions to reflect the Stripe routes added in PAY-2/PAY-3 instead

## Risks

1. **Historical payment reconciliation breaks**
   - **Mitigation:** Preserve all database columns (`truelayer_payment_id`, `payment_provider_ref`, etc.) and the TrueLayer handling branch in `settle-paid-job.ts`
   - **Test:** Load a historical job paid via TrueLayer before and after this change; verify identical rendering

2. **Accidentally delete Stripe code**
   - **Mitigation:** Grep for `truelayer` (case-insensitive) to find references; do NOT touch any `stripe` imports or logic
   - **Test:** Full suite must pass, including any PAY-2/PAY-3/PAY-4 acceptance tests for Stripe

3. **Environment variable removal breaks a deployment**
   - **Mitigation:** Only remove TrueLayer env vars after confirming the code that reads them is deleted and deployed
   - **Sequence:** Deploy this PR first, verify production stable, THEN remove the env vars from Vercel/CI

4. **Missing a TrueLayer import**
   - **Mitigation:** Run `npm run build` and `npm run typecheck` after deletion; any missed import becomes a compile error
   - **Test:** Full test suite and type check must pass

5. **Tests become flaky or fail silently**
   - **Mitigation:** Run the full test suite (`npm test`) before and after deletion; compare pass rates
   - Any test that relied on TrueLayer mocking must be explicitly deleted or updated
