# Issue #443: PRICE-3 — Line-item provenance, and unsourced lines as flagged £0/TBC

## Problem

Invented content is indistinguishable from captured content by the time it reaches a customer-facing document. The reviewed quote carried £45 cable, £22.50 back boxes, £15 connectors and £22.50 sundries that were never mentioned aloud. They read exactly like the lines that were, because nothing on a line item records where it came from. That indistinguishability is not only the visible defect — it is what makes PRICE-4 impossible. A reconciliation gate that cannot tell a captured line from an invented one has nothing to reconcile.

## Scope: what changes

1. **Provenance.** Every line item carries a reference to the transcript span it came from, or is explicitly marked unsourced. PRICE-1 already records `transcript_span` on each stated amount; this item carries that reference onto the rendered line and persists it with the quote.

2. **Unsourced lines.** A line the model proposes with no provenance does not get a plausible number. It renders as a flagged £0/TBC line requiring explicit confirmation before the quote can be sent.

3. **Flag mechanism.** The flag mechanism already exists: `quotes.contractor_flags_json` is read by the quote editor, and `src/lib/unpriced-quote-copy.ts` already words the unpriced case. Reuse both rather than inventing a second flag channel.

4. **Provenance checks are conditional.** They apply only when price extraction actually ran — that is, when `statedPrices` is non-empty. An empty array means either a pre-PRICE-1 legacy draft or the guest funnel (which has no transcript extraction at all); in both, materials with estimated costs must keep pricing normally.

## Explicitly out of scope: what does not change

- **The reconciliation gate.** PRICE-4. This item makes the gate possible; it does not add a blocking send check. An unconfirmed £0/TBC line may keep the existing zero-total confirmation behaviour, and nothing more.
- **ZERO_TOTAL_CONFIRM_REQUIRED.** The existing deliberate-zero flow in `src/lib/quote-send-guards.ts` stays as it is. A goodwill callout or a warranty visit is a legitimate £0 quote and refusing to send one creates a support problem that never arrives as a bug report. A flagged unsourced line is a different thing from a deliberate zero and must not collapse into it.
- **Language and double-charge guards.** PRICE-5.
- **Showing provenance to the customer.** Provenance is contractor-facing and internal. Nothing about "we heard you say this" appears on a document a customer sees.
- **Retrofitting provenance to existing quotes.** Rows written before this item have none. They must not break, and they must not be back-filled with a guessed source.
- **The guest quote funnel** (`src/lib/guest/quote.ts` and `tests/regression/guest-draft-quote.test.ts`). It runs no price extraction, so provenance does not apply to it. Its behaviour must be **unchanged** — do not edit that regression test, and do not make its materials unpriced.
- **The signature of `compileDraftToLineItems`.** No new parameter. `src/app/jobs/actions.ts` and `src/lib/guest/quote.ts` are not modified.

## Files

- `src/lib/schemas/job.ts` (modify) — provenance on `lineItemSchema`
- `src/lib/compile-draft.ts` (modify) — attach the reference; suppress or flag the unsourced
- `src/lib/unpriced-quote-copy.ts` (modify) — wording for a flagged unsourced line
- `src/app/jobs/[id]/quote-editor.tsx` (modify) — set contractor-sourced provenance when line is added/edited
- `tests/acceptance/443.test.tsx` (new) — acceptance tests

`lineItemSchema` is persisted in `quotes.line_items_json`, so a new optional field needs no migration. Make it optional, not required: every existing row lacks it, and a required field would fail to parse every quote in the database.

## Edge cases

- **Legacy quote with no provenance on any line.** Renders exactly as it does today. Absent provenance on an old row means "unknown", not "unsourced" — do not flag historical quotes into a review state nobody asked for.
- **A line the contractor typed themselves in the quote editor.** Sourced — by the contractor, not the transcript. This is not an invented line and must never be flagged. Provenance needs a value meaning "entered by the contractor" distinct from both "from the transcript" and "unsourced".
- **A line the contractor edited after it was drafted.** Its amount is now the contractor's, not the transcript's. Treat as contractor-sourced from the edit onwards.
- **An item genuinely mentioned but never priced** ("and we'll want to sort the bonding"). This is the case the £0/TBC line exists for: a flagged line naming the work, never a number.
- **Materials the contractor expects to be itemised.** A trade who wants a cable line can add one; it is then contractor-sourced. What must not happen is the model adding it unbidden.
- **Every line unsourced.** The quote is entirely invented. It should be reviewable, not un-sendable — but this is exactly the state PRICE-4 will block, so do not paper over it here.

## Risks

- **Over-flagging is the failure mode.** A quote where every ordinary materials line arrives flagged is a review screen the contractor will learn to click through, which destroys the value of the flag before PRICE-4 even ships. Suppression versus flagging is the lever: prefer suppressing a line the model invented over rendering it flagged at £0.
- **lineItemSchema is shared** by the quote editor, the PDF payload, the contract's money panel and the fee calculation. An added optional field is safe; a changed or reordered required field is not.

## Derived criteria

1. Every line item drafted from a stated price carries a provenance reference identifying its transcript span.
2. A line item the model proposes with no stated-price source renders as a flagged £0/TBC line when provenance checks are enabled (statedPrices non-empty), never as a plausible number.
3. Given the fixture transcript with labour and two materials priced, a line for sundries/cable/back-boxes/connectors that was never dictated does not appear with a plausible number — it is either suppressed or flagged £0/TBC.
4. A quote row persisted without provenance parses and renders unchanged (the field is optional).
5. A line added by the contractor in the quote editor is marked with contractor-sourced provenance, not flagged as unsourced.
6. A line the contractor edits carries contractor-sourced provenance afterwards, not the original transcript span.
7. The existing ZERO_TOTAL_CONFIRM_REQUIRED behaviour for a deliberate £0 quote is unchanged.
8. An item mentioned in the transcript with no price produces a flagged line naming the work, with no monetary amount.
9. When statedPrices is empty (guest funnel, legacy drafts), materials with estimated costs price normally — provenance checks do not run.
10. The guest quote regression test (`tests/regression/guest-draft-quote.test.ts`) passes unchanged.
