# Issue #160: Improve the empty state on the jobs list

## Problem

When a trade has no jobs yet, the jobs list shows a basic empty state with only a title and description. It doesn't provide a clear path forward or encourage the user to create their first quote.

## Scope

This change updates the empty state that appears when a trade has zero jobs:

1. The empty state will render a heading, one line of body copy, and a primary action button
2. The primary action is a link to `/jobs/new` labelled "Create your first quote"
3. This improved empty state renders only when the trade has exactly zero jobs (`allJobs.length === 0`)
4. When jobs exist but are filtered out (`allJobs.length > 0` but `visible.length === 0`), the existing filter-specific empty states continue to render unchanged (no action button)

## Files

- `src/lib/job-history.ts` — export a new `buildEmptyStateProps` helper function that returns the props to pass to EmptyState based on filter and whether any jobs exist. When `hasAnyJobs` is false, the returned props include an `action` containing a Link to `/jobs/new` with label "Create your first quote" and primary button styling
- `src/app/jobs/page.tsx` — update the empty state logic to call `buildEmptyStateProps({ filter, hasAnyJobs: allJobs.length > 0 })` and spread the returned props to EmptyState
- `src/components/ui/empty-state.tsx` — no changes required (already accepts an optional `action` prop)

## Explicitly out of scope

- Changes to the EmptyState component itself (it already accepts an `action` prop)
- Changes to the filter-specific empty state copy in `EMPTY_COPY`
- Changes to the jobs list rendering when jobs exist
- Changes to the `/jobs/new` route
- Any new styling tokens or dependencies
- Changes to empty states on other pages

## Edge cases

1. **Zero jobs, "all" filter**: Show improved empty state with CTA
2. **Zero jobs, other filters**: Show improved empty state with CTA (the filter is irrelevant when there are no jobs)
3. **Jobs exist, but filter returns empty**: Show existing filter-specific empty state without CTA
4. **Jobs exist, search returns empty**: Show existing "all" filter empty state without CTA

## Risks

None. This is a UI-only change with no data mutations, migrations, or money handling.

## Derived criteria

The human asked for:
- An improved empty state that is "more encouraging" and does a "better job of getting someone started"
- Make it "look nicer too"

The amendment clarified this to mean:
- The empty state should have a heading, body copy, and a single primary action
- The action should link to `/jobs/new` with the label "Create your first quote"
- This should only appear when the trade has zero jobs total
- When jobs exist but are filtered out, the existing empty states remain unchanged
