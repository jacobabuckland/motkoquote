# JOBUI-2: The quote editor gets its own screen

## Problem

The job page (`/jobs/[id]`) currently renders 11 sections in one route, including the entire quote editor component inline (1,393 lines). A contractor scrolls past the pricing form to find the next action. The editor was always meant to be separate — the job page wraps it in `<div id="quote">` and the dashboard links to `#quote`, but these are fragment anchors on a bloated page, not a real route.

## Scope

Create a new route at `/jobs/[id]/quote` that mounts the quote editor. The dashboard links draft quotes directly to this route ("one tap" from dashboard to pricing form). The job page links to it with context-aware text: "Price it up" for drafts, "Review the quote" for sent quotes. The job page itself keeps only the status panel, timeline, and action buttons — no inline editor.

Add a routing helper `jobQuoteHref(jobId)` in `src/lib/job-routes.ts` that returns the quote route path. Both the dashboard and job page use this helper when linking to the quote screen.

**Critical constraint**: The quote editor component file (`src/app/jobs/[id]/quote-editor.tsx`) does NOT move. Three frozen acceptance tests reference it by exact path (tests 207, 443, 148). The new route page imports `QuoteEditor` from its current location.

## Explicitly out of scope

- The quote editor component's internal behavior and props interface do not change.
- The sticky save bar from #717 (if it exists) moves with the editor to the new route, but its implementation is not part of this item.
- Do not pin the current structure of `src/app/jobs/[id]/page.tsx` or `src/app/dashboard/page.tsx` — the editable-gate card (in flight) is changing which quote states render the editor at all.
- Do not change when the editor is shown vs hidden (that's driven by `isEditableQuoteStatus` and is handled by another card).

## Files

- `src/app/jobs/[id]/quote/page.tsx` (new) — the quote editor route, imports QuoteEditor from its current location
- `src/lib/job-routes.ts` (new) — exports `jobQuoteHref(jobId: string): string`
- `src/app/jobs/[id]/page.tsx` (modify) — adds link to quote route using `jobQuoteHref`, likely removes inline QuoteEditor mount (or that logic may change depending on editable-gate)
- `src/app/dashboard/page.tsx` (modify) — draft quotes link to quote route using `jobQuoteHref` instead of job page

## Edge cases

- **Job doesn't exist**: Already handled by existing notFound() logic in page components.
- **Quote not in editable state**: The new route still renders (mounting QuoteEditor with the current status), but the editor's internal guards handle non-editable states.
- **Empty line items**: Already handled by QuoteEditor's internal empty state.
- **Navigation back from quote page**: Standard Next.js back navigation works. No special handling needed.
- **Deep links**: The route `/jobs/[id]/quote` is directly linkable, supporting the existing dashboard anchor pattern.

## Risks

- **Props mismatch**: The new page must pass all required props to QuoteEditor. Missing props would cause runtime errors. The props are listed in quote-editor.tsx lines 51-78, and the current usage in page.tsx lines 1070-1101 shows the pattern.
- **Routing helper not used consistently**: If one link doesn't use `jobQuoteHref`, that link will break when the route changes. All quote links must go through the helper.
- **Frozen test breakage**: Moving the quote-editor.tsx file would break three frozen tests immediately. The component file MUST stay at its current path.

## Derived criteria

1. A new route exists at `/jobs/[id]/quote` that renders the quote editor
2. A helper function `jobQuoteHref(jobId)` exists and returns `/jobs/jobId/quote`
3. The dashboard's draft quote section links to the quote route (not the job page) for "one tap" access
4. The job page links to the quote route (exact link text and conditions determined by implementation)
5. The quote editor component file remains at `src/app/jobs/[id]/quote-editor.tsx` (for frozen tests)
6. The new route page successfully imports and mounts QuoteEditor
7. The job page no longer mounts QuoteEditor inline (the `<div id="quote">` section is either removed or no longer contains the editor)
