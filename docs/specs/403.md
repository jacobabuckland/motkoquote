# PNL-4 — Voice "What's left?" must name what came off

## Problem

The voice interface reports an incorrect "what's left" figure. `getWhatsLeft` currently returns `collected - costsPaid` with no VAT term and no fee term. For a VAT-registered trade, the collected figure is gross, so the spoken number includes money that belongs to HMRC. The sentence "after paying your costs" correctly describes the only deduction that happened, which is precisely what makes it convincing — and wrong.

This is the worse of the two surfaces to be wrong on. A figure on the card sits next to SET ASIDE, and a trade can at least see two numbers and wonder how they relate. A spoken figure arrives alone, with nothing to check it against, and it is gone.

## Scope: what changes

PNL-1 (merged as b473760) already provides the breakdown:
- `SafeToSpend = { collected, costsPaid, motkoFees, vatToSetAside: number | null, total }`
- `MoneyPosition = { owedToYou, youOwe, vat, whatsLeft, safeToSpend, projection }`

This ticket migrates the voice consumer to use `safeToSpend.total` and names which deductions produced it.

### 1. New type and server action change

`src/app/ledger/query-actions.ts`:
- Define `WhatsLeftAnswer` type:
  ```typescript
  export type WhatsLeftAnswer = {
    total: number;              // pence — safeToSpend.total from PNL-1
    costsPaid: number;          // pence
    motkoFees: number;          // pence
    vatToSetAside: number | null;  // pence; null when not VAT-registered
  };
  ```
- Change `getWhatsLeft` signature from `Promise<number>` to `Promise<WhatsLeftAnswer>`
- Return the breakdown from `position.safeToSpend`

Returning a bare number again would rebuild the defect: the caller cannot name what came off if it was not told.

### 2. New formatter function

`src/lib/voice/ledger-query-prompt.ts`:
- Add exported `formatWhatsLeftResponse(answer: WhatsLeftAnswer): string`
- Compose the spoken sentence naming only non-zero deductions:
  - "You've got £99.20 safe to spend — that's after your costs, motko's fees, and £19.84 set aside for VAT."
  - Omit zero terms. With no costs, no fees, and no VAT registration: "You've got £119.04 safe to spend."
  - Never mention VAT if `vatToSetAside` is `null` (not VAT-registered)
  - Handle zero total: "You've got nothing left to spend" (not "£0.00 safe to spend")
  - Handle negative total as shortfall: "You're down £50.00 — that's after..." (use `formatAmount` which already renders negatives as "minus ...")
- Use the existing `formatAmount` function for all figures
- Place beside the existing `formatOwedToYouResponse` (around line 408)
- Must be exported and unit-tested

### 3. Update prompt strings

`src/lib/voice/ledger-query-prompt.ts`:
- Line ~90: tool description — change from "money collected minus costs paid" to describe the safe-to-spend total
- Line ~156: supported query list entry — change "collected minus paid costs" to match the new definition

The model routes on these strings. Leaving them saying "collected minus costs paid" invites it to answer the old question from the new number.

### 4. Update the handler

`src/app/ledger/query/page.tsx` (around line 178-184):
- Call `formatWhatsLeftResponse` from the imported module instead of composing inline
- Remove the inline sentence composition
- The handler receives the structured `WhatsLeftAnswer` and passes it to the formatter

## Edge cases

- **Not VAT-registered** (`vatToSetAside: null`): Never mention VAT at all. A trade who is not VAT-registered must never hear the word VAT.
- **Every deduction zero** (no costs, no fees, not registered): Collapse to bare total with no deductions named
- **Total exactly zero**: "You've got nothing left to spend" (spoken form, not £0.00)
- **Negative total**: Spoken as shortfall: "You're down £50.00 — that's after..." (compose around `formatAmount`, which already handles negatives as "minus ...")
- **Only some deductions present**: Name only the non-zero ones in the sentence

## Risks

- **Money**: This is a money-position report. The figure must be correct.
- **VAT registration boundary**: The most critical assertion is that a non-VAT-registered trade never hears the word VAT (criterion 3). Getting this wrong would cause a trade to set aside money they don't owe.
- **Prompt coordination**: The tool description and supported-query list must match the implementation, or the model routes incorrectly.

---

## Derived criteria

1. The spoken figure is `safeToSpend.total`, not `collected - costs`
2. The sentence names VAT and the VAT amount when `vatToSetAside` is a number
3. The sentence never mentions VAT when `vatToSetAside` is `null` (not registered) — **most important**
4. Zero deductions collapse to the bare total with no "after" clause
5. The sentence mentions motko's fees when `motkoFees > 0`
6. Negative totals speak as shortfalls ("You're down..."), not with a bare minus sign
7. The old sentence phrasing "after paying your costs" is gone
8. `getWhatsLeft().total` equals `getMoneyPosition().safeToSpend.total` (integration test proves the link)
9. The two prompt strings (tool description, supported-query entry) no longer read "collected minus costs paid"
10. The new formatter is exported and unit-tested separately from the handler
