# Issue #403: PNL-4 — Voice "What's left?" must name what came off

## Problem

The voice ledger query "What's left?" currently speaks an overstated figure: `collected - costsPaid` with no VAT or fee deductions. For VAT-registered trades, this includes money that belongs to HMRC. The spoken sentence correctly says "after paying your costs" — which is precisely what makes it misleading, because that's the only deduction that happened.

This is worse than the card surface being wrong: a figure on the card sits next to "SET ASIDE" and a trade can at least see two numbers and wonder how they relate. A spoken figure arrives alone, with nothing to check it against, and then it's gone. A false all-clear spoken aloud gets no second look.

PNL-1 has shipped (merged as b473760), providing the breakdown this ticket consumes: `SafeToSpend = { collected, costsPaid, motkoFees, vatToSetAside, total }` in `src/app/jobs/money-position-actions.ts:14-36`. All values are integer pence. This ticket migrates the voice consumer to use that safe-to-spend total and name what came off it.

## Scope: what changes

### 1. getWhatsLeft returns structured breakdown, not a bare number

`src/app/ledger/query-actions.ts` gains a new type and `getWhatsLeft` returns it:

```typescript
export type WhatsLeftAnswer = {
  total: number;              // pence — safeToSpend.total from PNL-1
  costsPaid: number;          // pence
  motkoFees: number;          // pence
  vatToSetAside: number | null;  // pence; null when not VAT-registered
};
```

The function delegates to PNL-1's `getMoneyPosition` (as it already does for the current `whatsLeft` figure) and extracts the breakdown. Returning a bare number again would rebuild the defect: the caller cannot name what came off if it was not told.

### 2. formatWhatsLeftResponse composes the spoken sentence

A new exported function in `src/lib/voice/ledger-query-prompt.ts`, beside the existing `formatOwedToYouResponse` and `formatYouOweResponse`. The existing formatters are exported and unit-tested; this one must be too.

**Shape:**  
"You've got £99.20 safe to spend — that's after your costs, motko's fees, and £19.84 set aside for VAT."

**Rules:**
- Name the AMOUNT of each non-zero deduction, not just its existence. "after your costs, motko's fees, and £19.84 set aside for VAT" fails criterion 5 below because the fee was mentioned without its figure. Every deduction the sentence names must be named with a number.
- Name only non-zero terms. With no costs, no fees, and no VAT registration it collapses to "You've got £119.04 safe to spend."
- Never mention VAT when not registered (`vatToSetAside: null`). A non-registered trade must never hear the word VAT.
- Use `formatAmount` (already in the file at :286) for every figure — it's built for speech.
- Handle zero specially: "You've got nothing left to spend" rather than "£0.00 safe to spend."
- Negative totals speak as shortfalls. `formatAmount` on negatives already yields "minus …"; compose around it so the sentence reads naturally, not "You've got minus £50 safe to spend."

### 3. Update the voice page to call the formatter

`src/app/ledger/query/page.tsx` currently composes the sentence inline at :179-185. Replace that with a call to the exported `formatWhatsLeftResponse`.

### 4. Update two prompt strings to match the new definition

The model routes on these; leaving them saying "collected minus costs paid" invites it to answer the old question from the new number.

- Line 90 (tool description): "Get what's left: money collected minus costs paid."  
  → Update to describe the safe-to-spend total and the deductions it accounts for.

- Line 156 (supported-query list): "5. What's left? — collected minus paid costs"  
  → Update to match the new definition.

### 5. Update three superseded assertions in tests/acceptance/257.test.ts

**Done in the spec commit**, under the precedent in `areas/motko.md`, 24 Aug: *"a prior ticket's acceptance test may be updated where a later ticket deliberately supersedes the behaviour it pinned, in the first commit of the branch doing the superseding, and never to make a finding go away."*

This is a supersede: the old figure is wrong, which is why this ticket exists. The spec commit is where it must happen, not a later one — `scripts/ci/acceptance-immutability.ts` permits `tests/acceptance/` to be written only in the branch's first commit.

**Three assertions to update:**
- Line 294-310: "calls getMoneyPosition from LED-4 and returns whatsLeft figure"
- Line 313-329: "handles negative whatsLeft (spent more than collected)"
- Line 627-644: "handles zero collected with costs paid"

**What changes:** Only the figure's name and shape. What the tests are about does NOT change: that `getWhatsLeft` delegates to LED-4's `getMoneyPosition` rather than recomputing the figure itself. Keep that claim exactly as it is.

- Assert `result.total` where they currently assert `result`.
- Give each mock a `safeToSpend` field. The `safeToSpend.total` must DIFFER from the mock's `whatsLeft` — carrying one number through both would let a regression to `collected - costsPaid` pass by coincidence, which is the exact defect this ticket removes.

## Edge cases

- **Not VAT-registered:** No VAT mentioned at all. `vatToSetAside: null` → `expect(spoken).not.toMatch(/VAT/i)`. This is the assertion that matters most; a non-registered trade told to set aside VAT will act on it.
- **Every deduction zero:** Collapse to the bare total ("You've got £119.04 safe to spend."). Listing deductions of zero is noise.
- **Total exactly zero:** "You've got nothing left to spend" rather than "£0.00 safe to spend". Speech, not a ledger line.
- **Negative total:** Spoken as a shortfall. Do not clamp. `formatAmount` on negatives already yields "minus …"; compose around it rather than passing a negative straight through into a sentence that reads badly.

## Risks

None. This is a voice response formatter consuming a breakdown that already exists on `main`. No money writes, no migrations, no auth surface.

## Derived criteria

1. `getWhatsLeft` returns a structured `WhatsLeftAnswer` with `{ total, costsPaid, motkoFees, vatToSetAside }`, not a bare number.
2. The spoken figure is the safe-to-spend total from PNL-1's breakdown, not `collected - costsPaid`.
3. The spoken sentence names the AMOUNTS of all non-zero deductions: costs (when non-zero), fees (when non-zero), and VAT (when registered and non-zero).
4. Mentioning "motko's fees" without stating the amount does NOT satisfy criterion 3.
5. When not VAT-registered (`vatToSetAside: null`), the word "VAT" never appears in the spoken sentence.
6. When all deductions are zero, the sentence names no deductions and still states the total.
7. When the total is exactly zero, the sentence says "You've got nothing left to spend."
8. Negative totals speak as "You're down £X" (a shortfall), not "You've got minus £X safe to spend."
9. The old phrasing "after paying your costs" no longer appears — that sentence described the old arithmetic and would only be true of the new number by accident.
10. The two prompt strings at :90 and :156 in `ledger-query-prompt.ts` agree with the new behaviour (no longer say "collected minus costs paid").
11. `formatWhatsLeftResponse` is exported from `ledger-query-prompt.ts` and is unit-tested, matching the pattern of the existing `formatOwedToYouResponse`.
12. `getWhatsLeft` delegates to `getMoneyPosition` from PNL-1 — it does not recompute the figure itself. This is what the three updated assertions in 257.test.ts continue to pin.
