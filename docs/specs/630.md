# MONEY-1: The paid panel shows every settled payment at 1/100 of its value

## Problem

On a settled £500 job, `/jobs/[id]` shows the trade they received -£4.90 instead of £490.10. Three numbers are wrong by 100x, and one is negative when it should never be.

`invoices.amount` is `numeric(10,2)` POUNDS per migration 23. `formatGBP` takes pounds per its module comment. But `src/app/jobs/[id]/page.tsx:532` assigns `paidInvoice?.amount` to a variable named `customerPaidPennies`, then divides by 100 again before formatting (:598, :606). A £500 payment formats as £5.00, and subtracting a £9.90 fee (genuinely in pennies) produces a negative "You receive".

`tests/acceptance/587.test.tsx` has the same unit confusion in reverse: its fixtures use `amount: 50000` for a £500 invoice (pennies), so the page matched the fixture while both were wrong. Correcting the page turns that frozen test red, so the first commit corrects those fixture values under the retirement rule.

## Scope

1. **Correct the unit handling in `src/app/jobs/[id]/page.tsx`:**
   - Rename `customerPaidPennies` to reflect that `invoices.amount` is pounds
   - Remove the `/ 100` divisions on lines that format customer paid and you-receive amounts
   - Convert `feeDeductedPennies` to pounds when computing the difference
   - The refund path (line 586) already converts correctly — leave it unchanged

2. **Add `src/checks/money-units.check.test.ts`:**
   - Standing check (not an acceptance test) that reads source by design
   - No source file assigns `invoices.amount` or `quotes.total` to a variable name ending `Pennies` without multiplying by 100
   - Model on `src/checks/money-source.check.test.ts`

3. **First commit corrects unit-wrong fixture values in `tests/acceptance/587.test.tsx`:**
   - All `amount:` values in invoice fixtures are in pennies (e.g. `amount: 50000` for £500)
   - Column stores pounds, so these should be `500`, `1200`, `600`, etc.
   - Commit message names each corrected value and why (unit mismatch, superseded by MONEY-1)
   - Only the fixture literals change — every assertion about fee states keeps running

## Explicitly out of scope

- Renaming the database columns themselves
- The refund path (`refund-button.tsx`, `refund-actions.ts`), which already reads amounts from Stripe in pennies and converts correctly

## Files

- `src/app/jobs/[id]/page.tsx` (modify) — fix the unit conversion
- `src/checks/money-units.check.test.ts` (new) — standing check for unit discipline
- `tests/acceptance/630.test.tsx` (new) — the two behavioural criteria below
- `tests/acceptance/587.test.tsx` (modify, first commit only) — correct unit-wrong fixture values

## Edge cases

- A waived fee: the full amount is shown in "You receive", unreduced
- Legacy jobs with `fee_amount_pennies` or `fee_status` null: already handled by existing guards at :543-547
- Refund eligibility: `settledAmountPennies` must convert from pounds at the call site (:586), which it already does

## Risks

**Money display.** This is the one panel that tells a trade what they earned. Showing 1/100th of the value (or a negative number) is a trust-destroying defect, and the fix touches arithmetic between invoice amounts and fees. The acceptance tests cover:
- A settled job with fee collected
- A waived fee showing the full amount received

## Acceptance criteria

Both criteria are rendered-and-observed. Neither reads source.

1. **A settled £500 job with a £9.90 fee shows correct amounts:**
   - "Customer paid: £500.00"
   - Fee line shows £9.90
   - "You receive: £490.10" — never negative

2. **A waived fee shows the full amount received, unreduced:**
   - If fee was waived, "You receive" equals "Customer paid"
   - No negative amounts

The unit-discipline rule across the codebase is enforced by `src/checks/money-units.check.test.ts`, which is a standing check and runs on every branch — not an acceptance criterion for this item.
