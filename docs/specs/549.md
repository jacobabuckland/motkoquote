# PFIX-7: Fixed-price dead end (remaining)

## Problem

A fixed-price quote with any stated price can become unsendable with no route out through the interface. When `stated_prices` is non-empty, provenance checking is enabled for all lines. The fixed-mode works line is built by `buildFixedModeLineItems` with no provenance at all. The reconciliation gate then reports "Unsourced line" and refuses the send, leaving the contractor with a quote they cannot send. The editor's `confirmContractorSourced` retry can mark lines as contractor-sourced, but that incorrectly labels a system-generated line as contractor-added. Adding a new line to a fixed-price quote breaks the fixed-amount reconciliation check. There is no way out.

## Scope: what changes

1. Extend `lineItemProvenanceSchema` to add a third source type: `"system-generated"` (or similar), for lines created by pricing-mode transformations rather than by the model or the contractor
2. `buildFixedModeLineItems` attaches this new provenance type to the works line it constructs
3. `reconcileStatedPrice` in `stated-price-guard.ts` accepts system-generated lines as validly sourced and does not fail them
4. The send guard recognizes system-generated provenance as legitimate and allows the quote through

This is a targeted fix: only the fixed-mode works line receives the new provenance type. All other lines continue to use `"transcript"` or `"contractor"` as they do today.

## Explicitly out of scope

- Other pricing-mode transformations (the day-rate mode uses the calculated breakdown unchanged)
- The three flag-hygiene defects originally part of PFIX-7, now split to PFIX-8
- Any change to how `applyPricingMode` collapses lines (the collapse itself is correct; only the missing provenance is wrong)
- Changes to the editor UI beyond what naturally follows from the provenance fix

## Files

- `src/lib/schemas/job.ts` (modify) — extend `lineItemProvenanceSchema` to add the third source
- `src/lib/pricing-mode.ts` (modify) — `buildFixedModeLineItems` attaches provenance to the works line
- `src/lib/stated-price-guard.ts` (modify) — `reconcileStatedPrice` accepts system-generated provenance
- `src/app/jobs/actions.ts` (modify) — callers of `buildFixedModeLineItems` that might need to pass provenance through (e.g., `setQuotePricingMode`)
- `tests/acceptance/549.test.ts` (new) — the reproduction case and success criteria

## Edge cases

- A fixed-price quote with **multiple** stated prices. The works line still has one amount (the `fixed_amount`), and that amount may not match any individual stated price. This is legitimate: the contractor stated several component prices and then named a total. The system-generated provenance should allow the line through.
- A switch **into** fixed mode after lines were already drafted. The provisional items carry their original provenance; only the new works line gets system-generated.
- A switch **out of** fixed mode. The calculated breakdown returns, each line keeping its original provenance. The system-generated works line is discarded, so it never reaches the send gate.
- A manual job with fixed pricing. There is no transcript and no `stated_prices`, so provenance checking never turns on. The works line has system-generated provenance but the check never runs. Harmless.
- The works line amount is edited by the contractor in the editor. The provenance stays system-generated: the *line* was created by code, even if the contractor later changed its figure. An edited amount does not retroactively make it contractor-sourced.

## Risks

- **Schema change.** `lineItemProvenanceSchema` is frozen on every quote row in production as part of `line_items_json`. Adding a third enum value is backward-compatible (existing rows stay valid), but rollback would require a migration to remove any system-generated provenance that landed.
- **Send-gate interaction.** If the logic accepting system-generated lines has a bug, quotes could be sent with incorrect provenance or with missing amounts. The acceptance tests exercise the exact failure scenario to guard this.
- **Not money, but adjacent.** This does not change what a customer is charged, but it gates whether a quote can be sent at all, which blocks revenue. Treated as a P1 pricing-path defect.

## Derived criteria

1. A fixed-price quote carrying one or more stated prices has a collapsed works line with no provenance from the transcript
2. That works line is given a third provenance source type meaning "created by the pricing-mode transformation"
3. The reconciliation check accepts this provenance type and does not report "Unsourced line"
4. The quote can be sent successfully with no contractor intervention beyond setting the fixed price
5. The test reproduces the exact production failure: fixed mode, one stated price, the collapsed works line, and verifies the send succeeds
6. Switching out of fixed mode and back in again keeps the system-generated provenance on the works line each time
7. A manual fixed-price job (no transcript, no stated prices) with the system-generated works line does not break anything, because provenance checks never turn on
