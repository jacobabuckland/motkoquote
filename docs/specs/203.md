# Issue #203: Lock interface orientation to portrait on iPhone

Auditing branch: `factory/203` @ `f3cec19`

## Problem

The iOS app's Info.plist currently permits landscape orientations (LandscapeLeft and LandscapeRight) on iPhone. The product is a focused voice and quoting flow with layouts built for portrait. Landscape is unintended and causes layout jank, particularly on the voice intake screen where the orb and transcript assume vertical space. A tradesperson holding a phone sideways in a van will trigger landscape rotation accidentally, breaking the interface.

## Scope: what changes

- `ios/App/App/Info.plist`: remove `UIInterfaceOrientationLandscapeLeft` and `UIInterfaceOrientationLandscapeRight` from the `UISupportedInterfaceOrientations` array (the iPhone-specific key)
- The array will contain only `UIInterfaceOrientationPortrait`

## Explicitly out of scope

- **iPad orientations remain unchanged.** The app targets both iPhone (device family 1) and iPad (device family 2). `UISupportedInterfaceOrientations~ipad` must retain all four orientations (Portrait, PortraitUpsideDown, LandscapeLeft, LandscapeRight). iPad users legitimately expect landscape support, and removing it is a separate product decision outside this item's scope.
- No layout changes to accommodate or improve landscape rendering
- No per-screen orientation overrides via view controller code
- No changes to safe-area handling
- No changes to splash screen orientation configuration

## Files

- `ios/App/App/Info.plist` — the sole file touched

## Edge cases

- **Device rotation lock already engaged by user:** unaffected. The OS respects the user's rotation lock setting regardless of app preferences.
- **Accessibility settings that force orientation:** the OS handles these and they override app preferences. No handling required.
- **User-visible change:** yes. After this change, the interface no longer rotates when an iPhone is held in landscape. This is the intended behaviour.
- **Video or media playback requiring landscape:** none exists in the product. If any is found during implementation, stop and report rather than adding an exception.

## Failure modes

None specific to this change. If Info.plist becomes malformed (invalid XML), the iOS build will fail at compile time with a clear parse error, not at runtime.

## Empty states

Not applicable. Orientation support is a static configuration declared at build time.

## Risks

None. This is a purely declarative change to a build-time configuration file. It does not touch user data, money, migrations, or runtime code paths. The worst case is accidental removal of iPad landscape support (explicitly guarded against in acceptance tests) or syntax error in the plist (caught at build time).

## Derived criteria

Based on the issue body, I understand the Engineer will:

1. Edit `ios/App/App/Info.plist` to remove the two landscape orientation values from `UISupportedInterfaceOrientations` (the iPhone key)
2. Ensure `UISupportedInterfaceOrientations` contains only `UIInterfaceOrientationPortrait`
3. Leave `UISupportedInterfaceOrientations~ipad` completely unchanged (all four orientations remain)
4. Confirm that rotating an iPhone to landscape no longer rotates the interface
5. Verify no layout regression in portrait mode by visually checking the voice intake screen, dashboard, and quote editor
6. Confirm that iPad landscape support is unaffected (if testing on an iPad build)
