# Issue #207: Add and configure keyboard and status bar plugins

## Problem

Neither `@capacitor/keyboard` nor `@capacitor/status-bar` is installed. Input focus, scroll-into-view, keyboard overlap and the input accessory bar are left to WKWebView defaults, which routinely hide focused inputs behind the keyboard on forms. Status bar text style is not controlled, so the time and battery indicators can render in a colour that disappears against the brand green background (#004225).

## Scope

1. **Install `@capacitor/keyboard`** as a dependency
2. **Configure keyboard plugin** in `capacitor.config.ts` to:
   - Enable automatic scroll-to-input behavior so focused inputs appear above the keyboard
   - Explicitly configure the input accessory bar (toolbar above keyboard) behavior
   - Prevent layout shift in fixed-position elements when keyboard appears/hides
3. **Install `@capacitor/status-bar`** as a dependency
4. **Configure status bar style** so text meets contrast requirements against the brand green (#004225)
5. **Initialize the status bar** on app mount in the native app initialization component
6. **Update the Capacitor test helper** at `tests/helpers/capacitor.ts` to include mocks for both new plugins
7. **Verify forms work correctly** - specifically quote editor, settings form, and login form

## Explicitly out of scope

- Do not change any form layout or field ordering
- Do not add form validation or change validation behavior
- Do not change safe-area handling (already correct)
- Do not change the splash screen configuration or appearance
- Do not add keyboard shortcuts or external keyboard handling
- Do not modify the keyboard appearance (light/dark mode of the keyboard itself)

## Files

The Engineer will touch:

- `package.json` — add both plugins to dependencies
- `capacitor.config.ts` — add plugin configuration for Keyboard and StatusBar
- `src/components/native-app-init.tsx` — initialize status bar style on mount (may need to create if doesn't exist, or add to existing native initialization)
- `tests/helpers/capacitor.ts` — extend mocks to include Keyboard and StatusBar plugins
- Possibly `src/app/layout.tsx` or similar if native initialization needs to be invoked from the root layout

## Edge cases

1. **External hardware keyboard attached**: The software keyboard does not appear, so no scroll adjustment should be applied. The code must not assume focus implies a visible keyboard.

2. **Input focused near the bottom of a long scrolling page**: Scroll far enough that both the input field and its associated label are visible above the keyboard, not just the input itself.

3. **Keyboard dismissed by swipe-down gesture** (not by blur/unfocus): Layout must restore correctly without leaving offset scroll position or shifted fixed elements.

4. **Status bar during splash screen**: The splash screen sets its own appearance. Ensure the transition from splash to app doesn't flash the wrong status bar color.

5. **Dark mode**: If the OS is set to dark appearance, the status bar style must be explicitly configured for both light and dark modes. Do not rely on inheritance or automatic switching.

6. **Notched device (e.g., iPhone 12+)** vs **non-notched device (e.g., iPhone 8)**: Status bar height differs. The style must work on both profiles without text becoming invisible.

7. **Input accessory bar**: The toolbar that appears above the keyboard (with Prev/Next/Done buttons) — explicitly choose whether to show, hide, or customize it. Do not leave it at the WKWebView default. Document the choice.

8. **Rotation**: If the device rotates while an input is focused and the keyboard is visible, the scroll adjustment must remain correct in the new orientation.

9. **Multiple rapid focus changes**: If the user tabs through fields quickly, keyboard show/hide events may fire rapidly. Ensure scroll adjustments don't stack or leave the form in a broken scroll state.

10. **VoiceOver enabled**: Keyboard configuration must not interfere with VoiceOver's scroll-to-focused-element behavior.

## Risks

- **Fixed-position elements shifting**: The keyboard plugin can cause layout shifts if not configured correctly. Specifically, the bottom navigation or any fixed header must not jump when the keyboard appears.
  - **Mitigation**: Configure the keyboard to resize the WebView (or use appropriate scroll mode) rather than overlaying, and verify fixed elements in tests.

- **Status bar invisible on green background**: If the status bar style is not set to light content, white text will disappear against #004225.
  - **Mitigation**: Explicitly set status bar style to light content and verify on both light and dark OS modes.

- **Input accessory bar unexpected behavior**: If left to default, the input accessory bar may block part of the form or interfere with custom controls.
  - **Mitigation**: Explicitly configure the accessory bar and document the chosen behavior in the PR.

- **Breaking change from Capacitor mock helper**: Extending the mock to include Keyboard and StatusBar changes the shared test helper, which could break existing tests that rely on its shape.
  - **Mitigation**: Follow the existing pattern exactly (add mocks for the two new plugins without changing the helper's API), and verify no existing tests fail.

## Derived criteria

What the spec is asking for:

1. **Plugins installed**: Both `@capacitor/keyboard` and `@capacitor/status-bar` appear in `package.json` dependencies
2. **Keyboard configuration present**: `capacitor.config.ts` includes a `Keyboard` plugin section with explicit settings for scroll behavior and input accessory bar
3. **Status bar configuration present**: `capacitor.config.ts` includes a `StatusBar` plugin section (if static config is needed), or status bar is initialized programmatically in native app init
4. **Status bar style initialized**: On app mount (in native app init component), status bar style is set to ensure white text on the brand green background
5. **Mocks extended**: `tests/helpers/capacitor.ts` exports mocks for Keyboard and StatusBar alongside the existing five plugins
6. **Forms verified**: Quote editor, settings form, and login form all have inputs that can be focused and the keyboard scroll behavior is confirmed to work (via tests or manual verification checklist in PR)
7. **Fixed elements stable**: Header and any bottom-anchored controls do not shift when keyboard appears (verified via test or explicit PR note)
8. **Input accessory bar choice documented**: PR states whether the input accessory bar is shown, hidden, or customized
9. **Both device profiles verified**: Status bar legibility is confirmed on a notched device (e.g., iPhone 12 simulator) and a non-notched device (e.g., iPhone 8 simulator)
10. **No splash flash**: Status bar transition from splash to app is smooth (explicit verification in PR)
11. **Dark mode explicit**: Status bar style is explicitly configured for both light and dark OS appearances, not left to inherit
