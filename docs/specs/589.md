# STAGE-1: Detect over-ceiling quotes at quote time

## Problem

Pay by Bank refuses transactions above £10,000. When this is discovered at payment-link generation (invoice creation) or worse at payment failure, the trade finds out in front of a customer who has already agreed the price. This creates an awkward situation where the contractor must explain payment limitations after the quote has been accepted, turning a capability constraint into a perceived problem.

## Scope: what changes

Add a pre-send check in `sendQuote` that detects when a quote total exceeds the Pay by Bank limit (£10,000) and surfaces a confirmation dialog to the contractor before the quote is sent. The check reads the existing `PAY_BY_BANK_LIMIT_PENNIES` constant from `src/app/i/[id]/pay-panel.ts` — no second constant, so the limit moves in one place when Stripe grants an increase.

The confirmation explains that quotes above £10,000 will use the staged payment path (or transfer_only fallback until STAGE-2 exists), framing it as a capability rather than an apology. The contractor acknowledges this once and the quote sends normally.

Pattern follows the existing `ZERO_TOTAL_CONFIRM_REQUIRED` and `NARRATIVE_TOTAL_CONFIRM_REQUIRED` guards: the server throws a sentinel, the editor catches it and shows a confirmation dialog, and the re-send carries a `confirmOverCeiling` flag that allows it through.

## Explicitly out of scope

- Building the staged schedule or staged payment UI (STAGE-2)
- Changing payment panel behavior (already handles over-ceiling invoices correctly)
- Blocking the send (this is a confirmation, not a gate)
- Altering the quote or invoice amount

## Files

- src/app/i/[id]/pay-panel.ts (modify) — export `PAY_BY_BANK_LIMIT_PENNIES` so it can be imported by guards
- src/lib/quote-send-guards.ts (modify) — add `OVER_CEILING_CONFIRM_REQUIRED` sentinel and `quoteExceedsCeiling` check function that imports the constant
- src/app/jobs/actions.ts (modify) — add check in `sendQuote` against the limit, throw sentinel if over and not confirmed
- src/app/jobs/[id]/quote-editor.tsx (modify) — catch sentinel, show confirmation dialog with staged-payment copy, add `confirmOverCeiling` flag to confirmed state

## Edge cases

- **Exactly £10,000**: Does not trigger confirmation (limit is `>` not `>=`, matching pay-panel.ts line 98)
- **Quote edited after confirmation**: If the contractor confirms at £14,000 then edits down to £8,000, no confirmation is needed on re-send (the check runs fresh every time)
- **Multiple confirmations**: A quote can trigger both over-ceiling AND zero-total or narrative-mismatch confirmations in sequence — the confirmation state accumulates exactly like the existing guards do (see quote-editor.tsx:436)
- **VAT-registered quote**: Check runs against `quotes.total` (VAT-inclusive), matching what the customer will be asked to pay, not the net subtotal

## Risks

- **Import cycle**: `quote-send-guards.ts` importing from `pay-panel.ts` must not create a cycle. Current imports flow client → guards, server → guards, server → pay-panel, with no guards → pay-panel or pay-panel → guards edges, so adding guards → pay-panel (the constant only, not the logic) is safe.
- **Production constant divergence**: If `PAY_BY_BANK_LIMIT_PENNIES` is copied rather than imported, the two will drift when Stripe raises the limit. The spec forbids this explicitly; QA must verify the import exists.

## Derived criteria

- A £14,000 quote shows a confirmation dialog explaining staged payment before the trade sends anything
- A £8,000 quote sends without any new friction — no confirmation, no delay, behavior unchanged
- The check reads `PAY_BY_BANK_LIMIT_PENNIES` from `src/app/i/[id]/pay-panel.ts` by import, not a second constant
- After the contractor confirms, the quote sends successfully and the customer receives it
- The confirmation dialog frames staged payment as a capability (how large jobs are handled) not an apology
- A quote exactly at £10,000 sends without confirmation (matches pay-panel.ts logic)
- No raw Stripe error about the limit ever reaches the customer
