# HARN-3: A golden render for the Statement of Work

## Problem

The quote and contract PDFs each have a golden render test that produces a real PDF in a Node test, compares it against a committed baseline, and catches rendering defects before they ship. The Statement of Work has neither test nor baseline, leaving it vulnerable to the class of defect that garbled timeline cells, orphaned sections, and duplicated lists in August.

## Scope: what changes

- Add `src/lib/pdf/render-sow.ts` exporting `renderSowPdf(jobId)`, following the pattern `render-quote.ts` and `render-contract.ts` already establish. The function loads the job row with its SOW and related contractor/customer data via the admin client, then renders the SOW PDF to a Buffer.

- Add `tests/regression/sow-pdf-golden.test.ts` that:
  - Stubs the admin client to serve fixture job rows
  - Renders each fixture through `renderSowPdf`
  - Normalises the output with the existing `normalizePdfBytes` helper
  - Compares a SHA-256 hash of the normalised bytes against a committed golden
  - Documents the re-baseline procedure matching the existing quote/contract convention

- The test covers two fixture cases:
  1. **full-featured**: A SOW with assumptions (including a provisional sum), customer-supplied materials, and all optional sections populated
  2. **no-assumptions**: A SOW with no assumptions, proving the section is absent rather than present-and-empty

- The committed golden is `tests/regression/sow-pdf-golden.json`, a `{ [key: string]: string }` map of fixture key to hash.

## Explicitly out of scope

- Changing the SOW PDF renderer (`src/lib/pdf/sow-pdf.tsx`) or its output. If the golden reveals a rendering defect, record it as a finding but do not fix it in this item.
- The quote and contract golden tests, which already exist and pass.
- Modifying the SOW API route (`src/app/api/jobs/[id]/sow-pdf/route.ts`) beyond what is needed to extract the render logic into the new `render-sow.ts` module.

## Files

- `src/lib/pdf/render-sow.ts` (new) — the `renderSowPdf` function and its job-row type
- `src/app/api/jobs/[id]/sow-pdf/route.ts` (modify) — refactor to use the new `renderSowPdf` function rather than duplicating the render logic
- `tests/regression/sow-pdf-golden.test.ts` (new) — the golden render test
- `tests/regression/sow-pdf-golden.json` (new) — the committed golden hashes, created by running the test with `UPDATE_SOW_PDF_GOLDEN=1`

## Edge cases

- **A SOW with no assumptions**: the Assumptions section must be absent, not present-and-empty. Covered by the `no-assumptions` fixture.
- **Very long scope lists**: pagination differences must be caught, not normalised away. The `normalizePdfBytes` helper already preserves text content, so a scope list that orphans across pages will fail the hash comparison.
- **Missing job row**: `renderSowPdf` returns `null` when the job row is absent, matching the pattern the quote/contract renderers establish.
- **Job with no `sow_json`**: `renderSowPdf` returns `null`, since there is no document to render.

## Risks

None. This is purely additive: a new test file, a new render function, and refactoring an existing route to use it. The route's behaviour is unchanged, and the golden test only catches rendering regressions — it does not alter what is rendered.

## Derived criteria

1. A new `renderSowPdf(jobId)` function exists in `src/lib/pdf/render-sow.ts`
2. The function loads the job row with SOW and contractor/customer relations via the admin client
3. The function returns a Buffer when the job row exists and has a `sow_json`
4. The function returns `null` when the job row is absent or has no `sow_json`
5. A golden render test exists at `tests/regression/sow-pdf-golden.test.ts`
6. The test stubs the admin client to serve fixture data
7. The test renders each fixture through `renderSowPdf`
8. The test normalises the output with `normalizePdfBytes`
9. The test compares a SHA-256 hash of the normalised bytes against a committed golden
10. The test covers a SOW with assumptions (including a provisional sum), customer-supplied materials, and all sections populated
11. The test covers a SOW with no assumptions, proving the section is absent
12. The test completes in under 5 seconds
13. The test documents the re-baseline procedure (`UPDATE_SOW_PDF_GOLDEN=1 npx vitest run tests/regression/sow-pdf-golden.test.ts`)
14. The SOW API route is refactored to use the new `renderSowPdf` function
15. A change that alters the rendered SOW fails the golden test
