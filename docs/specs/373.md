# VOICE-3 — A call that ends without customer name or contact must be visible

## Problem

Customer details (`customer_name`, `site_address`, `customer_phone`, `customer_email`) exist in the SoW schema and can be captured by the `update_sow` tool during voice intake, but nothing deterministically checks whether they were actually filled in. A call can end with no customer name and no way to reach them, yet present a complete-looking quote. The contractor then has to retype details they already said out loud, defeating the purpose of voice intake.

The gap is enforced only by prose in a 7,680-character instruction string sent to the model alongside thousands of tokens of tool JSON — instruction dilution, not a check.

## Scope: what changes

Make the gap visible using the existing `wrap_incomplete` / `unasked_required` machinery that already flags missing pricing slots. No questions are added to any call.

1. **New function `getMissingCustomerDetails`** in `src/lib/schemas/sow.ts`, analogous to `getUnansweredChecklistQuestions`, that returns which customer details are missing:
   - Missing means: no `customer_name`, OR neither `customer_phone` nor `customer_email`
   - One contact channel is enough (matching the quote editor's existing validation at `src/app/jobs/[id]/quote-editor.tsx:274`)
   - `site_address` is checked separately and reported but never sets a blocking state

2. **New export `CUSTOMER_DETAIL_LABELS`** in `src/lib/schemas/sow.ts`, analogous to `CHECKLIST_SLOT_LABELS`, with short sentence-fragment labels for each customer detail slot (e.g., "the customer's name", "contact details", "the site address")

3. **Update both `wrap_incomplete` / `unasked_required` write sites** in `src/app/jobs/actions.ts`:
   - Line ~382 (the first completeSow path)
   - Line ~581 (the voice_session_completed telemetry)
   - Both now call `getMissingCustomerDetails(sowState)` and merge the result into `unasked_required` alongside the checklist slots
   - If either list is non-empty, `wrap_incomplete` is true

4. **Job page banner** at `src/app/jobs/[id]/page.tsx:597` already renders `wrap_incomplete` and `unasked_required` using `CHECKLIST_SLOT_LABELS`. It now also uses `CUSTOMER_DETAIL_LABELS` to render missing customer details.

5. **Telemetry flag** `missing_customer_details` added to the `voice_session_completed` event (line ~568), so "how often does this actually happen?" is answerable from data.

## Explicitly out of scope

- **No questions are added to any call.** `REQUIRED_CHECKLIST_QUESTIONS` is unchanged. Making customer details a fourth deterministic slot group (option b from the original card) is deferred — decide it on the rate this ticket exposes.
- Prompt rewording. `customerLine` in the intake prompt is already explicit; adding prose to a 7.7k-character string is not a fix.
- Relying solely on the editor's existing block (option c) — still viable, deferred to the same decision point.
- Pinning the model (VOICE-4).
- The greeting loop (VOICE-1, shipped).

## Files

- `src/lib/schemas/sow.ts` (modify) — add `getMissingCustomerDetails` function and `CUSTOMER_DETAIL_LABELS` export
- `src/app/jobs/actions.ts` (modify) — update both `wrap_incomplete` / `unasked_required` write sites to include missing customer details
- `src/app/jobs/[id]/page.tsx` (modify) — import and use `CUSTOMER_DETAIL_LABELS` alongside `CHECKLIST_SLOT_LABELS` in the existing banner
- `tests/acceptance/373.test.tsx` (new) — acceptance tests

## Edge cases

- **A contractor who does not know the address:** Legitimate. `site_address` is reported but never sets `wrap_incomplete` to true. It flows to the assumptions layer.
- **A guest intake** (no account, no customer row) needs the details on the rendered quote just like the account path. Identical treatment — both call the same function.
- **Proper nouns** are already covered by `properNounLine` with read-back. No second confirmation pass is added.
- **A call that never reached wrap at all:** The flag describes a completed SoW only. A call abandoned mid-way is a different signal (not this ticket).
- **One contact channel is enough:** A SoW with `customer_name` and either `customer_phone` OR `customer_email` (but not both) does NOT set `wrap_incomplete`. The quote editor blocks on exactly this condition (name + at least one channel), so this must not be stricter.

## Risks

- **Telemetry schema change:** Adding `missing_customer_details` to `voice_session_completed` is a backwards-compatible addition (new optional field). Existing events are unaffected.
- **No migration required:** All changes are application-level logic; the database schema is unchanged.
- **The guest path and account path must behave identically**, per the pricing-slot invariant at `src/lib/prompts/job-intake-prompt.ts:5-10`. The same check function is called in both flows.

## Derived criteria

I understand the human is asking for:

1. A way to know when a voice call ended without capturing the customer's name or contact details
2. Using the existing `wrap_incomplete` / `unasked_required` pattern that already flags missing pricing slots
3. Missing customer details means: no name, OR no way to reach them (neither phone nor email)
4. One contact channel (phone OR email) is enough — matching the quote editor's existing validation
5. Site address is reported separately and never blocks
6. No new questions are added to any call (REQUIRED_CHECKLIST_QUESTIONS unchanged)
7. The job page's existing banner renders the gap for contractors to see and fix
8. Telemetry tracks the rate so the decision between options (b) and (c) from the original card can be data-driven
9. Guest and account paths behave identically
