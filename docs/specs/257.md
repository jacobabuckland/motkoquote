# LED-6: Voice query over the ledger (bounded question set)

## Problem

A tradesperson will not open a P&L screen with the engine running, but will ask a question by voice. This implements voice as **interrogation** rather than input — the direction that makes the ledger a daily habit rather than a quarterly report. A bounded query set covering the five questions that matter (what am I owed, what do I owe, job P&L, what's left) lets the contractor query their financials hands-free.

## Scope: what changes

**Voice query handler**
- A new server-side handler (API route or server action) that accepts a natural language query and returns a spoken response
- Query classification: maps the user's natural language input to one of the 5 bounded queries, or rejects as out-of-set
- Response generation: the LLM receives **pre-computed values** from the ledger and renders them into natural British speech

**Ledger projections called by voice queries**
Each of the 5 bounded queries calls an existing or new computation function:
1. **What am I owed?** → Outstanding invoices total (already exists: `openInvoices.reduce((sum, invoice) => sum + invoice.amount, 0)` from dashboard)
2. **What do I owe?** → Unpaid costs by counterparty (new computation)
3. **What do I owe [counterparty]?** → Unpaid costs filtered to specific counterparty (new computation)
4. **What did [job] make?** → Job P&L: revenue minus costs for a specific job (new computation)
5. **What's left?** → Collected revenue minus paid costs (new computation, uses same definition as on-screen projection)

**Voice UI entry point**
- A new UI component (button, voice button, or section) on the dashboard or a dedicated ledger screen that activates voice query mode
- Microphone access (reuses existing patterns from job intake: `src/lib/mic.ts`, `src/lib/voice-gate.ts`)
- Visual feedback during query (listening, thinking, speaking states)
- Spoken response via text-to-speech

**Amount formatting**
- A new utility function that converts amounts to natural British speech forms
- £1,240 → "twelve hundred and forty pounds" or "one thousand two hundred and forty pounds" (choose one consistently)
- Handles edge cases: zero, negative amounts, pence

**Privacy controls**
- Implements the recommendation: amounts and counterparty names yes, customer names only when the contractor named the customer in the question
- May include a UI toggle for a "quieter mode" if privacy decision requires it

## Explicitly out of scope

- Trend or comparison questions ("how does this month compare") — accounting product, not this
- Actions by voice (marking paid, editing) — query only
- General natural-language reporting beyond the 5 bounded queries
- Costs/expenses data model changes — assumes LED-1 through LED-4 already provide the necessary schema

## Edge cases

**Empty states:**
- No outstanding invoices → "You're all square. Nothing owed to you right now."
- No unpaid costs → "You don't owe anything at the moment."
- Job reference doesn't exist → "I can't find that job. Could you try the customer name or job number?"
- Job with no costs → Job P&L returns revenue only

**Query ambiguity:**
- Multiple jobs for same customer → Ask for clarification or return the most recent
- Counterparty name not found → "I can't find [counterparty]. Do you want to hear what you owe across all suppliers?"
- Partial matches → Use fuzzy matching but confirm if confidence is low

**Out-of-set queries:**
- Query doesn't map to the 5 bounded queries → "I can't answer that yet. I can tell you: what you're owed, what you owe, what a job made, or what's left after costs. What would you like to know?"
- Lists the 5 available queries clearly

**Error states:**
- Microphone permission denied → Fall back to existing mic permission screens from job intake
- Network failure during query → "Something went wrong. Try asking again."
- Database query timeout → Same as network failure
- TTS failure → Show text response as fallback

**Formatting edge cases:**
- £0.00 → "zero" or "nothing"
- Negative amounts (refund scenarios) → "You're owed minus £X" is wrong; handle as "You owe £X" or special-case
- Large amounts → "£25,340" → "twenty-five thousand, three hundred and forty pounds"
- Pence → £12.50 → "twelve pounds fifty" (not "and fifty pence")

## Risks

**Money spoken aloud:**
- Amounts are spoken potentially with customers or others present
- Privacy recommendation implemented: amounts and counterparty names yes, customer names only when contractor named them
- A "quiet mode" toggle could suppress amounts and just say "you have outstanding invoices" — decide before build

**Arithmetic by LLM:**
- The core invariant: code computes every number, LLM only renders
- Tests must assert that the voice handler calls the same computation functions as the screen projections
- No arithmetic in the prompt; the LLM receives final figures only

**Divergence from screen projections:**
- Voice-reported figures must match what's shown on screen
- Tests assert both paths call identical computation functions
- If projections change, voice queries automatically stay in sync

**Missing dependencies (LED-1 through LED-4):**
- The issue says "Requires LED-1 through LED-4 live, populated, and trusted"
- If costs data model doesn't exist yet, this item blocks on those predecessors
- Spec assumes LED-1–4 provide: costs table, job-to-cost associations, paid/unpaid status

## Derived criteria

What the human is asking for:

1. A voice interface that accepts one of 5 bounded natural-language queries about the ledger
2. Each query returns figures **identical** to corresponding on-screen projections, tested by asserting both call the same computation
3. Out-of-set questions produce a clear rejection message listing the 5 available queries
4. Code computes every amount; the LLM receives pre-computed values and only renders them into speech
5. Amounts are spoken in natural British forms (£1,240 as "twelve hundred and forty pounds" or similar), chosen consistently
6. Privacy: amounts and counterparty names are spoken; customer names only when the contractor named the customer in their question
7. No arithmetic by the model, no trend/comparison questions, no actions by voice
8. The 5 queries are:
   - What am I owed? (outstanding invoices)
   - What do I owe? (unpaid costs by counterparty)
   - What do I owe [counterparty]?
   - What did [job] make? (job P&L)
   - What's left? (collected minus paid costs)
