# Use the native share sheet for the referral link

## Problem
The referral section offers two copy buttons and nothing else. The trade has to leave Motko, open WhatsApp or Messages, find the right person and paste. On the one screen whose entire purpose is getting a link to another human, that is the whole job left undone. The native share sheet integration already exists elsewhere in the product but is not used here.

## Scope
Replace the "Copy link" button on the referral link row with a share action that:
- On native platforms: opens the native share sheet via `@capacitor/share`
- On web: falls back to clipboard copy

The existing `ShareLinkButton` component (`src/components/ui/share-link-button.tsx`) already implements this branching — this is a component swap, not new plumbing.

Also fix the stale comment at line 11 of `referral-section.tsx`: change "The referrer's +5 unlocks" to "The referrer's +3, rising to 5, unlocks" to match the actual reward schedule in `src/lib/paid-job-settlement.ts:162`.

## Explicitly out of scope
- The "Copy code" button — keep it as-is. Reading a six-character code aloud is a real path, and the alphabet was chosen for exactly that (referral.ts:11-13 drops I/O/0/1).
- The body copy about "They get 3 free jobs" — that wording is being revised separately on #351. Do not touch it here.
- The reward amounts or logic themselves — this is a UI change only.

## Files
- `src/app/settings/referral-section.tsx` — swap `CopyLinkButton` for `ShareLinkButton` on the link row (line 36), add import, fix comment (line 11)
- `tests/acceptance/356.test.tsx` — acceptance tests

## Edge cases
- **No referral code yet**: the empty state ("Your referral code will appear here once…") is already handled and unchanged. No share or copy controls appear.
- **Web platform**: `ShareLinkButton` detects the platform and falls back to clipboard copy with a toast. The fallback is already implemented and tested.
- **Native platform**: `ShareLinkButton` calls `Share.share()` with title and url. If the share sheet is dismissed without sharing, nothing breaks — the component handles this.
- **Share failure on web**: if `navigator.clipboard.writeText()` throws, the component shows "Couldn't copy — try again." toast. Already implemented.

## Risks
None. This is a low-risk UI swap of an existing, tested component. No money, migrations, or user data involved.
