# Deposits and staged payments: ask, agree, then trigger on signature and on stage completion

**Issue:** #722  
**Module:** payments

## Problem

Without a deposit on rails, the trade agrees terms verbally and takes cash outside the system, and the payment is lost entirely. Seven contracts carry a `deposit_pct` but it first appears on the contract after acceptance — never on the quote — so all 7 were agreed after the fact. The voice-captured `deposit_amount` is set on 0 of 25 SoWs and read by nothing. Two of those 7 are 1% on £7k+ jobs (£72 and £81), a number typed to clear a field.

This adds the ask to the quote flow, shows the agreed deposit or schedule on the quote before acceptance, and triggers invoices on signature and stage completion rather than relying on the contractor to remember.

## Scope: what changes

### Schema
- Add `deposit_amount_pennies`, `deposit_pct` to `quotes` table to store the agreed deposit before contract creation
- Use existing `payment_stages` table for tranches
- `jobs.work_completed_at` already exists (migration 52)

### Quote editor
- For totals under £5,000: show deposit field asking for amount or percentage
- For totals £5,000 and over: show payment schedule builder for tranches
- Validate that each tranche amount is under £10,000 (Pay by Bank limit)
- Store deposit/schedule on quote before sending

### Contract signature trigger
- When `signContract` fires:
  - If quote has deposit: create deposit invoice (already works via `deposit_pct` on contract)
  - If quote has payment schedule: create stage 1 invoice and link to payment_stages row

### Stage completion trigger
- When `markWorkComplete` fires on a job with payment stages:
  - Find the next unseeded stage (no invoice_id)
  - Create invoice for that stage amount
  - Link invoice to stage via `invoice_id`
  - Exactly-once semantics: the `invoice_id IS NULL` filter prevents double-triggering

### Display
- Contract PDF shows deposit or payment schedule before customer signs
- Job detail page shows stage completion status and "Mark work complete" button
- Job detail already has `PaymentStagesSection` component for displaying stages

## Explicitly out of scope

- Changing existing legal terms on contracts (decision: v1 attaches no new terms)
- Automatic tranche calculation — Motko asks, doesn't propose
- Forfeiture, refund, and cancellation wording (raises Consumer Contracts Regulations, deferred)
- Multiple manual work completion marks (one `work_completed_at` timestamp triggers next stage)
- Editing deposit/schedule after quote is sent (must redraft)

## Edge cases

### Empty states
- No deposit agreed: field is blank, no deposit invoice fires
- No schedule agreed: payment_stages has 0 rows, job behaves as single-payment

### Total changes after deposit set
- If line items change, deposit percentage recalculates automatically
- If fixed amount deposits become inconsistent, show warning in editor

### Marking complete twice
- `work_completed_at` is a timestamp, not a counter — setting it again does nothing
- Stage invoice trigger filters `invoice_id IS NULL`, so already-invoiced stages are skipped

### Stage amount exceeds £10k limit
- Validate at quote save time: each tranche must be ≤ £10,000
- Show error if validation fails, block save
- Contractor must adjust schedule to fit within limits

### Exactly-once semantics
- Contract signature: `signContract` already uses optimistic locking (`.eq("status", "sent")`)
- Stage completion: selecting `payment_stages WHERE invoice_id IS NULL` ensures idempotency

### Declined/refunded contracts
- Existing state-machine guards in `signContract` prevent signing declined contracts
- No changes to refund logic (out of scope)

## Risks

### Money
- Deposit invoice amounts must match quote exactly (percentage calculation)
- Stage invoices must sum to quote total
- Each stage must be under £10k or payment fails

### Migrations
- Adding columns to `quotes` is low-risk (nullable columns, no data transformation)
- Existing `payment_stages` table is reused, no schema changes there

### User data
- Deposit/schedule is captured at quote time, before customer sees it
- Must survive quote send/view/accept flow without data loss

### Backwards compatibility
- Existing contracts with `deposit_pct` keep working (signContract already handles this)
- Jobs without payment_stages behave as single-payment (existing logic)

## Derived criteria

1. Quote editor shows deposit amount/percentage field for jobs under £5,000
2. Quote editor shows payment schedule builder for jobs £5,000 and over
3. Deposit or schedule is stored on quote record before sending
4. Contract PDF displays agreed deposit or payment schedule
5. Contract signature creates deposit invoice when deposit is set
6. Contract signature creates stage 1 invoice when payment schedule exists
7. `markWorkComplete` creates next stage invoice when stages exist
8. Each stage invoice is created exactly once (idempotent)
9. Stage invoices are linked to payment_stages via `invoice_id`
10. Job detail page shows payment stages with status (not invoiced, awaiting payment, paid)
11. Validation prevents stage amounts over £10,000
12. Empty deposit/schedule (nothing agreed) does not create invoices
