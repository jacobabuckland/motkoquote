# HARN-4: Run the pipeline suite nightly and route its findings to a human

## Problem

The factory's gate covers types, lint, tests, generated language and build. The pipeline suite (HARN-1/2/3) can answer whether the quote says what the tradesperson said, but nothing runs it on a schedule. Findings only surface when someone remembers to run `npm run test:pipeline` manually. The suite is currently red (2 of 9 failing on scenario-1) and this is expected, but no one sees it.

## Scope: what changes

- A nightly GitHub Actions workflow running `npm run test:pipeline` against main
- A script that parses vitest output and distinguishes prompt hash mismatches from content findings
- Issue creation when the suite fails, with different messaging for stale recordings vs content findings
- Issue closure when the suite goes green again
- No duplicate issues for the same finding on consecutive runs

The workflow runs in replay mode (no `RECORD_PIPELINE=1`, no `ANTHROPIC_API_KEY`), so it needs no credentials and can run anywhere.

## Explicitly out of scope

- Fixing the current scenario-1 failures or re-recording fixtures (tracked separately)
- Adding more test scenarios (HARN-1)
- PR gating or branch protection (never blocks a PR)
- The CI gate job (`.github/workflows/ci.yml` is untouched)

## Files

- `.github/workflows/pipeline-nightly.yml` (new) — the scheduled workflow
- `scripts/ci/report-pipeline-findings.ts` (new) — parses vitest output and reports findings
- `tests/acceptance/573.test.ts` (new) — acceptance tests

## Edge cases

**The suite stays red for weeks**  
Update the existing issue rather than opening a new one. Match by title or label to detect the existing issue.

**The suite goes green again**  
Close the open issue. The report must say the suite is now passing, not leave a stale open issue.

**The workflow itself breaks (missing dependency, bad install)**  
That is not a content finding and must not be reported as one. A workflow failure without vitest output should fail visibly but not create a misleading issue about quote content.

**Prompt hash mismatch vs content finding**  
Two different messages:
- Hash mismatch → "Stale recording: re-record with RECORD_PIPELINE=1"
- Content finding → "Quote content may be wrong: review the failing scenarios"

The script must parse the vitest output to tell them apart. A prompt hash mismatch contains "Prompt hash mismatch" in the error message. Content findings are assertion failures from `compareLineItems`, `checkStatedPricesSurvive`, or `checkForbiddenAmounts`.

## Risks

None. This is a reporting mechanism for an offline test suite. It writes no data, mutates no state, and blocks no PR.

## Derived criteria

1. A workflow file exists under `.github/workflows/` that runs on a schedule (nightly)
2. The workflow runs `npm run test:pipeline` against main with no API key
3. A script exists that can parse vitest output and identify prompt hash mismatches vs content findings
4. When the suite fails, an issue is opened with appropriate messaging
5. Prompt hash mismatches are reported as "stale recording, re-record needed"
6. Content findings are reported as "quote content may be wrong"
7. Re-running when the suite is still red does not create duplicate issues
8. When the suite goes green, the open issue is closed
9. The workflow does not block any PR (no required check, not in CI gate)
10. The reporting script is unit-testable and covered by acceptance tests
