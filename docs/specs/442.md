# UI-2: Mark as paid freezes the modal on "Marking as paid…" and never confirms on the job page

## Problem

The "Mark as paid" button is the last completing action in the app that never got the settled end-state pattern. When the contractor marks an invoice paid, `setOpen(false)` and `router.refresh()` both run inside the transition, so React holds the commit until the server round-trip completes. Until then, the modal remains on screen with its primary button reading "Marking as paid…" and both buttons disabled — including Cancel, and the backdrop click is also disabled. If the refresh stalls, there is no way out. Worse, it never navigates to the job page banner that confirms what happened: it calls `router.refresh()` and raises a toast, so the contractor sees a transient message and no durable confirmation that the job closed. From a dashboard row, the user stays on the dashboard rather than landing on the job page, so the banner never appears at all.

## Scope: what changes

1. **Add terminal state to the modal button.** `mark-as-paid-button.tsx` gains a `paid` state variable, mirroring `sent` in `create-invoice-form.tsx` and `create-contract-form.tsx`. The primary button label reads `Paid ✓` when it is set, taking precedence over the `pending` spinner.
2. **Navigate rather than refresh.** On success, push `/jobs/<jobId>?sent=paid` after a ~450ms dwell, so the job page banner confirms what happened. The component does not currently receive `jobId` — thread it from both call sites (job page and dashboard row).
3. **Add the `paid` banner variant.** `buildSentBanner` gains a `paid` branch that returns a banner confirming the job was marked paid, with `link: null` (it has no link to offer).
4. **Clear the timer on unmount.** A `useEffect` cleanup clears the navigation timer so a navigation cannot fire from a component that is gone.

## Explicitly out of scope

- **`mark-paid-actions.ts` and anything it calls.** The server action, the fee accrual, the free-job allowance and the reminder cancellation are all correct and are money paths. This item changes what the client does *after* a successful response, and nothing about the response itself — including its type, which stays `{ ok: true } | { error: string }`.
- `markPaidFeeLine` and the fee copy in the dialog body.
- `archive-quote-button.tsx` — job-ending, so per CLAUDE.md's post-action navigation map it correctly stays on the dashboard with a toast.
- The `delivered=0` / `payout=setup` banner variants. Marking as paid reaches no channel and needs neither.
- Marking paid from `cost-list.tsx` / `cost-form.tsx` — those are job costs, a different action on a different record.
- The date picker's `min`/`max` bounds in the same file. That is #444 and is deliberately queued behind this one.
- The toast. Keep it or drop it; the banner is the durable confirmation, not the toast.

## Files

- `src/app/jobs/[id]/mark-as-paid-button.tsx` (modify) — terminal state, navigation timer and cleanup, thread `jobId` from props
- `src/app/jobs/[id]/sent-banner.ts` (modify) — the `paid` variant
- `src/app/jobs/[id]/page.tsx` (modify) — pass `jobId` to `MarkAsPaidButton` at both call sites
- `src/app/dashboard/page.tsx` (modify) — pass `jobId` to `MarkAsPaidButton`, derived from `invoice.quote?.job?.id`
- `tests/acceptance/442.test.tsx` (new) — acceptance tests

## Edge cases

- **The action returns `{ error }`** → unchanged: the modal stays open, shows the error, and the button returns to `Mark as paid`. No terminal state, no navigation.
- **Already on `/jobs/[id]`** → still push, so the banner renders. A push to the current route with new search params re-renders it; the current `router.refresh()` does not produce a banner at all.
- **Fired from a dashboard row** → navigates to the job page, same as every other job-scoped completion.
- **Unmount mid-dwell** → the cleanup clears the timer, exactly as `create-invoice-form.tsx` and `create-contract-form.tsx` do.
- **No `jobId` available** → should not happen, but if `jobId` is missing or undefined, fall back to the current `router.refresh()` behaviour rather than breaking. This maintains backwards compatibility if the prop is somehow omitted.

## Risks

None. This is a UI-only change to a client component. The server action and its return type are unchanged, and the money path (fee accrual, settlement, reminder cancellation) is untouched.

## Derived criteria

1. After `markInvoicePaid` resolves `{ ok: true }`, the primary button reads `Paid ✓` — not `Marking as paid…` — before any navigation is attempted.
2. The navigation target is `/jobs/<jobId>?sent=paid`.
3. The terminal label is reached even if `router.push` hangs — stub `push` to never resolve and assert the button still reads `Paid ✓`.
4. On `{ error: "…" }`, the button returns to `Mark as paid`, the dialog stays open, and no navigation is attempted.
5. `buildSentBanner({ sent: "paid", … })` returns a banner whose title states the job was marked paid, with `link: null`.
6. `buildSentBanner` still returns `null` for an unrecognised `sent` value.
7. The navigation timer is cleared on unmount so a scheduled navigation cannot fire from a torn-down component.
