# Issue #140: Add animation primitives for completion moments

**Auditing branch:** `factory/140` @ `b7a692a`

## Problem

The four completion moments (quote ready, sent, signed, paid) each need a count-up numeral, a drawn check, and a success ring. None of these exist, so each moment would otherwise implement its own. Building these once means the four moments speak one visual language and can be composed and tuned without writing animation code each time. Built per-moment, they will diverge in timing and easing and cannot be adjusted centrally.

## Scope

**What changes:**

1. **Create CountUp component** at `src/components/ui/count-up.tsx`:
   - Accepts props: `to` (number), `from` (number, defaults to 0), `durationMs` (number), and `format` (optional function: `(n: number) => string`)
   - Renders the counting value with `tabular-nums` applied so digit width does not shift during the count
   - Animates from `from` to `to` over `durationMs` milliseconds
   - Lands exactly on `to` with no rounding drift
   - When `to` equals `from`, renders the value statically with no animation
   - When `to` changes mid-animation, restarts from the current displayed value (not from `from`)
   - If unmounted mid-count, cancels cleanly with no React state update warning
   - Under `prefers-reduced-motion`, renders the final `to` value immediately with no animation

2. **Add keyframe animations** to `src/app/globals.css`:
   - `@keyframes check-draw`: animates `stroke-dashoffset` from full (100%) to zero over `var(--dur-base, 300ms)`
   - `@keyframes success-ring`: scales from 0.6 to 1.0 using `var(--ease-spring, cubic-bezier(0.68, -0.55, 0.27, 1.55))`
   - Both keyframes respect `prefers-reduced-motion` and render their end state immediately (no animation) when reduced motion is preferred

3. **Add design tokens** to `src/app/globals.css` `:root` block:
   - `--color-success-burst: #15803d;` (vibrant green for success moments)
   - `--shadow-success-glow: 0 0 20px rgba(21, 128, 61, 0.3);` (subtle green glow)
   - `--dur-base: 300ms;` (standard animation duration)
   - `--ease-spring: cubic-bezier(0.68, -0.55, 0.27, 1.55);` (spring easing for playful moments)

**Files expected to change:**
- `src/components/ui/count-up.tsx` (new file)
- `src/app/globals.css`

## Explicitly out of scope

- Do NOT build any of the four completion moments (quote ready, sent, signed, paid). This item ships parts only.
- Do NOT add particle, confetti, or burst effects
- Do NOT add audio
- Do NOT modify any existing screen or route to use these primitives
- Do NOT add haptics inside the primitives (haptics are triggered by the consuming screen, not the primitive)
- Do NOT add any documentation beyond inline code comments
- Do NOT modify the existing `prefers-reduced-motion` media query (lines 252-260 of globals.css) — the keyframes are covered by its blanket rule

## Edge cases

**CountUp component:**
- `to` equals `from`: renders the value statically with no animation
- `to` is negative: counts down. The sign is part of the formatted output
- `to` changes mid-animation: restarts from the current displayed value, not from `from`
- Component unmounts mid-count: cancels cleanly with no React state update warning
- `format` function not provided: renders the raw number (formatted with default `toString()`)
- `prefers-reduced-motion` is enabled: renders the final `to` value immediately, skipping the animation entirely
- Precision: a value of `2480.50` formatted as currency (e.g., `£2,480.50`) must land exactly on that value with no rounding drift to `2480.49` or `2480.51`

**Keyframe animations:**
- Applied to an element when `prefers-reduced-motion` is enabled: the existing blanket media query (globals.css:252-260) sets `animation-duration: 0.01ms !important`, so the animation completes instantly and shows the end state
- Applied to an element with no `animation-duration` specified: uses the duration from `var(--dur-base)` if referenced, or the consuming CSS must specify a duration

**Design tokens:**
- Used in a component before the globals.css has loaded: falls back to the browser's default (no value). This is a non-issue in this app — globals.css loads on first paint
- `--ease-spring` applied to a transition instead of an animation: works — cubic-bezier is valid for both

## Risks

**Low risk — new UI primitives with no consumers:**
- No database migrations
- No changes to existing components or screens
- No user-visible changes until a consuming screen is built (out of scope for this item)
- No money-touching logic

**Verification required:**
- CountUp must land exactly on the `to` value for a currency amount of `2480.50` formatted as `£2,480.50` — acceptance test must verify this
- Reduced motion behavior must be tested: both keyframes and CountUp must render their end state immediately when `prefers-reduced-motion` is enabled
- CountUp must use `tabular-nums` so digit width does not shift during animation
