# Motko must ask who the quote is for, and the full materials question

## Problem

Two intake failures reported from live calls on 12 Sep:

1. **Customer name missing** — the quote came back with no customer name, not because the call ended early, but because Motko never asked. Today the name is a paragraph of prompt instruction with no `askQuestion` call, no record of whether the model complied, and no surface that shows it is missing.

2. **Materials question incomplete** — `materials_supply` already is a required slot, but the current question only asks WHO supplies materials ("you, or the customer?"), not HOW MUCH is needed or WHAT SPECIFICALLY. A contractor can answer "I'm supplying it" without ever naming quantities or specific items, and the slot reads as answered because the `responsibility` field was set.

## Scope: what changes

### Customer name becomes a trackable question

1. **Add tracking for when customer_name is asked**
   - New client-side ref tracks whether the customer name question was actually put to the contractor during the call
   - This tracking is separate from `askedRequiredSlotsRef` (which is typed to checklist slots)
   - The "was asked" status is passed to the server alongside `askedRequiredSlotsRef`
   - The server records it in telemetry so a missing name can be diagnosed

2. **customer_name does NOT enter REQUIRED_CHECKLIST_QUESTIONS**
   - Per Jacob's ruling (14 Sep) and the frozen contract at `tests/acceptance/373.test.tsx:222`
   - A voice call may still wrap cleanly with no customer name
   - The wrap detour asks for it when missing (already implemented) but does NOT block for it

3. **The absence reaches human surfaces**
   - `wrap_incomplete`, `getMissingCustomerDetails` and the job-page banner already exist from VOICE-3
   - `unasked_required` already includes `"customer_name"` when missing
   - No changes needed to these mechanisms — they already work

### Materials question asks all three parts

1. **Add quantity_guidance field to materialsSupplySchema**
   - `quantity_guidance: nullishString` (same pattern as other free-text fields)
   - Valid answers: actual quantities ("about 40 square metres"), "you work it out", null/undefined (not asked or contractor didn't answer)
   - "you work it out" is a storable answer, distinct from silence

2. **Update materials_supply answeredness check**
   - Currently: the object existing at all means "answered"
   - New: all three parts must be captured:
     * `responsibility` is set (who supplies overall)
     * `quantity_guidance` is set (can be "you work it out" or an actual quantity)
     * At least one item array is non-empty OR the answer was "nothing special to note"
   - When any part is missing, `materials_supply` remains in `getUnansweredRequiredChecklistQuestions`

3. **Update the materials_supply question text**
   - From: "Who's supplying the materials for this job — you, or the customer?"
   - To: "Who's supplying the materials for this job — you or the customer? And roughly how much are we talking — or should I work it out from the job?"

4. **Update the update_sow tool description for materials_supply**
   - Add guidance to capture quantity_guidance when the contractor mentions quantities
   - Emphasize that all three parts should be captured together

## Explicitly out of scope

1. **Contact details and site address** — deliberately NOT made into gating questions. A contractor mid-call doesn't know their customer's email off by heart (Jacob, 12 Sep). Motko takes them if volunteered but never holds a wrap for them. The capture path already exists in the quote editor.

2. **Making customer_name required** — per the ruling, customer_name does NOT enter `REQUIRED_CHECKLIST_QUESTIONS`. A call can wrap without it; the absence is surfaced to the contractor, not held as a gate.

3. **Deadline** — must NOT be promoted to required as part of this change. `tests/regression/agreed-costs-is-asked.test.ts:72` pins it out.

## Edge cases

1. **Empty materials answer** — "nothing special, standard stuff" should set `quantity_guidance` to "standard" or similar, and leave both arrays empty. This is distinct from the slot being unanswered.

2. **"You work it out" for quantity** — this is a valid, complete answer for quantity_guidance. It means the contractor is delegating quantity estimation to Motko.

3. **Customer name volunteered early** — if captured during the initial description phase, should not be re-asked during followups.

4. **Materials partially answered** — if contractor gives responsibility but not quantity, or items but not responsibility, the slot remains unanswered and gets re-asked.

## Risks

- **Type compatibility**: `customer_name` is `string | undefined`, NEVER null (per the type rules from killed attempts). SowState.customer_name is `nullishString`, which transforms null to undefined.

- **Frozen test constraints**: 
  - `tests/acceptance/373.test.tsx:222` requires customer_name NOT in REQUIRED_CHECKLIST_QUESTIONS
  - `tests/acceptance/81.test.ts:233` and `:258` pin exact contents of getUnansweredRequiredChecklistQuestions with toEqual — must use toContain/not.toContain for new assertions

- **Materials answeredness**: Tightening the materials_supply answeredness check means some calls that previously wrapped cleanly will now detour. This is the intended behavior — we want all three parts captured.

## Derived criteria

1. **Customer name tracking**:
   - A new tracking mechanism records when the customer name question is asked
   - This tracking is independent of checklist slot tracking
   - The tracked status reaches the server for telemetry

2. **Customer name NOT required**:
   - customer_name does NOT appear in REQUIRED_CHECKLIST_QUESTIONS
   - A call CAN wrap without customer_name being answered
   - The wrap detour asks for it but doesn't block on it

3. **Materials schema gains quantity_guidance**:
   - New `quantity_guidance` field in materialsSupplySchema
   - Accepts free text quantities, "you work it out", or remains undefined
   - "you work it out" is distinguishable from never asking

4. **Materials answeredness tightened**:
   - materials_supply is only answered when all three parts are captured: responsibility, quantity_guidance, and either items or explicit "nothing special"
   - Partial answers keep the slot in unanswered list

5. **Materials question updated**:
   - CHECKLIST_QUESTIONS["materials_supply"] asks for all three parts in one natural question
   - Tool description for update_sow emphasizes capturing all three parts

6. **Backward compatibility**:
   - Existing rows with no quantity_guidance remain valid
   - Old answeredness logic applies to legacy data
   - New answeredness check only applies when quantity_guidance field exists in schema

7. **No deadline promotion**:
   - deadline does NOT become required as part of this change
   - Existing test pins remain valid
