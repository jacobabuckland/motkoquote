# FACT-1: Block comment attribution must use diagnostics, not mentions

## Problem

When the factory blocks an item on a red gate, the Engineer workflow's catch-all handler composes a block comment that names files "the Engineer may not edit" by running a simple grep over the log:

```bash
FROZEN=$(grep -oE '(tests/acceptance|docs/specs)/[A-Za-z0-9._/-]+' /tmp/eng-catchall.log ...)
```

This finds any **mention** of a frozen path, not just those identified by a diagnostic. On four occasions in one evening the named file had nothing to do with the failure: #623's cross-branch-collision log mentioned migration paths, #627's schema-in-tree errors pointed at `src/` files but acceptance test paths appeared elsewhere in the log, and two others followed the same pattern.

The workflow already has `attribute-failure.sh` which correctly attributes failures only to files the log identifies as failing (vitest FAIL lines, tsc diagnostics, ESLint errors). The CI gate handler at line 826-831 uses it. The catch-all handler at line 991 does not — it greps the log directly, which is the exact pattern `attribute-failure.sh` was written to replace.

## Scope: what changes

- The catch-all handler in `.github/workflows/factory-engineer.yml` (around line 991) is changed to call `/tmp/attribute-failure.sh` instead of grepping the log
- The frozen-file block is shown only when `attribute-failure.sh` reports `frozen=<path>`, meaning a diagnostic actually identified that path as failing
- When no frozen file is attributed, the block says "The failure could not be attributed to a file" (matching the wording already used in the CI gate handler at line 886)
- The DECISION NEEDED section offering amend-or-re-derive options appears only when a frozen path was actually attributed

## Explicitly out of scope

- The CI gate handler (lines 826-831), which already uses `attribute-failure.sh` correctly
- The `attribute-failure.sh` script itself, which already does attribution correctly
- The wording of the options once a frozen file genuinely is attributed
- What the gates choose to run or how they report failures

## Files

- `.github/workflows/factory-engineer.yml` (modify) — the catch-all handler that currently greps for frozen paths
- `tests/regression/factory-failure-attribution.test.ts` (modify) — extend to assert that the catch-all does NOT grep, matching the existing check at line 188-190

## Edge cases

- **When the attributor script is not available**: The catch-all already tolerates a missing `/tmp/attribute-failure.sh` (it's materialised with `|| true`). The handler must check `-x` before calling it and degrade gracefully to "could not be attributed" when absent
- **When attribution succeeds but finds no frozen files**: Say "could not be attributed to a file" and quote the log, never offer the amend-or-re-derive options (which only apply when a frozen file failed)
- **When attribution finds both frozen and non-frozen files**: Show both blocks — frozen separately with its DECISION section, non-frozen as "attributed to" with its section
- **When the log itself cannot be retrieved**: Already handled at line 990; the FROZEN variable would be empty and the "could not be attributed" path fires

## Risks

None. This is fixing a parser to match what the rest of the workflow already does. The change makes blocking recommendations more accurate and reduces false attributions, so it strictly improves the signal a human reads.

## Derived criteria

I understood this item to be asking for:

1. The catch-all handler uses `attribute-failure.sh` to determine which files failed, not a simple grep of the log
2. When a log mentions frozen files but no diagnostic points at them (cross-branch collision, schema-in-tree with errors elsewhere), no frozen file is named in the block comment
3. When a frozen file genuinely fails, it is still named and the amend-or-re-derive options are still offered
4. The "failure could not be attributed" wording is used when no file can be identified from diagnostics
5. The test suite confirms the catch-all does not use the grep pattern, enforcing that the same mistake cannot return
