# Motko — Adversarial Bug Hunt (read-only)

**Date:** 2026-07-26
**Scope:** `motkoquote` — Next.js App Router + Server Actions, Supabase (RLS), **Stripe** (the brief said TrueLayer; the codebase actually uses Stripe Connect + Payment Links — audited what exists), OpenAI Realtime, Resend, Twilio, Capacitor.
**Deliverable:** this report only. No code, deps, or migrations were changed.

Auth model (baseline): two Supabase clients. The RLS-scoped anon client (`src/lib/supabase/server.ts`) runs as the signed-in user; the **admin/service-role client** (`src/lib/supabase/admin.ts`) **bypasses RLS**. Core-table RLS is present and owner-scoped (`supabase/migrations/00000000000001_init_schema.sql:118-203`; contracts patched in `...0020_contracts_rls.sql`). Public route allow-list is in `src/lib/supabase/middleware.ts:30-44` (`/q/ /i/ /c/ /api/quotes/ /api/contracts/ /api/stripe/ /api/twilio/ /api/cron/`). Every serious finding sits where the admin client is used, where a route is publicly reachable, or where a money value is not tied to server-adjudicated data.

## 2. Fix directions — Critical / High

- **#1 (sow-pdf IDOR):** Add `auth.getUser()` and verify the job's `contractor_id` resolves to the caller's contractor before rendering — same pattern the payouts routes already use (`.eq("owner_user_id", user.id)`). Consider moving it out of the raw `/api/jobs/` namespace or requiring RLS by using the user-scoped client.
- **#2 (client-supplied amount):** Derive the charge server-side. For `final`, compute `quote.total − sum(existing non-refunded invoices)`; reject or clamp any client amount that exceeds the remaining balance; enforce `deposit + final ≤ quote.total` and refuse a second deposit. The number that moves must come from adjudicated server data, never the request body.
- **#3 (email XSS):** Add one `escapeHtml` helper and wrap every interpolated `companyName`/`customerName`/`heading`/`nextStep`/`buttonLabel`/chase `body` (escape *then* apply the `\n→<br/>` transform). App-generated URLs are lower-risk but escape them too to close attribute-breakout.
- **#4 (forgeable sign/accept):** Gate the public accept/sign/decline on a per-link possession secret (a signed token or a random nonce column on the quote/contract), not the row UUID. The signing path auto-raises real financial documents, so authority must be proven, not assumed from knowing an ID.
- **#5 (public PDF PII):** Require the same possession token as #4 (or at least strip customer email/phone/address from the quote PDF to match what the HTML page exposes). Today these leak PII to any unauthenticated UUID-holder.
- **#6 (illegal transitions):** Make the guards assert the *legal prior state* (`.eq("status","sent")` for accept/sign, `.in("status", [...])`), not merely `.neq(target)`. Block sign/accept from `declined`; block decline after a deposit invoice exists (or void it on decline).
- **#7 (orphan chases):** Have the chase selection join quote/contract status (skip `archived`/`declined`), or transition orphaned invoices to a non-chased status when the parent is archived/declined.
- **#8 (paid-but-not-notified):** Wrap the notify/push/analytics side-effects in try/catch so a downstream failure cannot fail the webhook after settlement has committed (settlement is idempotent, so redelivery can't recover the notification). Return 200 once `paid` is committed.

## 3. Verified sound (checked, held up — with evidence)

- **Webhook signature** verified on every path before any branch — `stripe/webhook/route.ts:146-158` (missing sig → 400, `constructEvent` in try/catch → 400, missing secret → 503).
- **Settlement is atomic + idempotent** — single conditional `UPDATE … WHERE id=? AND status<>'paid' RETURNING` (`route.ts:28-52`); redelivered `completed`/`async_payment_succeeded` update zero rows → notify/analytics fire exactly once. Pay-by-Bank correctly deferred to `async_payment_succeeded` (`:160-171`).
- **No competing manual "mark as paid"** path exists — grep shows invoice `status='paid'` written only by the webhook (`route.ts:30`); there is no manual-vs-webhook settlement race.
- **Contract re-sign / double-invoice is prevented** — atomic `.neq("status","signed").select()` + `if(!updated.length) return` before raising the deposit (`c/[id]/actions.ts:49-55`); same for quote accept/decline.
- **Invoice creation idempotency** — reuse-existing check on `(quote_id, invoice_type, amount)` (`invoicing.ts:43-63`) + stable Stripe `idempotencyKey` (`:91`) so retries never mint duplicate Stripe objects.
- **Twilio inbound signature** validated in constant time (`timingSafeEqual` + length guard) before any DB write — `twilio.ts:24-28`, `inbound/route.ts:32-34`.
- **Contractor internal flags never exposed** on the public quote page — `contractor_flags_json` (migration 22) is not selected (`q/[id]/page.tsx:37-38`).
- **Quote reference is display-only** — `id.slice(0,8)` is rendered but every lookup keys on the full UUID; grep found no reference-based lookup. IDs are UUIDs (non-enumerable).
- **No raw-HTML injection in web pages, PDFs, or contract templates** — all customer/contractor/voice text renders through JSX / react-pdf `<Text>` (auto-escaped); the contract markdown parser (`contracts/markdown.ts`) emits a typed plain-text AST with **no** raw-HTML passthrough; the only `dangerouslySetInnerHTML` is static JSON-LD.
- **SMS is injection-safe** — `URLSearchParams({To,From,Body})` separates params (`sms.ts:33-37`); no Twilio-param or header injection. Email subjects go through Resend's structured `subject` field, not raw SMTP headers.
- **No server secret exposed to the client** — `STRIPE_SECRET_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `CRON_SECRET`, `TWILIO_AUTH_TOKEN`, `STRIPE_WEBHOOK_SECRET`, OpenAI/Anthropic keys referenced only in server files; every `NEXT_PUBLIC_*` is non-secret (Supabase URL/anon, VAPID public, Maps browser key). `admin.ts` is never imported by a client component.
- **Ephemeral OpenAI key handling** — long-lived `OPENAI_API_KEY` stays server-side; browser only ever receives a short-lived client secret minted fresh per session (`realtime.ts:20-57`).
- **Money display path is single + consistent** — VAT computed once on the rounded subtotal (`quote-math.ts:52-57`), reused by quote PDF, contract, and stored total; `formatGBP` is the single pounds formatter; pounds→pence conversion happens exactly once at the Stripe boundary (`stripe.ts:164`).
- **Server-derived deposit** — the auto-deposit on contract sign uses server-fetched `quote.total × pct` (`c/[id]/actions.ts:60`), not a client field (contrast #2's dashboard path).
- **Normal-path mic/WebRTC teardown** stops tracks + closes the peer connection on unmount and on normal finish (`setup/voice/page.tsx:63-67,282-285`).
- **Graceful degradation** on missing 3rd-party creds — email/SMS/Stripe/Maps return "not delivered/null" instead of throwing, so a missing key never 500s a user flow.
